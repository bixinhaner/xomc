# OMC 端到端验证

验证范围以本次改动为准，选择最窄但足够的验证；不要把全量 E2E 当作每次改动的默认动作。

## 1. 确认范围与环境

- 说明要验证的业务链路、目标环境和 API 地址；默认不假定端口或服务运行方式。
- 先检查适用的编译、单测与服务健康状态。容器化服务遵循 `deployments/docker/README.md` 与 compose 配置；不要用裸进程脚本重启容器化服务。
- 数据重置、执行种子 SQL、重启服务会改变环境。执行前列出影响并取得用户确认。

## 2. 执行后端链路验证

项目现有全量脚本是 `omcgo/scripts/e2e_verify.sh`，种子数据是 `omcgo/scripts/seed_e2e_testdata.sql`。

- 只验证本次改动时，优先运行相关测试、针对性接口检查或脚本中的相关段。
- 需要全量回归且前置条件已满足时，运行：

```bash
cd omcgo && bash scripts/e2e_verify.sh <base-url>
```

- 记录脚本末尾的 PASS、FAIL、TOTAL、claim 数量以及失败用例；任何 FAIL 都不得报为通过。
- 新增接口时，核对新增 E2E claim 数不少于新增 route 数；不适用时明确标记 N/A 并说明原因。

## 3. 验证前端联动

页面、路由、登录、渲染或交互必须使用 `$browser-control` 选择并执行浏览器验证；HTTP 脚本不能替代页面验证。

- 进入受影响页面，以真实后端完成关键操作。
- 检查页面错误、加载失败、空白状态、控制台错误和关键请求结果。
- 保留最终浏览器现场，除非用户要求关闭。

## 4. 输出结论

按“验证范围、环境、执行项、证据、结果、未覆盖项”汇报。

- 通过：列出关键证据和未执行项（如有）。
- 失败：列出首个可复现失败、影响链路和日志/截图位置；停止进入提交阶段。

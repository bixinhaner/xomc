# 产品模型 — 业务流程与表结构关系

> 提取自 `omcgo/docs/param-model-delivery/参数模型重新设计方案.md`（v 2026-04-29）
> 范围：聚焦业务流程 + 表结构关系；实施阶段 / REST API / 前端设计参见原文 §3-§7

---

## 0. 一句话定位

**TR-069 标准路径 ↔ 厂商私有路径双向映射系统**：一个产品（参数模型）有多个软件版本，不同版本可能有不同私有路径；OMC 统一面向标准路径操作，由 Translator 运行时翻译。

---

## 1. 业务流程

### 1.1 总览（4 个独立流程）

```
A. 启动加载       — 17 个 XML → 5 张表（一次性，进程启动时）
B. 设备首次连接   — productClass 字符串 → 路由解析 → 加载默认参数模型
C. 基站参数交集   — CPE 上传完整模型 → 与默认模型取交集 → 按软件版本存储
D. 参数操作翻译   — standardPath ↔ privatePath O(1) 翻译（每次 RPC 触发）
```

依赖关系：A 是基础（无 A 后续全失败）；B / C 在设备生命周期触发各一次；D 在每次 SetParameterValues / GetParameterValues 触发。

---

### 1.2 流程 A — 启动加载（loader.go）

```
配置目录 ParamModelConfig.XMLDirectory
   │
   ▼
扫描 *.xml → 解析四种格式
   ├── 产品映射 XML (17 份，对应 17 个 paramModel)
   ├── product-name-routing.xml  (42 条规则)
   ├── param-model-routing.xml   (42 条规则)
   └── standard-model.xml        (~2555 条标准路径)
   │
   ▼
事务内 Upsert（每 XML 一个事务，保证单文件原子性）
   ├── 删除该 paramModel 旧映射
   └── 批量插入新映射 + 路由规则按 XML 元素位置赋 sort_order = 1, 2, 3 ...
   │
   ▼
预热 L1 缓存（sync.Map）→ 等待运行时查询
```

**预期落库行数**：17 模型 × ~800 = 约 13,600 条 `param_mappings` + 42 条 `product_name_routing` + 42 条 `param_model_routing` + ~2555 条 `standard_params`。

---

### 1.3 流程 B — 设备首次连接（registry.go）

替代旧 carrier/tech/oui/product_class 三级回退，直接走两步路由 + 加载：

```
基站 Inform 报文 → productClass 字符串（如 "FAP/pBS7430/DC"）
   │
   ▼
Step 1: productName 路由
   ├── ORDER BY sort_order ASC 遍历 product_name_routing
   ├── 首个 regexp.MatchString 命中 → productName（如 "QRTB-DC"）
   └── 用途：UI 设备列表显示名
   │
   ▼
Step 2: paramModel 路由
   ├── ORDER BY sort_order ASC 遍历 param_model_routing
   ├── 首个 regexp.MatchString 命中 → param_model_id（如 "QRTB"）
   ├── 多条同时命中 → 报错（提示调正则精确度）
   └── 用途：加载映射集
   │
   ▼
Step 3: 加载参数模型（三级缓存）
   ├── L1 sync.Map → L2 Redis (parammodel:mapping:{id}:{ver}) → L3 PostgreSQL
   └── 返回 standardToPrivate + privateToStandard 双向 map
```

**关键设计 — sort_order 决定匹配优先级**

`regexp.MatchString` 是**子串匹配**（非全匹配），因此匹配顺序必须确保**具体规则在前、宽泛兜底在后**。机制：

1. `generate_routing.py` 按正则特异性（锚点 `^$` > 通配符 `\w+` > 纯字符串）排序后输出 XML
2. 加载器按 XML 元素位置依次赋 `sort_order = 1, 2, 3, ...`
3. 运行时 `ORDER BY sort_order ASC` 逐条遍历，首次命中即返回

**反例**：兜底规则 `FAP` 能匹配所有含 "FAP" 的字符串。如果它排在前面，所有 Baicells 产品（FAP/MLN/SC、FAP/pBS7430/DC 等）都会被错误识别为 RTS。**正解**：兜底规则 sort_order 排到最大，仅在前面具体规则全部 miss 时生效。

**匹配示例**（productClass = `"FAP/pBS7430/DC"`）：

| 步骤 | 遍历到的正则 | 是否命中 | 说明 |
|------|-------------|---------|------|
| productName #1 | `FAP/\w*BSC\w+` | ✗ | 无 BSC |
| productName #N | `FAP/\w+(BS31)\w+/DC` | ✓ | 命中，返回 "QRTB-DC" |
| paramModel #N | `FAP/\w+(BS31)\w+/DC` | ✓ | 命中，加载 QRTB 参数模型 |

兜底规则 `FAP` 排在最后，仅在前面具体规则全部 miss 时才被命中（→ RTS）。

---

### 1.4 流程 C — 基站参数交集（intersect.go）

设备首次连接后会上传自身完整参数模型 XML。系统需与 OMC 预定义的默认模型取交集，得到该基站实际支持的参数子集：

```
CPE 上传参数模型 XML
   │
   ▼
解析得到 privatePath 集合（设备真实支持的私有路径）
   │
   ▼
通过流程 B 拿到默认 paramModel
   ├── param_mappings WHERE param_model_id = ? AND software_version IS NULL
   └── 即启动时从 XML 导入的全量映射
   │
   ▼
遍历 默认模型 的 privateToStandard 反向索引
   │
   ▼
交集 = 默认 paramModel 中 privatePath 存在于 CPE 集合的条目
   │
   ▼
按 (param_model_id, software_version) 写回 param_mappings
   └── software_version 非 NULL，标记为该设备特定版本的覆盖映射
```

**意义**：默认模型是产品线全集；交集结果是设备实际能力子集，避免下发设备不支持的路径。

---

### 1.5 流程 D — 参数操作翻译（translator.go）

每次 ACS 与 CPE 交互时双向翻译路径：

```
配置下发（SetParameterValues）
   ├── 模板 / 规则使用 standardPath 定义
   ├── TranslateToPrivate(ctx, paramModelId, softwareVersion, standardPath)
   ├── O(1) map 查找 → privatePath
   └── TR-069 SOAP 报文使用 privatePath 下发

参数响应（GetParameterValues / Inform）
   ├── CPE 返回 privatePath
   ├── TranslateToStandard(ctx, paramModelId, softwareVersion, privatePath)
   ├── O(1) map 查找 → standardPath
   └── 应用层按 standardPath 存储 / 联动配置基线 / KPI 等
```

**软件版本回退语义**：先用 `software_version` 精确匹配；未命中则回退到 `software_version IS NULL` 的默认映射。

## 2. 表结构关系

### 2.1 ER 关系总览

```
                           ┌─────────────────────┐
                           │   param_models      │
                           │  (17 行：参数模型)    │
                           │  - id (PK, UUID)    │
                           │  - name (UNIQUE)    │
                           └────┬────────────────┘
                                │ 1:N (CASCADE)
                                │
              ┌─────────────────┼──────────────────┐
              │                                     │
              ▼ N                                   ▼ N
      ┌──────────────────┐               ┌──────────────────────┐
      │ param_mappings   │               │ param_model_routing  │
      │ (~13,600 默认行) │               │ (42 条规则)            │
      │ 双向映射核心      │               │ productClass→model   │
      └──────────────────┘               └──────────────────────┘

      ┌─────────────────────┐                 ┌────────────────────┐
      │ product_name_routing│                 │  standard_params   │
      │ (42 条规则)          │                 │  (~2555 条)         │
      │ productClass→显示名  │                 │  OMC 标准路径全集    │
      │ 1:1 映射             │                 │  独立于厂商私有实现  │
      └─────────────────────┘                 └────────────────────┘
            │                                          │
            └────── 由 productClass 路由（双查询）─────┘
                       两表查询互不依赖
```

**关系特征**：

- `param_models` ⇄ `param_mappings`：**1:N 强耦合**（CASCADE 删除）。一个参数模型有多组（standardPath, privatePath）映射；不同 software_version 可同时存在
- `param_models` ⇄ `param_model_routing`：**1:N 强耦合**（CASCADE）。同一参数模型可被多个 productClass 正则指向（如 QRTB-CA/DC/SC 三个 productClass 都路由到 QRTB 参数模型）
- `product_name_routing` 与 `param_model_routing`：**形式同构、语义独立**。两表各 42 条规则，前者解析显示名（1:1），后者解析参数集（N:1）。运行时分别查询，结果互不影响
- `standard_params`：**独立全局表**。OMC 跨产品的标准路径定义，不与任何厂商私有路径直接关联；通过 `param_mappings.standard_path` 间接关联

**关键 N:1 案例**：QRTB-CA / QRTB-DC / QRTB-SC 三个不同子型号 → `param_model_routing` 三条规则 → 都指向同一 `QRTB` `param_models` 行 → 共用一组 `param_mappings` 默认映射；但 UI 上通过 `product_name_routing` 显示三个独立产品名。

---

### 2.2 `param_models` — 参数模型顶层

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | UUID PK | |
| `name` | VARCHAR(64) UNIQUE | "RTS"、"QRTB"、"BaiBNQ" 等 |
| `total_entries` | INT | 对象+参数总数 |
| `total_objects` | INT | 对象数 |
| `total_params` | INT | 参数数 |
| `description` | TEXT | |
| `is_active` | BOOLEAN DEFAULT true | |
| `loaded_from` | VARCHAR(256) | 来源 XML 文件名 |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

**职责**：定义参数模型的顶层元信息。一个模型服务多个产品子型号（如 QRTB-CA/DC/SC 共用 QRTB 模型）。

---

### 2.3 `param_mappings` — 参数映射（核心表）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | UUID PK | |
| `param_model_id` | UUID FK → `param_models.id` | CASCADE 删除 |
| `software_version` | VARCHAR(64) | NULL = 默认模型；非空 = 设备特定 |
| `standard_path` | TEXT NOT NULL | 标准路径 |
| `private_path` | TEXT NOT NULL | 厂商私有路径 |
| `entry_type` | VARCHAR(8) | CHECK ('object', 'parameter') |
| `access` | VARCHAR(16) | READ_ONLY / READ_WRITE |
| `data_type` | VARCHAR(16) | STRING / INT / U_INT / BOOLEAN / DATE_TIME |
| `change_applies` | VARCHAR(16) | Immediate / OnReboot |
| `min_value` / `max_value` | BIGINT | |
| `is_active` | BOOLEAN DEFAULT true | |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

**唯一约束**（两个 partial unique index 处理 NULL 语义）：

```sql
CREATE UNIQUE INDEX idx_pm_default ON param_mappings (param_model_id, standard_path)
  WHERE software_version IS NULL;
CREATE UNIQUE INDEX idx_pm_versioned ON param_mappings (param_model_id, software_version, standard_path)
  WHERE software_version IS NOT NULL;
```

**查询索引**（流程 D 双向翻译热路径）：

```sql
CREATE INDEX idx_pm_lookup_std  ON param_mappings (param_model_id, software_version, standard_path) WHERE is_active;
CREATE INDEX idx_pm_lookup_priv ON param_mappings (param_model_id, software_version, private_path)  WHERE is_active;
```

**预估行数**：17 模型 × ~800 默认映射 ≈ 13,600 行 + 设备特定覆盖（按上线设备数 × 软件版本累积）。

---

### 2.4 `product_name_routing` — 产品名路由（UI 显示）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | UUID PK | |
| `product_class` | TEXT NOT NULL UNIQUE | 正则表达式（精确 / 锚定 / 通配符三类） |
| `product_name` | VARCHAR(128) NOT NULL | 显示名，与 product_class 一对一 |
| `sort_order` | INT NOT NULL | 加载时按 XML 元素位置赋值，查询 ORDER BY ASC |
| `is_active` | BOOLEAN DEFAULT true | |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

**职责**：UI 设备列表的显示名解析。42 条规则 → 42 个不同 productName（QRTB-CA、QRTB-DC、QRTB-SC 等各自独立）。

---

### 2.5 `param_model_routing` — 参数模型路由（参数集解析）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | UUID PK | |
| `param_model_id` | UUID FK → `param_models.id` | CASCADE 删除 |
| `product_class` | TEXT NOT NULL | 正则表达式，多条可指向同一 param_model |
| `sort_order` | INT NOT NULL | 加载时按 XML 元素位置赋值，查询 ORDER BY ASC |
| `is_active` | BOOLEAN DEFAULT true | |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

**职责**：流程 B Step 2 加载映射集。42 条规则 → 17 个参数模型（多产品子型号共用一套参数集，如 QRTB-CA/DC/SC 三规则都指向 QRTB 模型）。

---

### 2.6 `standard_params` — 标准参数树

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | UUID PK | |
| `standard_path` | TEXT NOT NULL | OMC 统一标准路径 |
| `entry_type` | VARCHAR(8) | object / parameter |
| `access` / `data_type` / `change_applies` | VARCHAR(16) | |
| `min_value` / `max_value` | BIGINT | |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

**职责**：定义跨厂商统一的标准路径全集（~2555 条），用于配置模板、KPI 定义等跨产品场景。所有应用层操作面向标准路径，由 `param_mappings` 在运行时翻译为厂商私有路径。

---

### 2.7 正则匹配三类形态（路由表共用）

`product_class` 列存正则表达式，运行时 `regexp.MatchString` 子串匹配：

| 形态 | 占比 | 示例 | 场景 |
|------|------|------|------|
| **A. 精确匹配**（无通配符） | ~20 条 | `CHINA_TELECOM`、`fBS3251-B01`、`HM-TCELL-*-2100` | 第三方厂商固定 productClass（京信、大唐、CICT、华为）|
| **B. 锚定路径**（`^...$`） | ~10 条 | `^FAP/MLN/SC$`、`^FAP/MLQ/SC$` | Baicells 自有产品已知子型号 |
| **C. 通配符模式**（`\w+` / `\w*`） | ~12 条 | `FAP/\w+(BS31)\w+/SC`、`FAP/\w*BSC\w+` | 通过芯片型号 + 射频模式组合识别 |

**兜底规则** `FAP`（精确字符串匹配，无锚定）必须 sort_order 最大 — 任何含 "FAP" 的字符串都会命中，作为终兜底防漏匹配。

## 3. 索引读写视图汇总

| 操作场景 | 命中索引 | 表 | 流程 |
|---------|---------|-----|------|
| productClass → productName 查找 | ORDER BY sort_order | `product_name_routing` | B Step 1 |
| productClass → param_model_id 查找 | ORDER BY sort_order | `param_model_routing` | B Step 2 |
| 加载默认映射 | `idx_pm_default` | `param_mappings` | B Step 3 / C |
| standardPath → privatePath | `idx_pm_lookup_std` | `param_mappings` | D（下发翻译） |
| privatePath → standardPath | `idx_pm_lookup_priv` | `param_mappings` | D（响应翻译） |
| 设备特定版本覆盖映射 | `idx_pm_versioned` | `param_mappings` | C（交集存储） / D |

## 5. Redis 缓存键（运行时性能）

```
parammodel:mapping:{paramModelId}:{softwareVersion}  — paramModel 映射 JSON (TTL 24h)
parammodel:mapping:{paramModelId}:default            — 默认 paramModel 映射 (TTL 24h)
parammodel:name_routing:{productClass}               — 产品名路由结果 (TTL 1h)
parammodel:model_routing:{productClass}              — 参数模型路由结果 (TTL 1h)
parammodel:cache_version                             — 跨实例失效计数器
```

三级缓存：L1 sync.Map（进程内）→ L2 Redis → L3 PostgreSQL。

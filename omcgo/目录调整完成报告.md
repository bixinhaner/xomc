## 5. 架构分层

```
┌────────────────────────────────────────────────────────────┐
│  cmd/app        cmd/acs        cmd/worker        cmd/omcctl │  入口层
├────────────────────────────────────────────────────────────┤
│  internal/{acs, config, pm, alarm, mr, device, admin,      │
│    topology, software, backup, dashboard, ops, report,     │  业务模块层（23 个）
│    mml, filemanager, syslog, license, nedirect,            │
│    northbound, provision, interop}                         │
│  internal/transfer                                          │  模块间桥接
├────────────────────────────────────────────────────────────┤
│  internal/core/                                             │  核心公共层
│    ├── bootstrap        appconfig        carrier            │  启动/配置/运营商
│    ├── model    errors    event    middleware               │  领域类型/事件/中间件
│    └── components/{postgres, redis, nats, minio, ...}      │  基础设施适配器
├────────────────────────────────────────────────────────────┤
│  pkg/{tr069, soap, xmlutil}                                │  可复用公共库
├────────────────────────────────────────────────────────────┤
│  global/                                                    │  全局常量（零依赖）
└────────────────────────────────────────────────────────────┘
```

**依赖方向**：入口层 → 业务层 → core 层 → pkg 层 → global 层（严格单向，禁止反向依赖）

## 7. 关键决策与实施细节

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 包名冲突策略 | rediscomp/natscomp/miniocomp/logpkg 别名 | 避免与 go-redis/nats.go/minio-go/zap 的包名冲突 |
| global/ 兼容策略 | 类型别名 + 常量转发 | 避免一次性修改 185+ 个引用 model 的文件 |
| appconfig 分离 | 仅移动 config.go | F02 业务代码 (datamodel/template/baseline/sync_handler) 保留在 internal/config/ |
| main.go 精简 | bootstrap 启动框架 | 503 行 → ~180 行 → ~70 行（两轮精简） |
| core/ 聚合 | 8 个共享包统一迁入 internal/core/ | 业务模块（23 个）与公共基础设施明确分层，避免循环依赖 |
| 限流器优化 | hashicorp/golang-lru/v2 | sync.Map 无容量上限和生命周期管理；10 万设备淘汰 O(n) → O(1) |

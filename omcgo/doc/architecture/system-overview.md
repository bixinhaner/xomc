## 1. OMC 系统定位

OMC（Operations, Management and Control）即无线操作维护中心，在电信网络管理体系中处于**网元管理层（EML）**，负责对小基站/皮基站/微基站设备进行集中化的运维管理。

```
┌─────────────────────────────────────────────┐
│           OSS / 上层运维系统                   │  ← 网络管理层（NML）
│     （省级/集团网管、综合网管平台）              │
└──────────────────┬──────────────────────────┘
                   │ 北向接口（F08）
                   │ （性能/配置/告警数据）
┌──────────────────┴──────────────────────────┐
│              OMC 基站管理系统                   │  ← 网元管理层（EML）
│         （本项目 - omcgo）                      │
│                                               │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐      │
│  │ 配置管理  │ │ 性能管理  │ │ 告警管理  │      │
│  └──────────┘ └──────────┘ └──────────┘      │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐      │
│  │ 测量报告  │ │ 自动开站  │ │ 拓扑管理  │      │
│  └──────────┘ └──────────┘ └──────────┘      │
└──────────────────┬──────────────────────────┘
                   │ 南向接口（F01）
                   │ （TR069/CWMP 协议）
┌──────────────────┴──────────────────────────┐
│          基站设备（NE 网元层）                  │  ← 网元层（NEL）
│   皮基站 / 扩展型皮基站 / 微基站 / 飞基站       │
└─────────────────────────────────────────────┘
```

## 2. 系统核心角色

OMC 在 TR069 架构中扮演 **ACS（Auto Configuration Server，自动配置服务器）** 角色：

| 角色 | 组件 | 说明 |
|------|------|------|
| ACS | OMC 系统 | 自动配置服务器，管理和控制 CPE 设备 |
| CPE | 基站设备 | 被管理的客户端设备（Customer Premises Equipment） |

**核心职责**：
- **设备发现**：新设备上电后通过 TR069 Inform 自动注册
- **配置下发**：通过 SetParameterValues 等 RPC 下发配置
- **状态监控**：周期性采集设备运行状态与性能数据
- **告警处理**：接收和转发设备告警事件
- **软件管理**：远程升级设备固件/软件版本

## 3. 支持的设备类型

| 设备类型 | 英文 | 典型场景 | 覆盖范围 |
|---------|------|---------|---------|
| 皮基站 | Pico Base Station | 室内覆盖（商场、写字楼） | 50-200m |
| 扩展型皮基站 | Extended Pico BS | 室内深度覆盖（大型场馆） | 100-500m |
| 微基站 | Micro Base Station | 室外热点补盲 | 200-1000m |
| 飞基站 | Femto Base Station | 家庭/SOHO 覆盖 | 10-50m |
| 社会化基站 | Social Base Station | 联通对第三方基站的统称 | 视设备类型 |

## 4. 支持的制式

| 制式 | 技术标准 | 运营商支持 | 数据模型版本 |
|------|---------|-----------|------------|
| TD-LTE (4G) | 3GPP LTE | 移动、电信 | 移动 V2.1/V2.3，电信 V1.0/V1.1 |
| 5G NR (SA) | 3GPP NR | 移动、电信、联通 | 移动 V1.7/V1.9.4，电信 V2.1.7/V2.6，联通 V1.0/V1.1 |

## 5. 三大运营商差异概述

### 中国移动

- **规范体系最完整**：覆盖南向接口（总则+技术要求+测试要求三部分）、数据模型、MR、网元直连等全链路
- **设备类型**：以一体化皮基站和扩展型皮基站为主
- **特色**：网元直连接口（F07）为移动独有规范
- **数据模型**：LTE 和 NR 分别独立定义，版本迭代最频繁（NR 已到 V1.9.4）

### 中国电信

- **实用导向**：规范中包含开站模板、指标关联、KPI 整理等实操性文档
- **接口版本演进**：TR069 接口从 V1.7 演进到 V2.6，有专门的差异说明文档
- **共建共享**：独有的 5G 共建共享场景南向接口规范
- **地方定制**：包含贵州电信的地方化 4G 皮基站规范

### 中国联通

- **5G 专注**：规范全部面向 5G NR SA，不包含 4G 规范
- **社会化基站**：统一使用"社会化基站"概念，面向第三方设备厂商
- **北向接口最完整**：唯一明确定义 OSS 北向接口规范的运营商（性能/配置 + 告警）
- **体系最规范**：技术规范与测试规范严格配对，结构清晰

## 6. 功能域全景

系统共划分为 **10 个功能域**、**43 项子功能**：

| 优先级 | 功能域 | 说明 |
|-------|--------|------|
| **核心** | F01 南向接口、F02 数据模型、F06 OMC-R 核心 | 系统基础能力，必须优先实现 |
| **高** | F03 性能管理、F04 告警管理、F05 测量报告 | 运维核心数据能力 |
| **中** | F09 自动开站、F07 网元直连、F08 北向接口 | 扩展能力与上下游对接 |
| **辅助** | F10 互操作测试 | 质量保障 |

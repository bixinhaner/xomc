# 即插即用参数自配置修复记录（2026-08-21）

## 背景

本次修复围绕即插即用策略编辑页的参数自配置流程展开，主要处理以下现象：

- “软件升级 / License / 参数自配置”模块切换按钮点击后页面内容不切换。
- 参数自配置模板导入多个文件时，预览区只表现为一条导入结果。
- 修改配置抽屉中 `WAN(VLAN)/LAN` 区域打开后，“新增”按钮出现较慢。
- 导入模板后编辑 `WAN(VLAN)/LAN` 的接口名称，页面填入后保存，刷新或再次打开后值丢失。
- 点击单行“下载”后，下载文件的 `INTERFACE` 工作表中没有保存后的接口名称。
- 导出模板再导入编辑时，部分页面字段与 TRPath 映射关系无法重新对应。

## 涉及范围

- 页面：`/device/plug-and-play/edit/:id`
- 主要代码：
  - `omcmb/webcode/src/pages/device/PlugAndPlay/AddPolicyPage.tsx`
  - `omcmb/webcode/src/pages/device/PlugAndPlay/CommonQuickSettingsNetworkCards.tsx`
  - `omcmb/webcode/src/pages/device/PlugAndPlay/paramConfigDetail.ts`
  - `omcmb/webcode/src/pages/device/PlugAndPlay/paramConfigWorkbook.ts`
  - `omcmb/webcode/src/pages/device/PlugAndPlay/commonParameterConfig.ts`

## 根因与修复

### 1. 模块切换按钮失效

根因：模块选择的 `Radio.Group` 使用了组件本地状态，但策略表单提交与编辑回填依赖 Ant Design Form 字段，导致 UI 与表单状态脱节。

修复：

- 将模块选择绑定到 `Form.Item name="functionModule"`。
- 编辑策略时根据已有策略内容推断初始模块：存在参数自配置内容时默认进入“参数自配置”，存在 License 内容时默认进入“License”。

### 2. 多文件导入预览不符合预期

根因：导入流程按单个上传对象触发解析，多个文件选择后没有按文件逐个展开成独立预览行。

修复：

- 上传控件支持 `multiple`。
- 对本次选择的每个文件分别解析。
- 每个文件内的每条设备配置各自生成一行预览，不新增“来源”列，也不把多个文件合并成一条预览记录。

### 3. 修改配置抽屉中“新增”按钮出现慢

根因：网络快速配置分组在抽屉打开时重新请求，`WAN(VLAN)/LAN` 区域依赖该请求完成后才渲染。

修复：

- 按参数模型名称缓存网络快速配置分组。
- 已有缓存时抽屉打开直接渲染网络配置区，后台无需再次阻塞用户操作。

### 4. 接口名称编辑后保存丢失

根因：导入模板后的权威数据源是 `sheetParameters`。旧逻辑 `mergeExistingSheetCells` 只会覆盖导入工作表中已经存在的列；如果导入的 `INTERFACE` 工作表缺少 `Interface Name` 列，页面中填写的接口名称会在保存合并阶段被过滤掉，最终 PUT 请求中没有该值。表现为页面能输入，保存接口也返回成功，但刷新后值消失。

修复：

- 将 gNB 网络接口名称统一落到 `sheetParameters.INTERFACE[*]["Interface Name"]`。
- 为 `Device.Ethernet.Interface.N.Name` / `Device.IP.Interface.N.Name` 建立到 `INTERFACE.Interface Name` 的系统映射。
- 当导入工作表缺少 `Interface Name` 列时，只允许补充这个系统列，避免放开任意新增列。
- 清理旧的网络接口名称自定义参数落点，避免同一个接口名称同时存在于 `customParams` 和 `sheetParameters`。
- 空白新增的 `WAN(VLAN)/LAN` 行不再因为接口名称为空阻塞保存；用户填写后则按上述路径保存。

### 5. 导出模板的 TRPath 映射不完整

根因：历史或导入后的工作簿可能已有 `参数映射` 工作表，但缺少部分系统字段映射。旧导出逻辑在映射表已存在时直接跳过补充，导致再次导入后页面字段无法稳定还原到对应 TRPath。

修复：

- 导出时如果已有 `参数映射` 工作表，会根据当前数据工作表中实际存在的列补充缺失的系统映射。
- 接口名称等系统字段会随导出补齐映射关系，保证导出、导入、编辑、保存链路一致。

### 6. 单行下载文件缺少接口名称

根因：单行下载会先通过 `createParamConfigWorkbook` 构造业务工作表。旧逻辑在存在原始 `workbookMappings` 时，只保留映射表中已有的列；如果原导入文件缺少 `Interface Name` 映射，即使接口名称已经保存到 `sheetParameters.INTERFACE[*]["Interface Name"]`，下载构造阶段仍会把这一列过滤掉。

修复：

- 在下载构造阶段对白名单系统列 `gNB INTERFACE.Interface Name` 放行。
- 其他未知列仍保持原有过滤规则，避免把未映射的临时字段写入下载文件。

### 7. 修改配置抽屉保存只更新前端本地状态

根因：编辑已有策略时，抽屉内保存只更新页面内 `paramConfigList`，没有立即提交到策略保存接口。

修复：

- 编辑模式下抽屉保存会调用策略 PUT 接口持久化。
- 保存失败时回滚页面内配置列表，避免 UI 显示与后端状态不一致。

## 数据约束

- `sheetParameters` 仍然是导入模板配置的权威数据结构。
- `networkParameterValues` 只作为表单临时状态使用，不持久化到设备覆盖配置。
- 仅允许补充 gNB `INTERFACE.Interface Name` 这一类明确系统列；其他未知列仍按导入模板原结构处理。
- 多文件导入只改变预览行数量，不改变预览表头结构。

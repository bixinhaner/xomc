# 即插即用多小区参数配置设计

> 日期：2026-08-14
> 状态：已实施（设备指定参数与公共参数均采用多小区/BTS 列表）
> 影响范围：即插即用参数页面、参数配置 Excel 导入导出、策略配置 JSON、参数编译与自开站 XML 生成
> 关联代码：`paramConfigWorkbook.ts`、`paramConfigDetail.ts`、`GnbQuickSettingsCards.tsx`、`EnbQuickSettingsCards.tsx`、`parameter_compiler.go`

## 1. 背景

即插即用参数配置当前已经完成单小区场景的页面配置、Excel 导入和自开站 XML 参数编译。现有数据结构中的 `sheetParameters` 已允许一个工作表保存多行，Excel 解析器也会将同一设备序列号、同一工作表的多行聚合为数组，后端编译器则会根据工作表行序号生成具体的小区实例路径。

但是当前页面和编译规则仍主要按照单小区设计：

- 页面字段大量固定绑定到 `sheetParameters.CELL[0]`，无法编辑第二个及后续小区；
- 编译器同时使用顶层配置行号和 Sheet 行号推导小区实例，存在两套隐式 index 来源；
- Excel 没有显式小区实例列，依赖物理行顺序表达设备实例；
- PLMN、接口、IPsec 等其他多实例参数与小区实例共用行号，无法可靠表达二维实例关系；
- 删除、插入或重排页面/Excel 行后，隐式实例号可能发生变化，导致参数指向错误的设备实例。

本设计的目标是建立稳定、可校验、可兼容旧单实例配置，并覆盖 NR/gNB、LTE/eNB、GSM BM（BTS 型设备）和 GSM BSC 的多无线实例模型。

## 2. 设计结论

采用以下统一模型：

1. 一个设备序列号在 `paramConfigList` 中只保留一个顶层配置对象；
2. 设备下的主要无线实例使用可增删列表表达，NR/LTE 页面称为“小区”，GSM BSC 页面称为“BTS”；
   公共参数配置与指定设备配置使用同一种列表结构，公共列表批量下发到匹配设备，指定设备列表存在时整体覆盖公共列表；
3. 每个主要无线实例保存显式、持久化的 `instanceIndex`，并根据制式暴露为 `cellIndex` 或 `btsIndex`；
4. NR 的主实例绑定 `CellConfig.{i}`，LTE 的主实例绑定 `FAPService.{i}`，GSM 分别绑定 `GsmBTSCellDT.{i}` 或 `DeviceGSM.Bts.{i}`；
5. Excel 使用各制式已有业务列表达实例：NR 增加 `Cell Index`，LTE 复用 `*CELL_NUMBER`，GSM 根据产品使用 `Cell Index` 或 `BTS Index`；
6. PLMN、邻区、载波、TRX、接口和 IPsec 隧道使用各自的实例 index，不再统一依赖 Sheet 行号；
7. 实例绑定必须由制式、产品参数模型和具体 TRPath 决定，不能把所有 `{i}` 都替换成同一个数字；
8. 参数仍编译到自开站 XML 并通过既有 XML Download 流程下发，不改为 `SetParameterValues`。

## 3. 设计原则

### 3.1 一台设备一个顶层配置

`paramConfigList` 的业务主键是设备序列号。同一 SN 不应通过多个顶层对象表达多个小区，否则顶层数组序号会被误认为小区序号，也会破坏现有按 SN 导入覆盖、合并和执行匹配逻辑。

NR/LTE 的目标结构为：

```text
设备配置（SN001）
├── 设备级参数
├── 小区 1（instanceIndex=1）
│   ├── 小区参数
│   └── PLMN 1、PLMN 2
└── 小区 2（instanceIndex=2）
    ├── 小区参数
    └── PLMN 1
```

### 3.2 实例号不能使用数组下标

页面数组下标只表示当前展示顺序，不能作为长期设备实例号。删除第一个数组元素后，后续元素的数组下标会前移；如果直接用下标下发，原小区 2 会错误地变成小区 1。

因此需要区分：

| 字段 | 用途 | 是否下发 |
| --- | --- | --- |
| `id` | 前端稳定渲染 key | 否 |
| `instanceIndex` | 设备侧主要无线实例号 | 是，用于解析 TRPath |
| `cellIndex` / `btsIndex` | 按制式呈现的 `instanceIndex` 业务别名 | 不作为参数下发；参与路径解析 |
| 数组下标 | 页面展示和表单定位 | 否 |

`instanceIndex` 从 1 开始，在同一设备内必须唯一。删除实例后不得自动重排其他实例号。

### 3.3 不同实例层级使用不同 index

TR-069 路径可能同时包含小区实例和小区下的列表实例，例如：

```text
Device.Services.FAPService.1.CellConfig.{cell}.NR.CN.TA.1.PLMNList.{plmn}.PLMNID
```

其中 `{cell}` 和 `{plmn}` 是两个独立维度，不能都使用 Excel 行号。类似地，接口、IPsec 隧道和邻区也应使用各自的 index。

### 3.4 各制式主实例绑定

“第几个小区”是页面业务概念，不代表各产品一定使用相同的 TR-069 对象层级。当前参数模型中的主实例绑定如下：

| 制式/产品族 | 页面对象 | Excel 主实例列 | 主实例 TRPath | 说明 |
| --- | --- | --- | --- | --- |
| NR/gNB | 小区 | `Cell Index` | `FAPService.1.CellConfig.{i}.NR` | `FAPService` 当前固定 1，`CellConfig` 使用小区实例号 |
| LTE/eNB | 小区 | 复用 `*CELL_NUMBER` | `FAPService.{i}.CellConfig.LTE` | `CellConfig.LTE` 不是实例对象，`FAPService` 使用小区实例号 |
| GSM BM（BTS 型设备） | GSM 小区 | `Cell Index` | `Device.Services.GsmBTSCellDT.{i}` | 一行对应一个 `GsmBTSCellDT` 实例 |
| GSM BSC | BTS | `BTS Index` | `DeviceGSM.Bts.{i}` | 一行对应一个 BTS；其下还有 2G/4G 邻区和 TRX |

LTE 现有模板中的 `*CELL_NUMBER` 就是实例控制列，不再增加含义重复的 `Cell Index`。该列不作为普通参数写入 XML，而是用于替换 `FAPService.{i}`。如果某 LTE 产品的参数模型采用其他主实例路径，必须在产品实例绑定中显式配置，不能沿用默认规则猜测。

### 3.5 各制式子实例差异

| 制式 | 子实例 | 典型路径 | 归属规则 |
| --- | --- | --- | --- |
| NR | PLMN | `CellConfig.{cell}.NR.CN.TA.1.PLMNList.{plmn}` | 归属具体 NR 小区 |
| NR | NR/LTE 邻区、异频载波 | `CellConfig.{cell}.NR...{child}` | 归属具体 NR 小区 |
| NR | AMF、NGU、IPsec | `AMFPoolConfigParam.{i}`、`NguIpBind{i}`、`FAP.Ipsec.{i}` | 设备/FAP 级独立列表，不使用小区 index |
| LTE | PLMN 列表 | `FAPService.{cell}.CellConfig.LTE.EPC.PLMNList.{plmn}` | 归属具体 LTE/FAPService 实例 |
| LTE | 聚合服务 PLMN | `FAPService.{cell}.FAPControl.LTE.Gateway.ExistPlmnidList` | 每个主实例一个聚合标量，不存在 PLMN 子实例号 |
| LTE | 邻区、异频载波 | `FAPService.{cell}.CellConfig.LTE...{child}` | 归属具体 LTE/FAPService 实例 |
| LTE | MME、IPsec | 产品实际路径 | 按参数模型判断是主实例级还是设备级列表 |
| GSM BSC | 2G/4G 邻区 | `DeviceGSM.Bts.{bts}.Neighbor2G/Neighbor4G.{neighbor}` | 归属具体 BTS |
| GSM BSC | TRX | `DeviceGSM.Bts.{bts}.Trx.{trx}` | 归属具体 BTS |
| GSM BM（BTS 型设备） | 产品子对象 | 以实际参数模型为准 | 不默认套用 BSC 子实例规则 |

固定实例也必须保留原语义。例如当前 NR 产品中的 `FAPService.1`、`TA.1`、`ScsSpecificCarrierList.1` 不能因为存在主实例而被替换成小区序号。

## 4. 目标数据模型

推荐在业务 DTO 中显式表达主要无线实例及其子实例。内部使用制式无关的 `radioInstances`，页面再根据 `kind` 显示“小区”或“BTS”：

```ts
interface ParamConfig {
  id: string;
  deviceType: 'eNB' | 'gNB' | 'GSM';
  serialNumber: string;
  updatedBy: string;
  updatedAt: string;

  // DEVICE、1588_CONFIGURATION 等设备级参数。
  sheetParameters?: Record<string, Record<string, unknown>[]>;
  workbookMappings?: ParamConfigWorkbookMapping[];

  radioInstances: RadioInstanceConfig[];
}

type RadioInstanceKind = 'nr-cell' | 'lte-cell' | 'gsm-cell' | 'gsm-bts';

interface RadioInstanceConfig {
  // 前端生成的稳定标识，只用于编辑和渲染。
  id: string;

  kind: RadioInstanceKind;

  // 设备侧主要无线实例号，从 1 开始。
  instanceIndex: number;

  // CELL 或 GSM 主 Sheet 对应的参数。
  parameters: Record<string, unknown>;

  plmnList?: IndexedParameterItem[];
  neighborList?: IndexedParameterItem[];
  interFrequencyCarrierList?: IndexedParameterItem[];
  trxList?: IndexedParameterItem[];
}

interface IndexedParameterItem {
  id: string;
  instanceIndex: number;
  parameters: Record<string, unknown>;
}
```

实施时可以继续保留 `sheetParameters` 作为 Excel 无损保存结构，但页面和编译器不能再从数组位置隐式推导实例。推荐增加统一的规范化层，在导入、页面保存和编译之前将数据转换为上述语义模型。

为了降低一次性迁移风险，也可以先采用保留 Sheet 形态的过渡结构：

```ts
sheetParameters: {
  CELL: [
    { 'Cell Index': 1, PCI: 10 },
    { 'Cell Index': 2, PCI: 11 },
  ],
}
```

LTE 过渡结构继续使用已有列：

```ts
sheetParameters: {
  CELL: [
    { '*CELL_NUMBER': 1, '*PCI': 10 },
    { '*CELL_NUMBER': 2, '*PCI': 11 },
  ],
}
```

无论采用独立 `radioInstances` 字段还是过渡结构，主实例号都必须成为持久化数据，而不能只在编译时临时生成。规范化层负责把 `Cell Index`、`*CELL_NUMBER`、`BTS Index` 转换为统一的 `instanceIndex`。

## 5. Excel 工作簿设计

### 5.1 NR/gNB CELL Sheet

NR 的 `CELL` Sheet 一行表示一个设备下的一个小区：

| Serial Number | Cell Index | PCI | NRARFCNDL | Band | DL Carrier Bandwidth |
| --- | ---: | ---: | ---: | ---: | --- |
| SN001 | 1 | 10 | 633984 | 78 | 100 |
| SN001 | 2 | 11 | 634560 | 78 | 100 |
| SN002 | 1 | 20 | 633984 | 78 | 100 |

唯一键为：

```text
Serial Number + Cell Index
```

导入校验规则：

- `Serial Number` 必填；
- `Cell Index` 必须为大于 0 的整数；
- 同一 SN 内 `Cell Index` 不得重复；
- 单元格值继续按照参数映射、枚举、范围和只读规则校验；
- Sheet 物理行顺序只影响展示顺序，不影响实例语义。

### 5.2 LTE/eNB CELL Sheet

LTE 复用现有模板的 `*CELL_NUMBER`，不新增 `Cell Index`：

| *SERIAL_NUMBER | *CELL_NUMBER | CELL_NAME | *ECI | *PCI | *EARFCN_DL | *BANDWIDTH_DL |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| SN001 | 1 | LTE-CELL-1 | 101 | 10 | 38950 | n100 |
| SN001 | 2 | LTE-CELL-2 | 102 | 11 | 39148 | n100 |

唯一键为：

```text
*SERIAL_NUMBER + *CELL_NUMBER
```

`*CELL_NUMBER` 规范化为 `instanceIndex`，默认绑定到 `FAPService.{i}`。它是实例控制列，不作为名为 `CELL_NUMBER` 的参数下发。LTE 的 `NETWORK_ENABLE`、邻区、异频载波等 Sheet 如果包含主实例相关参数，也必须携带 `*CELL_NUMBER`，才能归属到正确的 `FAPService` 实例。

### 5.3 GSM Sheet

GSM 保留现有 `GSM` 主 Sheet，但需要按产品明确实例列：

- BM（BTS 型设备）产品增加 `Cell Index`，绑定 `GsmBTSCellDT.{i}`；
- BSC 产品增加 `BTS Index`，绑定 `DeviceGSM.Bts.{i}`；
- 同一工作簿只能使用与所选产品匹配的一种实例列；
- GSM 主 Sheet 唯一键为 `Serial Number + Cell/BTS Index`。

BSC 的子实例应拆分为独立 Sheet：

| Sheet | 唯一键 | 典型路径 |
| --- | --- | --- |
| `GSM_BTS` | `Serial Number + BTS Index` | `DeviceGSM.Bts.{bts}` |
| `GSM_NEIGHBOR_2G` | `Serial Number + BTS Index + Neighbor Index` | `Bts.{bts}.Neighbor2G.{neighbor}` |
| `GSM_NEIGHBOR_4G` | `Serial Number + BTS Index + Neighbor Index` | `Bts.{bts}.Neighbor4G.{neighbor}` |
| `GSM_TRX` | `Serial Number + BTS Index + TRX Index` | `Bts.{bts}.Trx.{trx}` |

如果为了兼容现有模板继续使用主 Sheet 名 `GSM`，它等价于上表的 `GSM_BTS`；新子实例 Sheet 仍应使用独立名称，不能把主实例和子实例混在同一行数组中。

### 5.4 设备级 Sheet

`DEVICE`、`1588_CONFIGURATION` 等设备级 Sheet 每个 SN 最多一行，唯一键为 `Serial Number`。重复行应在导入阶段报错，不能通过“最后一行覆盖”静默处理。

### 5.5 主实例子列表 Sheet

存在父子关系的 PLMN、邻区、载波和 TRX 需要同时标识所属主实例和自身实例。以下是 NR PLMN 示例：

| Serial Number | Cell Index | PLMN Index | PLMN ID | Primary |
| --- | ---: | ---: | --- | --- |
| SN001 | 1 | 1 | 46000 | 1 |
| SN001 | 1 | 2 | 46001 | 0 |
| SN001 | 2 | 1 | 46000 | 1 |

PLMN 唯一键为：

```text
Serial Number + Cell Index + PLMN Index
```

NR/LTE 邻区使用相同原则，增加 `Neighbor Index`；异频载波增加 `Carrier Index`；GSM BSC TRX 增加 `TRX Index`。

LTE 需要区分两种 PLMN 模型：

- 路径包含 `PLMNList.{i}` 时，Sheet 使用 `*CELL_NUMBER + PLMN Index`；
- 参数为 `ExistPlmnidList` 等聚合标量时，页面可以编辑列表，但编译结果是当前 `*CELL_NUMBER` 下的单个逗号分隔参数，不输出 `PLMN Index`。

### 5.6 Sheet 与实例列矩阵

| 制式/Sheet | 归属层级 | 显式实例列 |
| --- | --- | --- |
| NR `CELL` | 设备 → NR 小区 | `Cell Index` |
| NR `PLMN` | 设备 → NR 小区 → PLMN | `Cell Index`、`PLMN Index` |
| NR 邻区/载波 | 设备 → NR 小区 → 子实例 | `Cell Index`、对应子实例 Index |
| LTE `CELL` | 设备 → LTE/FAPService 实例 | `*CELL_NUMBER` |
| LTE PLMN/邻区/载波 | 设备 → LTE/FAPService 实例 → 子实例 | `*CELL_NUMBER`、对应子实例 Index |
| GSM BM `GSM` | 设备 → GSM 小区 | `Cell Index` |
| GSM BSC `GSM`/`GSM_BTS` | 设备 → BTS | `BTS Index` |
| GSM BSC 邻区/TRX | 设备 → BTS → 子实例 | `BTS Index`、`Neighbor Index`/`TRX Index` |
| `INTERFACE` | 设备 → 接口 | `Interface Index` |
| `IPSEC` / `NETWORK_IPSEC` | 设备 → 隧道 | `Tunnel Index` |
| `DEVICE` / `1588_CONFIGURATION` | 设备 | 无实例列 |

### 5.7 参数映射 Sheet

`参数映射` Sheet 继续保存“工作表 + 表头 → TRPath”的映射。`Cell Index`、`PLMN Index` 等实例控制列属于系统控制字段，不映射为设备参数，也不进入 NR `<config>` 或 LTE/GSM `<param>` 参数节点。

如果后续新增产品自定义 Sheet，建议在映射元数据中增加实例作用域：

```ts
type WorkbookInstanceScope =
  | 'device'
  | 'nr-cell'
  | 'lte-fap-service'
  | 'gsm-cell'
  | 'gsm-bts'
  | 'primary-plmn'
  | 'primary-neighbor'
  | 'primary-carrier'
  | 'bts-trx'
  | 'interface'
  | 'tunnel';
```

映射元数据还应包含主实例列名和路径绑定，例如 LTE 的 `*CELL_NUMBER → FAPService.{i}`。编译器应以产品实例绑定、作用域和显式 index 解析路径，而不是根据 Sheet 名字、制式名称或物理行号猜测。

### 5.8 历史 Sheet 中混合作用域的拆分

现有模板按业务界面组织字段，同一个 Sheet 可能混合设备级、主实例级和子实例级参数。单实例时这种混合不会暴露问题，多实例时会造成公共参数被重复、冲突或错误绑定。新模板和规范化层必须以实际 TRPath 作用域为准：

| 现有位置 | 典型字段 | 实际作用域 | 多实例处理 |
| --- | --- | --- | --- |
| NR `CELL` | gNB Name、gNB ID、gNB ID Length | FAP/gNB 级 | 移到 `DEVICE`/公共配置，每个 SN 一份 |
| NR `CELL` | PCI、NRARFCN、带宽、功率 | NR 小区级 | 保留在带 `Cell Index` 的小区行 |
| NR `PLMN` | NCI、TAC | NR 小区/TA 级 | 携带 `Cell Index`，固定 TA 实例保持 1 |
| NR `PLMN` | PLMN ID、Primary、切片字段 | PLMN 子实例级 | 同时携带 `Cell Index` 和 `PLMN Index` |
| NR `PLMN` | AMF IP、NGU Bind Interface | FAP 级独立列表 | 拆为 AMF/接口列表，使用各自 index |
| LTE `CELL`/`NETWORK_ENABLE` | Cell、PLMN、MME 等字段 | 可能是 `FAPService` 级、子列表或设备级 | 依据产品 TRPath 分类；属于主实例的 Sheet 必须带 `*CELL_NUMBER` |
| GSM `GSM` | IPA、Unit ID、Remote IP | GSM 小区/BTS 级 | 随 `Cell Index`/`BTS Index` 保存 |
| GSM `GSM` | Synchronization、WAN、OMC | 通常为设备级 | 拆到设备级配置，每个 SN 一份；最终以产品 TRPath 为准 |

导入器处理当前模板的混合字段布局时，规范化层应按 `workbookMappings.trPath + instanceScope` 将列拆到正确作用域。设备级字段在同一 SN 的多实例行中重复出现时，只允许值完全相同；不同值直接报冲突。新导出的工作簿应避免继续生成混合作用域的 Sheet。

## 6. 页面交互设计

### 6.1 主要无线实例列表

参数配置详情增加主要无线实例列表，每个实例使用独立 Card 或折叠面板：

- NR/LTE/BM 标题显示“小区 1 / 小区 2”，BSC 标题显示“BTS 1 / BTS 2”；
- 同时显示实际 `instanceIndex`，表单字段标签按制式显示为 `Cell Index`、`*CELL_NUMBER` 或 `BTS Index`；
- 支持新增、复制、删除；
- NR/LTE 小区内编辑 PCI、频点、带宽、功率、标识等参数；
- GSM BM 小区实例内编辑 IPA、Unit ID、Remote IP、Bind IP 等参数；
- GSM BSC 实例内编辑 BTS、小区、切换参数，以及 2G/4G 邻区和 TRX 子列表；
- 仅展示当前产品参数模型真实支持的 PLMN、邻区、载波、TRX 等子列表；
- 设备级网络、时钟、管理和 IPsec 参数继续在小区列表之外展示。

### 6.2 新增和复制

- 新增实例默认分配 `max(instanceIndex) + 1`；
- 复制实例复制参数值，但生成新的前端 `id` 和新的 `instanceIndex`；
- 不建议自动复用已删除的空洞 index，避免用户误认为旧设备实例被覆盖；
- 如果产品明确要求实例连续，可在保存时增加产品级连续性校验。

### 6.3 删除和修改 index

- 删除实例不得自动重排剩余 `instanceIndex`；
- 可以允许用户修改实例号，但保存前必须检查重复和合法范围；
- 修改已经执行过的策略时，应提示 index 变化会改变设备侧目标实例；
- 至少保留一个小区还是允许零小区，由产品参数模型和自配置模块校验决定，不在通用组件中硬编码。

### 6.4 页面与 Excel 一致性

页面编辑和 Excel 导入必须进入同一个规范化模型。禁止维护两套独立的字段到 TRPath 映射。导入后页面应完整显示所有小区；页面保存后再次导出，实例号和参数值应保持不变。

## 7. 后端编译设计

### 7.1 编译上下文

将当前宽泛的 `cellIndex`、`listIndex` 参数升级为明确的实例上下文：

```go
type instanceContext struct {
	PrimaryIndex   int
	CellIndex      int
	BTSIndex       int
	PLMNIndex      int
	NeighborIndex  int
	CarrierIndex   int
	TRXIndex       int
	InterfaceIndex int
	TunnelIndex    int
}
```

`PrimaryIndex` 是从 Excel/页面规范化得到的主要无线实例号；`CellIndex`、`BTSIndex` 是经过产品绑定后的语义值。不同产品使用不同路径段：

| 制式/产品 | TRPath 实例段 | 取值 |
| --- | --- | --- |
| NR | `FAPService.{i}` | 固定 1，除非产品实例绑定另有声明 |
| NR | `CellConfig.{i}` | `PrimaryIndex` / `CellIndex` |
| LTE | `FAPService.{i}` | `PrimaryIndex` / `CellIndex` |
| LTE | `CellConfig.LTE` | 非实例段，不替换 |
| GSM BM | `GsmBTSCellDT.{i}` | `PrimaryIndex` / `CellIndex` |
| GSM BSC | `DeviceGSM.Bts.{i}` | `PrimaryIndex` / `BTSIndex` |
| 通用子实例 | `PLMNList.{i}` | `PLMNIndex` |
| 通用子实例 | 邻区对象 `{i}` | `NeighborIndex` |
| 通用子实例 | 异频载波对象 `{i}` | `CarrierIndex` |
| GSM BSC | `Trx.{i}` | `TRXIndex` |
| NR | `NguIpBind{i}` | `InterfaceIndex` |
| NR/LTE | `FAP.Ipsec.{i}` | `TunnelIndex` |

不能再使用全局字符串替换规则把所有 `FAPService.{i}` 固定为 1。编译器应先读取产品实例绑定，再按照完整对象片段替换。对于同一路径中的多层 `{i}`，必须根据对象前缀分别取主实例和子实例；无法识别的占位符直接报错。

### 7.2 编译流程

```text
策略 JSON
  → 按 SN 选择唯一设备配置
  → 根据制式和产品实例绑定规范化设备级、主实例级和子实例级参数
  → 校验实例号及层级引用
  → 根据参数映射解析参数定义
  → 使用 instanceContext 解析具体 TRPath
  → 检查重复路径和值冲突
  → 生成自开站 XML
  → 走既有 ACS Download 下发流程
```

### 7.3 编译校验

编译阶段必须拒绝以下情况：

- 同一 SN 存在多个顶层配置对象；
- 同一设备存在重复 `instanceIndex`；
- PLMN/邻区/载波/TRX 引用不存在的父实例；
- 同一父实例内存在重复子实例 index；
- TRPath 仍包含未解析的 `{i}`；
- 两个输入值解析到同一具体 TRPath 且值不同；
- 参数未注册、只读、类型错误、枚举或范围非法；
- 设备产品不支持配置中使用的实例路径。

此外必须检查实例列与产品绑定匹配，例如 BSC 文件不得使用 NR `Cell Index` 绑定规则，LTE `*CELL_NUMBER` 不得被编译为普通设备参数。

错误信息应包含 SN、Sheet、Excel 行号、实例号和参数表头，便于定位导入文件。

### 7.4 设备实例存在性

本设计负责把逻辑实例号解析为具体 TRPath，不隐式执行 `AddObject`。执行前提是目标设备/产品支持对应实例，或者自开站 XML 协议允许设备在应用文件时创建目标实例。

如果某产品要求先创建对象再设置参数，需要在产品能力模型中显式声明，并设计独立的对象创建编排；不能由通用参数编译器猜测。

## 8. 兼容与迁移

### 8.1 旧单小区配置和单行 Excel

没有显式实例号的旧单实例配置和单行 Excel 按以下规则读取：

- NR/LTE 同一 SN 在 `CELL` 中只有一行时，补为 `instanceIndex=1`；LTE 如果已有 `*CELL_NUMBER` 则以该值为准；
- GSM 同一 SN 在 `GSM` 中只有一行时，补为 `instanceIndex=1`；
- 页面旧字段映射到 `radioInstances[0]`；
- 保存后写入新结构；
- 导出时按制式输出 `Cell Index`、`*CELL_NUMBER` 或 `BTS Index`。

同一 SN 在主实例 Sheet 中存在多行但缺少该制式要求的实例列时，直接拒绝导入并提示补充实例列，不再按物理行序推断实例。PLMN、邻区、载波和 TRX 等二维实例数据同样不得使用行序推断父子关系。

### 8.2 同 SN 多个顶层对象

历史数据如果存在同 SN 多个 `paramConfigList` 对象，需要在读取时执行一次规范化：

1. 将第一个对象作为设备级配置来源；
2. 将各对象的主实例字段转换为不同的 `radioInstances[]` 项；
3. 检测设备级参数冲突，有冲突则停止迁移并提示人工处理；
4. 保存后只保留一个顶层对象。

## 9. 实施拆分

### 阶段一：契约和编译器

- 增加 NR、LTE、GSM BM、GSM BSC 模板及旧单实例模板往返测试。

### 阶段三：页面多小区编辑

### 阶段四：端到端验证

- 使用支持多小区的真实设备或模拟器验证 Download、应用结果和 105/106 状态闭环。

## 10. 测试与验收标准

### 10.1 单元测试

- 单实例旧配置按制式自动补 `instanceIndex=1`；
- NR 同 SN 的两行 CELL 使用 `Cell Index` 导入为两个小区；
- LTE 同 SN 的两行 CELL 使用 `*CELL_NUMBER` 导入为两个 `FAPService` 实例，且控制列不下发；
- GSM BM 同 SN 两行解析为两个 `GsmBTSCellDT` 实例；
- GSM BSC 同 SN 两行解析为两个 `Bts` 实例；
- Excel 行重排不改变显式实例号；
- 重复 `instanceIndex` 导入失败；
- 删除实例 1 后，实例 2 仍保持 `instanceIndex=2`；
- 同一 NR 小区可包含两个 PLMN，并解析为同一 `CellConfig` 下的 `PLMNList.1/2`；
- LTE `PLMNList` 正确解析主 `FAPService` 和子 `PLMNList` 两层实例；
- LTE `ExistPlmnidList` 按主实例生成一个聚合标量，不错误生成 `PLMNList` 实例；
- 两个小区各自的 PLMN 不发生交叉；
- BSC 两个 BTS 的 2G/4G 邻区和 TRX 不发生交叉；
- NR 固定的 `FAPService.1`、`TA.1`、载波列表固定实例不会被主实例号覆盖；
- 设备级 Sheet 重复行导入失败；
- 导入 → 页面编辑 → 导出 → 再导入保持语义一致；
- 旧单小区模板仍可导入；所有多实例文件都必须包含制式对应的实例列；新模板始终带实例列。

### 10.2 后端/XML 验收

NR/gNB 两个小区至少应生成：

```text
Device.Services.FAPService.1.CellConfig.1....PCI
Device.Services.FAPService.1.CellConfig.2....PCI
```

如果小区 1 配置两个 PLMN、小区 2 配置一个 PLMN，还应分别得到：

```text
...CellConfig.1....PLMNList.1.PLMNID
...CellConfig.1....PLMNList.2.PLMNID
...CellConfig.2....PLMNList.1.PLMNID
```

LTE/eNB 两个小区至少应生成：

```text
Device.Services.FAPService.1.CellConfig.LTE....PhyCellID
Device.Services.FAPService.2.CellConfig.LTE....PhyCellID
```

不得错误生成 `CellConfig.1.LTE`，也不得继续把所有 LTE `FAPService.{i}` 固定为 1。

GSM BM 两个实例至少应生成：

```text
Device.Services.GsmBTSCellDT.1.IPAUnitID
Device.Services.GsmBTSCellDT.2.IPAUnitID
```

GSM BSC 两个 BTS 及其子实例至少应生成：

```text
DeviceGSM.Bts.1.IpaUnitId
DeviceGSM.Bts.2.IpaUnitId
DeviceGSM.Bts.1.Neighbor2G.1....
DeviceGSM.Bts.2.Trx.1....
```

所有制式的 XML 中都不得出现未解析的 `{i}`；`Cell Index`、`*CELL_NUMBER`、`BTS Index` 和各种子实例 Index 不得作为普通参数节点输出。

### 10.3 页面验收

- NR/LTE/GSM BM 可以新增、复制和删除小区，GSM BSC 可以新增、复制和删除 BTS；
- 删除主要无线实例不会改变其他实例的设备实例号；
- 重复或非法 index 无法保存；
- 导入多实例文件后每个小区/BTS 及其产品支持的子实例均可编辑；
- 保存并重新打开策略后数据完整；
- 导出文件中的 Sheet 行和实例号与页面一致；
- 所有新增用户可见文案通过 i18n 管理。

## 11. 风险与待确认项

| 风险/问题 | 处理建议 |
| --- | --- |
| 不同产品的小区实例上限不同 | 从产品参数模型或产品能力配置读取，通用层只校验正整数和唯一性 |
| 某些设备要求连续实例号 | 作为产品能力校验，不全局硬编码 |
| 某些设备不能通过 XML 创建不存在的实例 | 联调前确认设备行为；需要创建对象时另行设计对象创建流程 |
| LTE 主实例位于 `FAPService.{i}`，NR 主实例位于 `CellConfig.{i}` | 为每个产品维护并校验实例绑定，禁止全局替换规则 |
| GSM 的实例可能表示小区或 BTS | 由产品模型决定 `kind`、页面名称、Excel 列名和路径绑定 |
| LTE PLMN 同时存在聚合标量和列表对象 | 根据具体参数定义编译，不能仅根据页面列表形态判断 |
| 固定实例和动态实例同时出现在一个 TRPath | 以完整对象片段绑定，固定 `.1` 原样保留 |
| 多实例文件缺少 PLMN/邻区/载波/TRX 父实例信息 | 不猜测二维关系，要求用户补充实例列 |
| Sheet 名称和实例语义存在产品差异 | 在参数映射元数据中维护 `instanceScope` 和实例列绑定 |
| 页面一次展示大量小区字段性能下降 | 使用折叠面板、按需渲染和局部校验 |

实施前需要逐产品确认：主实例路径、主实例列名、最大实例数、实例是否必须连续、XML 是否支持创建实例、各子实例的真实 TRPath 层级，以及多实例配置生效后的 105/106 上报口径。至少应覆盖当前 NR BaiBNQ、LTE BLN/BLQ/MLN/MLQ/ENB_DEFAULT、GSM BM 和 GSM BSC 产品族。

## 12. 完成定义

满足以下条件后，多小区参数配置可视为完成：

1. 同一设备只保存一个顶层参数配置对象；
2. 页面、Excel、策略 JSON 和编译器使用同一套显式主实例及子实例语义；
3. NR、LTE、GSM BM、GSM BSC 都具有明确的主实例列、路径绑定和子实例规则；
4. 单实例旧配置和旧单行 Excel 可兼容导入，所有多实例 Excel 必须提供制式对应的实例列；
5. NR `CellConfig`、LTE `FAPService`、GSM `GsmBTSCellDT`、BSC `Bts` 及其子实例可稳定生成正确的具体 TRPath；
6. 固定实例不会被动态实例号覆盖，控制列不会作为普通参数下发；
7. 删除和重排行为不会静默改变设备实例；
8. 各制式的单元、前端、XML 和真实设备/模拟器端到端验证全部通过；
9. 自开站参数仍统一通过 XML Download 链路下发。

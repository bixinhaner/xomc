# OMC 邮件通知范围收敛评审

## 结论

当前实现应按“两条业务流程、一套可靠性底座”收敛：告警管理域负责告警邮件，通知中心
负责 Zed Mobile 状态汇总邮件、消息、邮件通道健康和投递审计；KPI 定时报表另行评审，
不并入本阶段。核心操作流程承接老
OMC，但界面、权限、并发控制和可靠性可按当前架构优化，不要求像素级或表结构级复制。

该方案符合小基站 OMC 的业务边界：告警 occurrence 是事实源，通知是异步下游；设备和
设备组是权限及作用域主体；邮件内容使用告警标准字段和后台处理建议；SMTP accepted 只
表示邮件服务器受理；KPI 统计口径继续由 PM 域负责，通知模块不重新计算指标。

## 依据

- 老 OMC 13.0.5 现场页面：告警视图模板中配置启用、Interval、Tolerance Duration、
  收件人和默认收件人，正文不可编辑；KPI Query Template 的 Regular Report 配置发送
  时间、周期和收件人。
- RR #31002、#31315、#31316：告警邮件需包含清除时间和后台维护的处理建议。
- 当前项目 `docs/ref/pm-metrics-knowledge.md`：KPI 查询与导出必须遵循模板查询的
  `statis_type`、15 分钟点和聚合入口矩阵，不能由通用报表模块重新计算。
- 当前架构：告警生命周期 Outbox、JetStream、通知 Inbox、持久化 schedule、逐收件人
  delivery/attempt 和渠道熔断已经通过本地故障与容量验证，继续保留具有明确运营价值。

## 保留与优化

| 能力 | 决策 | 原因 |
| --- | --- | --- |
| 告警范围、设备/设备组、级别 | 保留并优化 | 与老业务一致，设备组比逐设备配置更适合规模运维 |
| 实时/10/30/60 分钟与 Tolerance | 当前保留 | 已有现场证据；任意周期等待明确需求再扩展 |
| 固定邮箱和默认收件人 | 保留，改为专用管理 | 完成老业务闭环，不暴露通用联系组概念 |
| 后台固定邮件正文 | 保留并增强 | 增加告警名称、网元、原因、具体问题、处理建议和清除时间 |
| revision/ETag、地址加密、RBAC | 优化 | 防并发覆盖、明文泄漏和越权配置 |
| Outbox、幂等、重试、熔断、逐收件人历史 | 保留 | 属于运营商级可恢复和可审计要求，不是过度设计 |
| 通道页面 | 收敛为只读健康与验证 | SMTP 参数由部署配置管理，页面不暴露原始 JSON/Secret |

## 删除或停止暴露

- 通用跨业务通知规则编辑器及其前端 API/Hooks/类型；
- 操作员可编辑的邮件主题、HTML、正文、变量和模板发布页面；
- 通用联系组页面，默认邮箱改由告警邮件专用接口维护；
- SMS Kafka、直连 SMS、回执模拟、quiet hours、升级链和重复提醒界面；
- 原始 SMTP 参数 JSON 和 Secret 引用在线编辑；
- 老的批次邮件模板/历史管理 API 页面入口。

内部版本化规则、不可变模板版本、schedule、delivery 和 attempt 表继续作为执行与审计
实现细节使用。删除管理面不等于删除这些可靠性数据模型。

## KPI 定时报表边界

KPI 配置附着于现有 Query Template，只包含启用、发送时间、周期和收件人。Worker 持久化
领取到期订阅，计算系统时区下的上一个完整半开窗口，创建 `pm_kpi_export` 异步任务；导出
成功后以现有对象存储文件作为单附件发送。调度幂等键必须包含订阅 ID 和时间窗。不得伪造
告警 occurrence，也不得调用 `internal/report` 生成第二套 KPI 口径。

## 2026-08-06 复审修复状态

- 告警邮件专用端点已登记到 API 权限基线；非超管的列表、详情、更新和删除均按设备组与
  制式授权范围校验。更新同时校验旧范围和新范围，不能借修改操作接管越权规则。
- 默认收件人包含全局邮件地址，仅内置超管可读写；前端对非超管不请求、不展示该入口。
- 告警邮件一次表单保存已改为单数据库事务写入不可变版本、发布指针和启停指针，失败时
  整体回滚，不再出现“发布成功但启用失败”的半成功状态。
- 告警邮件列表会先从通用规则头读取完整不可变版本，再校验内置邮件通道和固定后台模板；
  该逻辑只位于业务适配层，避免为解决列表展示而改变通用规则仓储的浅列表契约。
- 逐设备选择改为服务端搜索并单独回读已选设备，不再静默截断到前 200 台；规模运维仍
  推荐优先使用设备组。
- Zed Mobile 汇总统计、固定正文、本地时区、持久化运行、配置 API 和逐收件人 attempt
  审计已接入；配置默认 disabled。周期、设备范围和收件人仍需老 OMC/业务确认；真实
  SMTP、重启恢复、多实例领取和浏览器验收仍未完成。

## 明确排除与上线门禁

Zed Mobile #98018 的实现已具备但仍保持 disabled；周期、设备范围和收件人确认、真实阿里
企业邮箱测试账号、白名单收件人、可控小基站 raised/clear 样本、Shadow 命中与权限对比
以及现场容量数据齐全后，才能进入试点。Office365 #72785 和 SMS 不在本阶段。

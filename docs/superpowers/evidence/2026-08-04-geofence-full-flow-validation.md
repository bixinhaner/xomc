## 1. 验证结论

新项目已经覆盖电子围栏的配置闭环：系统总开关、运营商设置、围栏创建/发布、查询/定位、编辑、批量绑定预览、异步绑定任务、单设备移除、启用/禁用、归档、影响预览、原因记录和审计入口均已具备。

本次浏览器回归同时发现并修复了一处确定缺陷：批量绑定任务汇总已经成功时，任务设备明细仍显示“待处理”。修复后，任务进入终态会同时刷新绑定列表、地图和任务明细缓存。

代码已经覆盖老系统控制链：`enforce` 越界、禁用或归档可生成幂等去激活动作，SPV 后自动
GPV 回读，回区只恢复本系统已验证去激活且实际改动的参数。控制结果独立持久化并展示请求值、
回读值和失败原因，不再把普通任务结束视为成功。

当前仍不能声称完成生产替代：104 授权环境尚未部署本分支，也没有完成真实设备 SPV+GPV、
离线、超时、重试和恢复验收。仓库及老系统证据均未证明存在独立 SecGW 接口，因此没有增加
猜测式安全网关调用。
3. 老系统本轮没有成功验证“编辑页单独移除设备”的实际点击结果；入口对应图标未暴露为可操作控件。老文档描述支持删除设备，新系统已经提供显式“移除绑定”并要求原因。
4. 位置来源规则已经定版并落地：第三方位置在 `tr069/external` 两种模式下均可受理；TR069 GPS
   仅在默认 `tr069` 模式受理。显式配置为 `external` 后可防止设备 GPS 覆盖第三方位置，接口调用
   本身不会切换模式；观测按 `updateTime`/观测时间防乱序，相同时间幂等。

## 2. 需求基线

### 2.1 105820 核心目标

1. 地图绘制不规则多边形合法区域。
2. 围栏按运营商隔离，并受系统级、运营商级开关控制。
3. 设备位置更新后判断进出围栏。
4. 离开围栏触发去激活，进入围栏触发激活。
5. 支持创建、编辑、删除、查询、关联设备查看。
6. 支持批量指定设备进入围栏，设备当前只生效一个围栏。
7. 支持控制记录和日志查询。
8. 第三方船舶平台可通过 `/fence/batchUpdateDeviceLocation` 批量上报位置。

1. 点击临时围栏行的编辑图标。
2. `Modify` 抽屉显示：Enable、Fence Name、Redraw the fence、Device List、Batch Input。
3. 将名称修改为 `codex-flow-20260804-1645-edited`。

### 3.6 编辑区域入口

`Modify` 抽屉存在 `Redraw the fence` 按钮。它与设备列表编辑是两个独立入口，说明老系统把“重新绘制区域”和“增删设备”视为不同变更，不应在新项目中合并成一次隐式操作。

本轮为避免再次覆盖地图上的专用测试区域，没有提交第二套坐标；入口和表单行为已核实。

### 3.7 单设备移除入口

编辑表格 DOM 中存在 `.fence-device-bt / el-icon-circle-close`，老文档也描述可删除设备；但本轮页面始终将该控件设为不可见，鼠标悬停后仍未成为可点击控件，因此没有伪造“移除成功”结论。

需要后续人工复核以下条件是否决定按钮显示：

- 围栏是否必须启用；
- 设备是否必须是手工绑定而不是区域自动识别；
- 当前用户权限；
- 固定列与滚动列的老前端渲染缺陷。

### 3.8 启用和禁用

1. 在围栏列表点击临时围栏开关。
2. 开关 `aria-checked` 变为 `true`，围栏启用。
3. 再次点击开关，围栏回到禁用。

实际行为：本次没有出现二次确认弹窗。老系统对单围栏启停是直接提交，操作风险提示不足。

### 3.9 删除围栏

1. 确认临时围栏处于禁用状态。
2. 点击该行删除图标。
3. 老系统弹出 `Confirmation`。

5. 点击 `Delete`。
6. 临时围栏从列表消失。

业务含义：老系统把删除围栏与围栏内设备自动去激活绑定在一起；删除不是单纯删除地图图形。

## 4. 新项目本地实际操作记录

### 4.1 环境与入口

1. 在独立工作区启动 `npm run dev:mock -- --host 127.0.0.1 --port 3005`。
2. 打开 `/topology/gis-map`。
3. 点击地图顶部 `电子围栏`。
4. 面板显示 2 个初始围栏和 `电子围栏总开关`。
5. 总开关显示“已开启，按运营商开关生效”。

### 4.2 创建和发布

1. 点击 `新增围栏`。
2. 面板隐藏，页面提示在地图绘制保护区域。
3. 绘制四点多边形并双击结束。
4. 打开 `新增电子围栏` 对话框。
5. 实际字段：
   - 围栏名称；
   - 运营商；
   - 越界动作；
   - 连续越界次数；
   - 连续回区次数；
   - 绘制区域；
   - 保存并发布。
6. 名称填写 `本地全流程-20260804`。
7. 点击 `保存并发布`。
8. 页面提示“围栏版本已发布”。
9. 围栏总数从 2 变为 3，新增围栏状态为“已启用”。

### 4.3 批量绑定预览

1. 在新增围栏行点击 `绑定设备`。
2. 输入 `MOCK-SN-003`。
3. 点击 `绑定设备预览`。
4. 返回：
   - 可绑定：1；
   - 将从其他围栏移入：0；
   - 已跳过：0。
5. 输入操作原因 `105820 全流程验证`。
6. 点击 `创建绑定任务`。

### 4.4 异步绑定任务

1. 页面提示“批量绑定任务已创建”。
2. 初始状态：执行中，已完成 0/1。
3. 轮询后汇总状态：执行成功，已完成 1/1。
4. 已绑定设备区出现：
   - 名称：杭州滨江站；
   - SN：`MOCK-SN-003`；
   - 状态：活动；
   - 位置判定：尚无成功判定。

发现缺陷：汇总已经成功时，明细行仍显示“待处理”。原因是任务查询进入终态后只刷新绑定列表和地图，没有刷新任务明细查询。

修复：任务进入终态时同时失效 `jobItemsRoot(jobId)` 缓存，确保明细重新读取成功状态。

### 4.5 单设备移除

1. 点击已绑定设备的 `移除绑定`。
2. 弹出 `围栏状态变更影响确认`。
3. 警告：移除绑定只停止该规则后续检查，不会自动恢复或重新激活设备。
4. 输入原因 `105820 全流程验证后恢复`。
5. 点击确认。
6. 设备状态变为“已移除”。

与老系统相比，新系统的单设备移除入口更明确，并强制填写原因；同时明确不做隐式恢复，安全性更高。

### 4.6 禁用围栏

1. 关闭绑定抽屉。
2. 点击测试围栏的 `禁用围栏`。
3. 影响预览显示：受影响绑定数 0、受影响设备数 0、活动批任务数 0。
4. 警告：禁用围栏只停止后续检查，不会自动恢复或重新激活设备。
5. 输入原因并确认。
6. 围栏状态变为“已禁用”。

### 4.7 归档围栏

1. 在已禁用围栏点击 `归档围栏`。
2. 影响预览再次显示绑定、设备和活动任务数量。
3. 警告：归档会移除当前绑定，不会恢复设备原围栏归属，也不会自动恢复或重新激活设备。
4. 输入原因 `105820 全流程验证清理`。
5. 点击确认。
6. 临时围栏消失，围栏总数恢复为 2。

## 6. 后续必须开发或确认的事项

### P0：真实设备控制验收

代码已固定 IPSec/RF 产品映射、动作幂等、SPV/GPV 关联回读、部分失败和恢复所有权。剩余
工作只在授权测试站完成：实际实例解析、可写性、0/1 语义、离线/超时/重试、回读不一致和
恢复顺序。若设备侧或老后端能证明存在独立 SecGW 协议，再补充该步骤；当前不做占位实现。

### P0：禁用/归档控制验收

安全策略已经定版：禁用或归档时，只对活动绑定、最后确认在围栏内且策略明确为
`deactivate` 的设备提交幂等去激活；`observe` 围栏不创建设备任务，已在围栏外的设备不重复
制造控制边沿，`unknown` 不自动猜测，流程也不自动激活。

当前剩余工作不是重新讨论策略或扩展代码，而是取得真实设备证据：

- 去激活任务的设备回执和最终成功条件；
- 部分参数失败、离线、超时和重试后的状态；
- 归档后控制记录仍可查询；
- 重新启用后先重新评估位置，只有存在本系统已完成的去激活记录才允许回区激活。

### P1：位置来源运行时验收

位置来源已按兼容矩阵实现：第三方平台位置在默认 `tr069` 和显式 `external` 模式均可受理；
TR069 GPS 只在 `tr069` 模式受理。船载设备可显式配置为 `external` 防止设备 GPS 覆盖。
运行时仍需验证过期 `updateTime`、重复批次、设备时钟漂移和来源切换审计，但这些属于验收项，
不再是待定业务规则。

### P1：运行时验收

数据库基线迁移、真实 HTTP 接口、系统/运营商双开关和页面权限已在独立全栈环境验证。上线前
仍需验证任务重启恢复、1000 设备批量上报压测、并发围栏修改、审计/失败 CSV，以及真实设备

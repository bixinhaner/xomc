# Issue #101：设备列表 GPS 经纬度同步问题分析与修复方案

## 问题范围

本问题包含四个相互关联、但根因不同的现象：

1. MLN、MLQ、BLQ 基站已经上报经纬度，设备列表仍显示 `--`。
2. BaiBLQ 提示经纬度有差异，但确认框中显示的值与列表一致，用户无法看出差异在哪里。
3. 用户确认采用设备上报坐标后，页面仍显示黄色警告三角形。
4. 英文界面的确认框仍出现中文。

黄色三角形的业务含义必须保持为“OMC 已接受坐标与设备最新上报坐标存在待处理差异”，不能替换为永久显示的操作图标。

## 问题一：设备已经上报，经纬度仍不显示

### 现象与证据

- BLQ 本地管理页面能够显示经度 `115.366462`、纬度 `25.92416`，证明设备 GNSS 已取得坐标。
- TR069 报文中能够看到 `Device.FAP.GPS.LockedLongitude` 等设备私有参数。
- OMC 设备列表显示 `--`，说明问题发生在“参数同步到 OMC 并投影到设备信息”的链路，而不是设备 GNSS 本身。

### 根因

MLN、MLQ、BLQ 的产品参数模型会把设备私有路径 `Device.FAP.GPS.*` 映射到 OMC 统一路径 `Device.DeviceInfo.SAS.FAP.GPS.*`。设备列表发起的局部参数同步却只请求了设备私有路径，未请求参数模型实际用于匹配和存储的统一路径，因此同步任务即使显示完成，也可能没有取得能够写入 `device_info` 的坐标值。

此外，原后端读取顺序优先使用设备私有路径，统一路径和私有路径同时存在时可能选中旧值；原实现也只识别第一组经纬度，没有处理 MLN/MLQ 的 `LockedLongitude2/3`、`LockedLatitude2/3` 备用槽位。

### 修复方案

- 设备列表局部参数同步只请求 SAS 统一标准路径第 1、2、3 组，由现有 Translator 按产品参数模型转换为设备实际私有路径；产品不支持的槽位自然忽略。
- 经纬度读取优先级统一为：统一路径第 1、2、3 组，随后才回退到历史私有路径第 1、2、3 组。
- 只接受同一组槽位中的完整经纬度对，避免把不同槽位的经度和纬度拼成无效坐标。
- 私有路径只作为数据库历史存量值的读取兼容，不从局部同步接口下发；不修改 XML，也不在前端硬编码具体产品型号。

### 验收标准

- 部署修复版本后，对一台已上报坐标的 BLQ 执行一次设备列表参数同步。
- 设备列表显示 `115.366462 / 25.92416`，刷新页面后仍存在。
- MLN、MLQ 仅第二或第三组槽位有完整坐标时，列表也能正常显示。

## 问题二：提示存在差异，但确认框显示一致

### 根因

差异判断比较的是两组数据：OMC 当前已接受坐标与设备最新上报坐标。原确认框却只显示设备列表中的一组坐标，并把它同时当成确认内容，导致即使后台确实检测到差异，用户看到的仍是与列表完全相同的数值。

问题一中的错误路径优先级还可能让后台用旧私有路径与新统一路径比较，进一步制造看似异常的差异。

### 修复方案

- 确认框分别显示“OMC 当前坐标”和“设备上报坐标”。
- 同时显示两点之间的水平差异距离，便于判断差异是否合理。
- 同一轮参数同步将 GPS 高度写入设备上报观察记录；历史观察记录高度为空时，弹窗回退到列表最新 GPS 高度，避免把设备已上报的 `174` 错误显示成 `--`。
- 差异计算与展示统一使用后端返回的 `LocationSync.accepted` 和 `LocationSync.reported`，不再从列表显示值反推。

### 验收标准

- 两组坐标不同时，确认框清楚显示两组数值和差异距离。
- 两组坐标相同时，不进入待确认状态，也不显示黄色三角形。

## 问题三：确认后黄色三角形仍不消失

### 根因

原前端只要单元格存在数值就显示图标，没有判断同步状态是否仍为 `pending`；上一次修改还把黄色警告三角形换成了蓝色操作图标，改变了业务语义。

确认接口成功后，原页面丢弃了接口返回的 `in_sync` 结果，只等待重新请求列表。如果重新请求有延迟、失败或命中旧数据，页面就继续保留警告图标。

### 修复方案

- 恢复黄色警告三角形。
- 只有 `LocationSync.status == pending` 且存在设备上报值时才显示警告。
- 确认成功后立即使用接口返回结果更新全部设备列表缓存、详情缓存和 SN 缓存，把状态改为 `in_sync`；随后再重新请求服务器数据进行校验。

### 验收标准

- 存在未处理差异时显示黄色三角形。
- 点击确认且接口成功后，三角形立即消失；刷新页面后不再出现。
- `initialized`、`in_sync`、`no_report` 状态均不显示警告图标。

## 问题四：英文确认框出现中文

### 根因

确认框标题和正文曾来自不同的文案来源，旧部署中的标题没有完全跟随当前语言环境；原回归测试只检查了一个中文标题，没有检查整个英文弹窗，因此混合语言未被及时发现。

### 修复方案

- 标题、字段名、提示语和按钮全部通过同一套国际化资源读取。
- 英文回归测试检查整个弹窗文本，任何汉字都会导致测试失败。

### 验收标准

- 英文环境下弹窗不包含任何中文字符。
- 中文环境下所有新增字段都有对应中文文案。

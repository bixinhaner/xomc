# 在途任务过期竞态根治计划

## 线上证据

- 18 分钟策略生效后仍出现 83 个 `UECountPolicy:GPV` 过期任务。
- 83 个任务全部已经下发；82 个在绝对截止前 90 秒内才下发，另有 1 个在截止后仍被下发。
- 正常完成样本的设备响应耗时 p99 为 5.9 秒、最大 55 秒。
- 原清理器只判断 `expires_at < now()`，会把截止前刚下发、响应仍在途的任务抢先置为 `expired`。
- PostgreSQL 下发栅栏没有检查 `expires_at`，存在截止后继续下发的竞态窗口。

## 修复

1. PostgreSQL 下发栅栏增加绝对截止校验，到期 `pending` 任务不能再变成 `sent`。
2. 过期扫描对已下发任务采用 120 秒有界在途保护，与 ACS idle timeout 对齐。
3. 保护只作用于截止前已经下发的 RPC；未下发任务到点立即过期，超过保护窗口的在途任务仍正常终结。
4. 增加真实 PostgreSQL 回归测试，覆盖到期下发拒绝、新鲜在途保护和陈旧在途终结。

## 验收

- 到期任务不再新下发。
- 截止前已下发且处于正常响应时延范围的任务不被清理器抢先终结。
- 保护窗口有上限，不会让无响应任务无限续命。
- 全量后端、竞态、前端和发布门禁通过；部署后新成熟 cohort 无 `failed/expired`。

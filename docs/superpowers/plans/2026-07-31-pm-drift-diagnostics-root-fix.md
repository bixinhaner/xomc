# PM 漂移诊断可操作性修复计划

## 问题

`PMReportKeysMissingFromLibrary` 告警要求运维检查旧日志消息，但过滤日志只给数量、不输出具体上报名；修复分类后日志消息也已变更。真正出现新厂家键时仍无法直接定位，同时逐文件打印会在万站批次形成日志洪峰。

## 修复

1. 白名单分类阶段收集最多 8 个去重后的真正未知 `report_key` 样本。
2. 仅在文件成功入库、指标计数提交后输出诊断日志，避免 NATS 重投重复记账。
3. 按 carrier/technology 对诊断日志做一分钟限频，防止万站同批次刷屏。
4. 更新 Prometheus 告警说明，使语义和日志检索入口与新分类一致。
5. 用单元测试锁定样本去重/上限和限频行为，再跑完整发布验证。

## 验收

- 已知未路由和明确禁止入库的键不进入未知样本。
- 真正未知键的日志包含可直接搜索的 `report_key_sample`。
- 同一 carrier/technology 一分钟最多一条诊断日志。

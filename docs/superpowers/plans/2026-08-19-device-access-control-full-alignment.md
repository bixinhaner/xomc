## 1. 实施原则

1. 以老项目核心业务等价为门槛，不以页面相似或接口存在为门槛。
2. 已通过104实测的判定、任务门禁和 RF 所有权恢复逻辑尽量复用，不重写。
3. 新系统允许使用更安全的实现替代老操作，例如用可恢复归档替代物理删除、用版本发布替代直接修改启用规则，但业务结果必须等价。
4. 名单、规则、决定、动作、通知分别建模，任何一个阶段成功都不能冒充整个业务成功。
5. PostgreSQL 是最终状态源；Redis、NATS 和页面缓存只用于加速与传递。
6. 所有运营商差异进入 `internal/core/carrier/`，所有 SQL 使用 Squirrel + pgx 参数化。
7. 数据库和权限变化折回三个 `000001` 基线文件，不新增 `000002+`。
8. 前端只维护 V1，用户可见文案全部走 i18n，所有交互必须在真实浏览器验证。
9. 每个工作包独立提交、独立验证，不夹带当前工作树中的离线地图、本地配置或其他用户改动。

## 3. 评审推荐决策

以下均给出推荐默认值，评审可以修改；未确认前不写业务代码。

| 决策 | 推荐方案 |
|---|---|
| 名单格式 | 官方 CSV；兼容80下载样本 |
| 规则维度格式 | SN/TAC/ECGI/IP/GPS 使用老项目等价 XLSX；支持老 CSV 导出回导 |
| `.xls` | 先收集生产样本；确有使用再提供受限解析或离线转换，不盲目引库 |
| 部分成功 | 默认 strict；允许显式 valid_only；replace+valid_only额外二次确认 |
| 名单删除 | 停用而非物理删除 |
| 决定删除 | 可恢复归档，当前有效决定不可归档 |
| IP | 同时支持 CIDR 和任意起止范围 |
| GPS | 同时支持中心半径和经纬度矩形；统一 WGS84 十进制度 |
| 默认动作 | 每运营商配置 reject/review，不允许 accept |
| 系统异常 | 固定 fail_closed；未知设备人工处理仅走候选审核 |
| 特殊平台 | 配置化 bypass profile，命中仍产出决定证据 |
| 动作重试 | 新动作最多3次，30秒/2分钟/10分钟；历史失败不自动重放 |
| 离线动作 | retry_wait，下一次 Inform 唤醒 |
| 导入回滚 | 后续同范围批次存在时，生成新的反向批次，不直接覆盖历史 |
| 通知 | 本轮完成事件、关联和状态；邮件短信通道后置 |
| 复杂审批 | 后置；保留可选变更单号和二次确认，不阻塞核心闭环 |

6. 实现规则 priority、默认动作、失败模式和 bypass profile。
7. 规则维度导入只修改草稿，发布时才触发设备重评。

- 名单工具栏：SN/设备名称查询、模板、导入历史、批量停用；

### WP3：身份与触发收敛

覆盖：AC-01～AC-08、AC-29～AC-33、AC-39。

后端任务：

1. 保存每次 Inform 的身份快照和 request ID。
2. 将设备编码、CloudKey必填规则放入 carrier profile。
3. 身份冲突进入拒绝或候选审核，禁止默认运营商回退。
4. 收敛首次Inform、BOOT、周期Inform、重连、名单/策略/候选/身份变更和手工重评。
5. 重评请求带稳定 trigger type、策略版本、证据版本和事件ID。
6. 同设备并发决定使用数据库锁/租约；Redis只做短期抑制。
7. 统一真实对端IP、可信代理IP和GPS归一化证据。

关键测试：

- CloudKey缺失、设备编码冲突、共享OUI、未知设备；
- 每一种入口重复投递和乱序投递；
- Redis清空后不重复动作；
- 策略发布按SN作用域后台分页重评，不阻塞HTTP请求。

### WP4：动作可靠性与下游安全门禁

覆盖：AC-34～AC-41。

后端任务：

1. 动作状态补充 verifying/retry_wait/dead，保留 failed 兼容。
2. 每次 baseline GPV、SPV、readback GPV 保存独立尝试明细。

4. 实现退避、到期扫描、任务终态对账、Inform唤醒和进程重启恢复。
5. 人工修复必须填写原因并完成GPV验证。
6. 重试前重新检查业务开关、接入状态和RF所有权。
7. 给位置/电子围栏RF开启动作增加 Admission Reader 硬门禁。

关键测试：

## 8. 发布、灰度和回滚

### 8.1 发布前

- 当前本地 `main` 落后且工作树有用户改动；评审通过后从最新接入控制基线创建 `codex/device-access-full-alignment`，隔离无关文件。
- 不主动 pull/push；如果需要更新远端基线，先取得用户授权。
- 保存104当前开关、策略版本、名单、决定、动作和测试设备RF状态。
- 开启关键设备TR069跟踪并确认日志容量。

### 8.2 灰度

1. 先部署 Schema和只读兼容代码，所有新自动行为关闭。
2. 开启批量治理，但只对测试运营商和受限管理员开放。
3. 开启新规则操作符和身份快照，执行新旧双算。
4. 开启动作自动重试前观察错误分类，不重放历史failed。
5. 对一个运营商、一个设备组、两台授权设备执行灰度。
6. 通过后逐步扩大，不一次性重评全部设备。

### 8.3 回滚

- 关闭新增运行时开关，停止新的导入提交、自动重试和通知事件；
- 已完成决定和动作记录不删除；
- 未完成动作由兼容版本保持冻结，不自动反向操作设备；
- 批量名单通过批次反向变更恢复；
- 策略通过发布上一版本内容的新版本恢复；
- RF状态必须以设备GPV回读确认，不能仅依赖数据库回滚。

## 9. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 覆盖导入误停用大量名单 | preview影响数、replace作用域、二次确认、批次回滚 |
| 旧IP/GPS规则被近似转换 | 新增无损操作符，迁移双算和边界测试 |
| 自动重试部署后误操作历史设备 | 历史failed不自动重放，新动作开关灰度 |
| 多Worker重复RF动作 | 幂等键、数据库租约、任务CommandKey、GPV前后检查 |
| 白名单被滥用绕过安全规则 | 高权限、二次确认、原因必填、事件和审计 |
| 特殊平台例外范围过大 | carrier profile、有效期、影响预览和审计 |
| 围栏恢复已拒绝设备 | Admission Reader硬门禁和RF所有权测试 |
| 通知故障反向影响接入流程 | 事务Outbox解耦，通知只消费事件 |
| 迁移数据归属错误 | 运营商分批、摘要对账、身份冲突人工裁决 |
| 当前脏工作树污染提交 | 独立分支/工作树，只暂存本功能路径 |

## 10. 完成定义

开发完成必须同时满足：

1. AC-01～AC-52全部达到“完成标准”；AC-53持续明确排除。
2. 老项目黑白名单、规则和状态管理操作都有新系统等价入口。
3. 老 IP/GPS 规则不丢语义，旧官方导出物可以直接迁移或有受控转换。
4. 决定、任务门禁、设备动作、通知四个结果独立可查。
5. 故障、并发、重启、离线和权限路径全部通过。
6. 104保留原始SOAP、API、数据库、页面和设备物理状态证据。
7. 最终环境开关、策略、名单和测试设备状态清理并与基线核对。

在上述条件全部满足前，正式结论只能写“核心判定闭环通过，老项目全量核心能力尚未完整覆盖”。

# MML 配置 API 快照 Excel 导出设计

## 1. 目标

生成一份基于现有 MML 管理 API 的当前配置快照 Excel，供人工整理分组、核对命令与 Path 关系，并作为后续生成回导脚本的输入底稿。

本次交付只生成独立 `.xlsx` 文件，不新增 MML 页面导出按钮，不修改后端 API，不写入数据库。

## 2. 已确认范围

- 数据范围：现有 API 当前返回的数据集合。
- 不传 `product_class` 或 `device_sn`，导出完整 API 可见树。
- 认证方式：优先使用 `OMC_API_BASE_URL` 与 `OMC_API_KEY` 环境变量；本地环境未配置时，可只读获取本地 OMC 容器提供的 API Key 后再通过 HTTP API 请求。
- 技术字段：保留 API 返回的 UUID、父子关系、排序、来源、保护标记、支持状态等字段。
- Excel 中原始字段与人工调整字段分离，空的调整字段表示保持原值。

现有 API 不暴露 `deleted_at`、`deprecated_at` 等历史状态字段，因此本设计不自行推断或过滤数据库历史记录。工作簿说明页必须明确写出这一限制。

## 3. API 数据流

### 3.1 分组树

调用：`GET /api/v1/mml/group-tree?lang=zh-CN`

用途：获取递归层级、节点路径、节点 ID、节点名称、命令关系和命令树显示信息。不传产品或设备过滤条件。

### 3.2 分组明细

调用：`GET /api/v1/mml/admin/groups`

用途：补充分组的 `param_version`、来源、显示排序和保护标记，并按分组 ID 与树结构合并。

### 3.3 命令明细

调用：`GET /api/v1/mml/admin/commands?source=all&page=1&page_size=1000`

用途：获取完整命令字段，包括命令 ID、命令代码、逻辑代码、名称、操作类型、RPC 方法、描述、目标对象、备注、确认配置、来源和保护标记。

必须根据响应的 `total_pages` 继续请求 `page=2`、`page=3` 等后续页，不能假定单页包含全部命令。

分组树负责提供层级关系，admin 分组/命令列表负责提供管理字段。三者按 ID 合并；如果某个 API 返回了另一接口没有的分组或命令，不静默丢弃，而是在 `接口差异` Sheet 中记录，并在对应明细行标记缺少树关系。

### 3.4 Path 绑定与标准参数元数据

对每个命令调用：`GET /api/v1/mml/admin/commands/{commandId}/sub-fields`

用途：获取命令下全部 sub-field，并使用 API 已富化的标准参数字段：

- SubField ID、命令 ID、标准参数 ID；
- MML Codex、中文/英文显示名称、Path 排序；
- `tr069_path` 作为标准路径；
- 参数类型、访问权限、对象标记、变更生效方式；
- 范围约束、参数说明；
- 默认选中、是否必填；
- `is_supported`、支持模型数、总模型数。

不额外调用全量 `standard-params` 列表作为主数据源，因为 sub-field 接口已经返回每条绑定所需的标准参数元数据。只有在后续发现富化字段缺失时，才按 `param_id` 调用单条标准参数接口补齐。

## 4. 工作簿结构

### 4.1 `配置整理主表`

一行对应一条命令 Path 绑定。包含原始字段：

- 分组层级、分组路径、分组代码、分组名称、父分组路径、分组 ID；
- 参数版本、分组排序、分组来源、分组保护标记；
- 命令 ID、命令代码、逻辑代码、命令显示名称、操作类型、RPC 方法、目标对象；
- SubField ID、Path 的 MML Codex、Path 显示名称、标准参数 ID、标准路径；
- 参数类型、访问权限、变更生效方式、范围约束、参数说明；
- 默认选中、是否必填、是否支持、支持模型数、总模型数、Path 排序。

同时提供人工调整列：

- `调整后分组代码`；
- `调整后分组名称`；
- `调整后父分组路径`；
- `调整后分组排序`；
- `调整说明`。

### 4.2 `分组节点`

一行一个分组节点，包含分组 ID、代码、名称、当前路径、父路径、层级、参数版本、排序、来源和保护标记，以及对应的调整列。

### 4.3 `命令节点`

一行一个命令节点，包含命令 ID、所属分组 ID、命令代码、逻辑代码、中文/英文名称、操作类型、RPC 方法、目标对象、描述、备注、确认配置、`target_paths` 原始值、来源和保护标记。

额外计算并保留 `target_paths` 数量、Path 明细数量和两者一致性结果，便于发现 API 数据链路异常。

### 4.4 `Path绑定`

一行一个命令与标准路径的绑定关系，保留 sub-field 原始技术字段和标准参数富化字段，作为后续回导脚本的主要明细来源。

### 4.5 `导出说明`

记录导出时间、请求的 API 地址和参数、各端点返回数量、工作簿字段说明、数据范围定义、API 限制、异常统计和后续回导注意事项。

### 4.6 `接口差异`

记录分组树、分组列表、命令列表和 sub-field 明细之间的差异，包括记录类型、业务 ID、所在接口、缺少的关联字段和处理结果。该 Sheet 用于人工复核，不从主表中删除异常数据。

## 5. 执行与错误处理

- 所有 GET 请求必须使用有限重试和退避；不在脚本中保存账号、密码或密钥。
- 命令列表按 API 分页完整拉取。
- sub-field 请求使用有限并发，避免瞬时压垮服务。
- 任意必需接口最终失败，导出任务失败，不生成正式 Excel。
- 记录失败的端点、HTTP 状态码、命令 ID、重试次数和错误摘要。
- 对重复分组 ID、命令 ID、SubField ID、命令内标准路径进行一致性检查。
- 对命令 `target_paths` 与 sub-field 标准路径做集合比对；不一致时在命令节点和说明页标记，不静默丢弃数据。

## 6. Excel 格式与验证

- UUID、代码、MML Codex 和路径全部按文本写入；
- 首行冻结，启用筛选，长文本自动换行；
- 原始字段与调整字段使用不同底色；
- 主表按分组路径、命令代码、Path 排序；
- 不写入修改数据库的公式或操作；
- 导出后检查关键 Sheet 的值和列结构；
- 扫描 `#REF!`、`#VALUE!`、`#N/A` 等公式错误；
- 渲染并目视检查全部 Sheet，确认中文、长路径、表头和筛选区域没有截断；
- 最终文件保存到 `outputs/` 下的本次会话唯一目录，并只交付正式 `.xlsx` 文件。

## 7. 非目标

- 不新增后端导出接口；
- 不新增前端导出按钮；
- 不直接执行 Excel 内容回导；
- 不修改 MML 分组、命令、sub-field 或标准参数数据；
- 不把 API 未返回的 `deleted_at`、`deprecated_at` 等字段伪装成已确认状态。

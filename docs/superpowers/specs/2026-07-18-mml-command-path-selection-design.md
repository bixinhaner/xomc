# MML 控制台命令 Path 前置选择设计

> 日期：2026-07-18
> 状态：已确认，待实现
> 范围：`/mml/console` 的“选择命令 → 配置参数”流程

## 1. 背景

当前 MML 控制台在“选择命令”弹框右侧只预览命令关联的 Path。用户确定命令后，才在下一页“配置参数”中选择查询 Path，或为全部可写 Path 填写修改值。

当一个命令包含数百个 Path 时，这个流程有两个问题：

- 用户在选择命令时无法同步限定本次操作的 Path。
- 修改类命令进入下一页后展示全部可写 Path，无法只聚焦本次需要修改的项目。

本次调整把 Path 选择前移到“选择命令”弹框，并让下一页只消费上一页明确选中的 Path。

## 2. 已确认需求

1. 选择查询类命令后，右侧 Path 列表增加复选框，允许多选。
2. 选择修改类命令后，右侧只展示可写 Path，并增加复选框，允许多选。
3. Path 默认全部不选。
4. 未选择任何 Path 时不能进入下一页。
5. 查询类命令的下一页只展示已选 Path，用于执行前确认，不再允许二次选择。
6. 修改类命令的下一页只展示已选 Path，并为每个 Path 填写修改值。
7. `ADD/RMV` 继续使用现有目标对象路径和实例号流程，不纳入 Path 多选。
8. 不修改后端接口或 MML 执行协议。
9. 最终在 `http://172.17.9.239:8081/mml/console` 使用真实浏览器验证。

## 3. 方案选择

### 3.1 采用方案：命令定义与本次 Path 选择分离

父页面分别维护：

- `command`：完整命令定义及其全部可执行 Path。
- `selectedPathKeys`：本次操作选中的 Path 字符串集合。

选择状态不通过裁剪 `CommandItem.paramPaths` 表达。这样可以保持 `CommandItem` 的“完整命令定义”语义，也便于重新打开命令弹框时回显选择、切换命令时清空状态，并避免后续功能误把“本次选择”当成“命令完整能力”。

### 3.2 未采用方案

- **在确定命令时裁剪 `CommandItem.paramPaths`**：改动较小，但会混淆命令定义与用户选择，重新编辑和派生实例槽位时容易丢失完整信息。
- **引入完整向导 Store**：扩展性更强，但当前状态只在 MML Console 页面及两个弹框间传递，引入全局 Store 会扩大范围。

## 4. 交互设计

### 4.1 选择命令弹框

左侧命令树保持不变。右侧根据操作类型展示：

| 操作类型 | 右侧内容 | Path 候选 |
|---|---|---|
| `LST/DSP` | 可多选 Path 列表 | 当前设备和产品过滤后的全部可执行 Path |
| `MOD` | 可多选 Path 列表 | 仅 `writable=true` 的 Path |
| `ADD/RMV` | 现有目标对象路径提示 | 不展示 Path 多选 |
| 其他类型 | 保持现有行为 | 不在本次需求中扩展 |

Path 多选区包含：

- “全选”复选框，支持全选、取消全选和半选态。
- “已选 N 项 / 共 M 项”计数。
- 每行展示 Path 标签和完整路径；长路径继续使用省略与 Tooltip。
- 首次选择命令或切换到另一命令时，默认选择为空。
- 重新打开当前已确认命令时，回显上次选择，避免用户无意丢失配置。
- 当前候选 Path 因设备能力或“不支持 Path”过滤变化时，自动剔除已经不可见或不可写的选择。

“确定选择”按钮规则：

- `LST/DSP/MOD`：至少选择一个 Path，且候选 Path 加载完成。
- `ADD/RMV`：沿用当前 `target_object` 校验。
- 其他命令：沿用现有校验，不因本需求改变。

### 4.2 配置参数弹框

#### 查询类命令

- 只读展示上一页选中的 Path。
- 不再显示 Path 复选框和“全选”控件。
- 显示操作类型、命令名称和“已选 N 项”。
- 用户确认设备、命令、Path 和执行模式后执行。

#### 修改类命令

- 只为上一页选中的可写 Path 渲染值输入框。
- 每个选中 Path 都必须填写修改值；存在空值时禁用执行按钮。
- `minValue` 等现有默认值规则继续生效，但用户仍可修改。
- 写操作警告、执行权限和执行模式规则保持不变。

#### 实例选择器

`LST/DSP/MOD` 的实例占位符只根据本次选中的 Path 计算，避免未选 Path 引入无关实例输入。`ADD/RMV` 仍根据 `target_object` 计算。

## 5. 状态与数据流

```text
选择设备
  → 打开选择命令弹框
  → 选择命令
  → 根据操作类型得到候选 Path
  → 用户多选 Path
  → onConfirm(command, selectedPathKeys)
  → 父页面保存完整 command + selectedPathKeys
  → 打开配置参数弹框
  → 按 selectedPathKeys 过滤 command.paramPaths
  → 查询：只读确认
  → 修改：填写选中 Path 的值
  → 构造原有 ExecRequest.checkedPaths
  → 沿用现有执行接口
```

父页面切换命令时同时清理：

- 旧的 `selectedPathKeys`。
- 旧命令对应的修改值。
- 旧命令派生的实例选择器。

同一命令重新选择 Path 时，配置页按最新选择裁剪旧值和实例选择器；新加入的 Path 再按现有 `minValue` 规则初始化，避免隐藏的旧值进入请求。

`ExecRequest` 继续使用现有 `checkedPaths` 字段，不新增后端字段。

## 6. 组件边界

### `CommandSelectModal`

- 维护弹框内尚未确认的 Path 选择。
- 根据命令类型构造候选 Path。
- 处理默认不选、全选、切换命令清空和重新打开回显。
- 确认时同时返回完整命令与已选 Path。

### `MMLConsole`

- 保存已确认的完整命令和 `selectedPathKeys`。
- 向配置参数弹框传递已选 Path。
- 命令变化时重置旧配置。

### `ConfigParamsModal`

- 根据 `selectedPathKeys` 派生本次可见 Path。
- 查询类只读展示。
- 修改类只展示选中输入项并校验值完整性。
- 构造现有 `ExecRequest`。

### 纯函数

把下列规则提取为可单测纯函数，避免散落在 JSX 中：

- 按操作类型筛选可选择 Path。
- 按已选 key 过滤 Path，并保持命令定义顺序。
- 从候选 Path 中清理失效选择。
- 判断 MOD 已选 Path 的值是否完整。

## 7. 国际化

新增或调整的所有用户可见文案同时维护中文和英文：

- 全选、已选/总数。
- 未选择 Path 的提示。
- 查询确认页说明。
- MOD 必填值提示。

不在组件中硬编码用户可见中文。

## 9. 非目标

- 不修改命令树、设备选择或产品能力过滤接口。
- 不改变 `ADD/RMV` 的对象路径和实例号语义。
- 不调整 MML 后端执行、任务、SSE 或结果展示协议。
- 不在本需求中重构整个 MML Console 向导状态管理。
- 不在验收环境执行真实查询或修改命令。

## 10. 风险与控制

- **大 Path 列表渲染**：沿用固定高度滚动容器，不引入一次性展开导致的页面增高。
- **命令切换残留选择**：命令 ID 变化时清空未确认选择；重新打开同一已确认命令时才回显。
- **设备能力变化**：候选列表变化后按当前候选集合清理选择。
- **只读 Path 误用于 MOD**：MOD 候选在进入复选框前即过滤为可写项，配置页再次按可写属性兜底。
- **空值误下发**：MOD 对本次选中项做完整值校验，全部有效后才允许执行。

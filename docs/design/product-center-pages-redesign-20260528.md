## 0. TL;DR（30 秒决策摘要）

- **现状问题**：产品中心 5 个页面（参数模型、KPI 指标库、告警库、产品管理、孤儿设备）由不同节奏迭代而成，工具栏密度、筛选位置、Tab/Card 层级、编辑容器（Drawer vs Modal）、辅助面板等均不统一，导致 ① 视觉割裂 ② 同类操作落点不可预期 ③ 高频运维路径被切碎到多个 Tab。
- **基准候选**：以「**产品管理 / Products**」页面为参照，**§2 先把基准的当前结构逐层剖析**，识别 10 个可能调整点（§2.7）→ 由用户裁决后再固化为基准规范。
- **已裁决（累计 2 项）**：
  1. §2.7 **A2 = 合并** — ① 顶部工具卡 + ② MatchTester 辅助卡 合并为单一 Card 双行布局；卡数 3 → 2。
  2. **M1 = 常驻紧凑** — 第二行始终可见，输入框 + 结果同行；首屏节省 76px。M2 默认折叠方案已淘汰。
- **统一规范**：§3 提炼 8 条页面级布局规范（R1–R8）；R8 = 「辅助/诊断面板内联到工具卡第二行，采用 M1 常驻紧凑模式」。
- **重构动作**：4 个非基准页面（参数模型 / KPI 指标库 / 告警库 / 孤儿设备）分别按 §5 的方案重排 toolbar、消除 Card 嵌套、统一编辑为 Drawer、辅助面板 **以 M1 常驻紧凑** 内联到工具卡第二行。
- **拆分**：本方案只动 UI 布局与组件容器，**后端 API / 数据模型 / 业务规则零改动**；估算工作量见 §7。
- **⚠ 当前等待**：§2.7 剩余 A1 / A3-A10 共 9 个调整点裁决。

**布局规范**：
- 整行高度 ~44px（含 8px 上下 padding）
- 输入框 `maxWidth: 320px`，结果区 `flex: 1`，整体 `<div display:flex align-items:middle gap:12>`
- 输入与结果同 Card body 背景，无副卡边框
- 防抖 300ms（沿用现 MatchTester 行为）

**结果状态设计（4 态，沿用现实现）**：

| 状态 | 触发 | 内联视觉 |
|------|------|---------|
| 未输入 | `value === ''` | 灰字提示「回车 / 失焦后命中规则会即时显示」 |
| 匹配中 | 防抖期间 | `<Spin size="small" />` + 灰字「匹配中…」 |
| 命中 | API 返回 `matched=true` | `<Tag color="success">命中</Tag>` + `<Text strong>{productName}</Text>` + `<Text code>{regex}</Text>` + `<Text type="secondary">全局序号 N · vendor / tech</Text>` |
| 未命中 | API 返回 `matched=false` | `<Tag color="warning">未命中</Tag>` + `<Text type="secondary">进入孤儿设备列表，请到「正则模式」段添加规则</Text>` |

**为什么选 M1**：① 免点击展开，运维排查随手可用；② 信息密度高，第二行始终承载具体操作；③ 与基准 R3「Search 用 onSearch」的"显式触发"风格一致。

##### 已评估并淘汰的备选 — M2 默认折叠（决策溯源用，不实现）

> 该方案在评审中被淘汰；保留在此仅为后续翻阅参考。

折叠态 ~36px：`⚡ 测试匹配 / Test Match · 诊断 productClass 命中规则 [▼ 展开]`；展开态 ~80px：输入 + 结果多行。
淘汰理由：① 需要额外点击展开，增加运维操作步骤；② Antd `Collapse ghost` 在 `size="small"` Card 内需自定义样式才能消除 padding 抖动；③ 新用户容易忽略该功能。

```tsx
// 推荐方案 M1
<Card size="small" style={{ marginBottom: 12 }}
```

`MatchResultInline` 组件签名：

```tsx
interface MatchResultInlineProps {
  result: ProductMatchResult | null
  loading: boolean
}

function MatchResultInline({ result, loading }: MatchResultInlineProps): JSX.Element {
  if (loading) return (<><Spin size="small" /> <Text type="secondary">匹配中…</Text></>)
  if (!result) return (<Text type="secondary">回车 / 失焦后命中规则会即时显示</Text>)
  if (result.matched && result.product) {
    return (
      <Space wrap>
        <Tag color="success">命中</Tag>
        <Text strong>{result.product.name}</Text>
        <Text code>{result.matchedPattern}</Text>
        <Text type="secondary">全局序号 {result.globalOrder} · {result.product.vendor}/{result.product.tech}</Text>
      </Space>
    )
  }
  return (
    <Space>
      <Tag color="warning">未命中</Tag>
      <Text type="secondary">进入孤儿设备列表，请到「正则模式」段添加规则</Text>
    </Space>
  )
}
```

### 4.1 共性问题（5 类）

1. **Card-in-Card 嵌套**：参数模型 / KPI 指标库 在 Tab 内重新套一层 Card，造成「双重边框 + 双重标题」。
2. **筛选位置不一致**：产品管理在顶 Card；告警库在顶 Card 但加灰色 label；KPI 库在 Tab 内 Card；参数模型只在第 3 个 Tab 内有搜索；孤儿设备完全没有。
3. **编辑容器分裂**：产品 / 告警 / KPI 详情用 Drawer；参数模型用 Modal；孤儿设备绑定用 Modal。**用户在同一菜单组内得不到一致的「右侧抽屉编辑」心智。**
4. **辅助面板缺失**：基准页有 MatchTester 作即时诊断；其他 4 页只有"打开 Modal"或完全无诊断入口。
5. **Tab 错维度切分**：KPI 库把"设备类型 + 单位定义"塞进同一组 Tab；参数模型把"模型 + 映射 + 标准树"切到三个 Tab，但**映射强依赖模型选择**，跨 Tab 操作动线被打断。

## 0. 总体模型（中心概念）

**一句话**：**聚合任务是数据生产单元，仪表盘是它的标准视图，两者一一对应；指标库是统一的指标定义中心，向聚合任务供给指标。**

现有两套并存的概念——「一次性自选设备聚合」与「自由拖拽图表卡片的仪表盘」——**收敛成「聚合任务 + 自动仪表盘」一套模型**：

- 建任务 → 在「性能管理-自定义聚合」页（多步骤向导）。
- 看数据 → 在「性能管理-性能仪表盘」页（每个任务对应一个自动出图的仪表盘）。
- 指标定义 → 在「产品中心-指标库」（统一页面）。

**被取代/下线**：自由拖拽图表卡片编辑器、8 种图表卡片类型、旧 12 个内置盘的空壳预置数据。

## 1. 支柱一 · 指标库统一（落产品中心）

### 1.1 页面合并
- 「性能管理-指标库」与「产品中心-KPI指标库」**合并为一个统一页面**，落**产品中心**菜单；性能管理侧的指标库入口取消。

### 1.2 能力
- **指标分组可编辑**：分组的增删改、指标在分组间移动。
- **自定义 KPI 增删改**在此页完成。
- **自定义 KPI 纳入 K 编号体系**（K 编号 = 每个指标的全局唯一编号，避免同名指标撞键）：自定义 KPI 与内置 KPI 共用同一套编号，存储与聚合口径一致（承接已闭环的 KPI 编号化）。
- **不设独立「展示换算」层——换算即指标**：一个指标就是「编号 + 计算公式 + 单位」一个确定值。需要别的单位或派生口径（如把字节看成 MB、把字节算成吞吐率）时，**新建一个指标**、把换算写进它自己的计算公式（如 `a_mb = a_byte/1000/1000`），不在指标上再挂一层"展示时才套的公式"。

### 1.3 供给关系
- 指标库是聚合任务「选指标」步骤的数据源；任务通过指标编号引用指标。

## 2. 支柱二 · 聚合任务体系（性能管理-自定义聚合）

### 2.1 五个聚合维度
全网 / 设备组 / 产品 / band（频段标识）/ 自选设备。

- **band 维度的聚合语义**：band 不在 PM 数据里，来自参数同步落库的小区频段参数（每个小区一个频段值）。聚合时按小区的频段值分组，把**同频段的所有小区**的指标聚到一起，作为该 band 的数据。小区与其 PM 数据的对应关系经实测一致（细节见实施计划）。

### 2.2 内置任务
- **预置规则**：聚合维度 × 制式（全网 / 设备组 / 产品 / band × LTE / NR / GSM），**粒度统一为小时**。即 4 维度 × 3 制式 = **12 个内置任务，均为小时粒度**。
- **一维度一任务、组内分系列**：如「按设备组-LTE」是**一个**任务，任务内部对每个 LTE 设备组分别汇总，仪表盘里每张指标图上每组一条线。产品维度、band 维度同理。
- 运行期若某维度暂无实体（如还没有任何设备组），任务存在、数据为空即可。

### 2.3 任务生命周期与过期（两层口径，勿混）
- **持续性**：内置任务都是持续型；用户自建任务可选持续 / 非持续。
- **任务过期**：仅针对**非持续型**任务，默认 **60 天**后任务本身过期删除。
- **结果数据过期**：任务产出的聚合**结果数据**跟原始 PM 数据使用**同一套过期时间**（非 60 天）。
- 即：60 天约束的是「任务定义」，结果数据按 PM 统一保留期清理。

### 2.4 指标锁定（查看收口；存储范围可配）
- 任务定义 N 个指标 → 查看 / 导出**只限这 N 个**（展示层收口不受存储开关影响）。
- **存储范围做成配置开关**（放配置文件，非任务级、全局生效，未来可调）：
  - `全存`（默认）：聚合运算时所有指标都存，底层全量，便于事后改任务指标集时无需重算。
  - `仅存所选`：只落任务定义的 N 个指标，省存储。
- 切换只影响"落库哪些指标"，不影响"查看/导出限 N 个"这条收口规则。

### 2.5 制式联动范围选择
- 第 1 步选定制式后，第 2 步「聚合范围」只呈现**该制式的设备 / 小区**：LTE 制式只能选 LTE 设备，NR、GSM 同理。
- 此限制对所有维度（全网 / 设备组 / 产品 / band / 自选设备）统一生效。

### 2.6 新建向导（整页 + 横向步骤条，5 步）
不使用右侧弹出面板。点「新建」跳转整页向导，顶部横向步骤条，中间一张大卡片装当前步骤表单，底部「上一步 / 下一步」。

1. **基本信息**：任务名、制式（LTE / NR / GSM）、持续性（持续 / 非持续 + 过期天数默认 60）。
2. **聚合范围**：选维度（全网 / 设备组 / 产品 / band / 自选设备）→ 选具体范围（受 2.5 制式过滤）；自选设备时可**下钻到小区 / PLMN（运营商网络标识）**。
3. **指标选择**：从指标库挑 N 个指标（决定查看 / 导出范围；底层仍全存）。
4. **聚合设置**：粒度（15 分 / 小时 / 日 / 周 / 月，**单选一个**；要别的粒度另建任务）。（周期对比不在此定义，见 §3.4——它是仪表盘视图级的临时开关。）
5. **确认**：预览汇总 → 提交。

### 2.7 任务管理 + 状态查询入口
- 自定义聚合页列出任务，**内置区 / 自建区分区展示**。
- 每个任务可看**运行历史**：任务编号、粒度、维度、时间窗、状态标签、入队 / 完成时间、失败原因，状态可点开详情。
- 替代当前「请用 SQL 查数据库」的临时占位。
- 制式**建后不可改**（详情页只读标签，不可切换）。

## 3. 支柱三 · 性能仪表盘（性能管理-性能仪表盘）

### 3.1 两个页签
- **页签1 · 任务仪表盘**
  - 左侧任务列表（内置区 / 自建区分区）与聚合任务**一一对应**。
  - 选中一个任务 → 右侧按该任务的 N 个指标**自动出图**。
  - **每个指标一张折线趋势图**（横轴时间、纵轴指标值），**横向铺满、纵向排列**（单列堆叠）。
  - 多组 / 多设备时同一张图多条线。
  - 自动生成、固定布局，**用户不再手工拖拽配置图表卡片**。
- **页签2 · 设备列表**（独立即席查看，不依赖任何聚合任务）
  - 选 ≤10 个设备 → 每个常用指标一张折线图；多设备时同图多条线（每设备一条）。
  - 默认展示各制式核心指标集全集（与内置任务同一份，见 §6 与实施计划对照表），用户可换其他指标。

### 3.2 顶部三级筛选
> 适用范围：两个页签（任务仪表盘 + 设备列表）都带此筛选区。
- **大时间段**：默认近 7 天，用户可调起止时间。
- **星期**：多选（如同时看周一、周二），默认全选。
- **小时段**：多选（如 8:00–9:00、20:00–21:00），默认全选。
- 语义：**只在已经算好的时间段上挑出命中的点、不重新聚合**；图横轴只显示命中的时间点。

### 3.3 指标查询页
- **隐藏**；其遗留 bug 不再修复。

### 3.4 周期对比（视图级临时开关）
- **定义位置**：不进任务定义，放仪表盘顶部筛选区一个临时开关，看的时候随时开 / 关。两个页签（任务仪表盘 + 设备列表）都有。
- **对比窗口**：把当前选的「大时间段」**往前推一个等长窗口**作为对比基线（看近 7 天对比前 7 天，看近 30 天对比前 30 天，即环比上一周期）。
- **与三级筛选一致**：上一周期窗口**套用相同的星期 / 小时段筛选**（筛「周一 8–9 点」则对比上一周期同口径的「周一 8–9 点」）。
- **呈现**：每张折线图叠加一条「上一周期」虚线（当前周期实线 + 上一周期虚线）。新仪表盘全是折线图，不再有旧设计的单值增减量、表格对比列。

## 4. 数据与存储影响（数据表结构层面，细节归实施计划）

- **聚合任务**需承载：制式、聚合维度、范围选择、指标集（引用指标编号）、粒度（单粒度）、持续性 + 过期天数、内置标记。（周期对比是仪表盘视图级临时开关，不入任务定义，见 §3.4。）
- **band / 小区 / PLMN 维度数据**来自参数同步落库的设备参数（与待办池 #9「小区/PLMN 下钻」同源），按制式提供对应频段 / 小区 / PLMN 的参数路径。
- **聚合结果**沿用现有 PM 时序存储与统一过期机制；任务过期是任务定义层面的清理，与结果数据过期分离。
- **自定义 KPI** 复用已落地的指标编号唯一键体系。
- **指标定义**统一为「编号 + 计算公式 + 单位」，无独立展示换算字段；不同单位口径靠新建指标实现（见 §1.2）。

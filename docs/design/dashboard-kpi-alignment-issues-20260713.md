## 数据链路审查（2026-07-13）

### 对齐基线

首页 KPI 与 PM 性能仪表板只有同时满足以下条件时，才应逐桶一致：

1. PM 任务维度为 `network`；
2. 两边选择相同制式、相同指标和相同业务时区；
3. 两边使用同一粒度与同一半开时间窗；
4. 比较的都是已完成桶，且 PM 任务结果已按当前聚合数据刷新。

首页是对 PM Aggregator 的实时查询；PM 性能仪表板读取的是 `pm_adhoc_aggregation_results` 中的任务结果快照。因此两者不是同一数据源的两个展示层，不能在未满足上述条件时直接用“页面曲线不同”判断 KPI 公式错误。

### 已确认一致的部分

- 首页全网 KPI 已复用 PM Aggregator 的“计数器聚合后重算 KPI 公式”路径；不会对设备 KPI 做简单平均。
- 首页周视图使用 `daily`，窗口为业务时区的 `[今日零点 - 7 天, 今日零点)`，即最近七个完整自然日；当天不显示 partial 日点。
- 周视图固定显示“七个完整日 + 今日”共八个日期槽；今日尚无 daily 数据时为 `null`，不补零、不画点、不跨缺口连线，日期标签仍按普通日期显示。
- 前端把后端返回的带偏移时间按系统业务时区钟面日期映射，避免浏览器时区影响日桶归属。

### 已现场确认的周视图数据

本地 LTE 指标 `K900010015` 的接口返回已包含七个 daily 桶：

### 未收口差异与建议

| 优先级 | 差异 | 当前表现 | 建议修复与验收 |
|---|---|---|---|
| P1 | 首页制式未透传到聚合请求 | 首页按 LTE/gNB 布局切换，但构造 `network` 查询时未设置 `Technologies`；PM 任务会透传任务制式。 | 给 Dashboard 时序接口增加并校验 `technology`，传入 Aggregator `QueryRequest.Technologies`；用同一 K/C 指标在 LTE、NR 各造一条数据，验证首页 LTE 只得到 LTE 汇总。 |
| P1 | 实时查询与 PM 任务快照不同 | 首页实时读聚合表；PM 仪表板读 `pm_adhoc_aggregation_results`。 | 明确产品契约：首页以实时聚合为准，PM 以任务产出时间为准；提供同窗口的查询时间/任务运行时间用于排障。若要求严格逐点比对，应由同一 network 任务结果作为验收基线。 |
| P1 | 维度范围不同 | 首页固定 `network`；PM 任务可为设备、设备组、产品、频段等。 | 仅承诺与 PM 的 `network` 任务对齐；前端/接口文档明确该前提，验收样例固定 network。 |
| P2 | 时间窗与结束边界不统一 | 首页聚合查询为 `[start,end)`；PM 结果读取为 `time <= end`，产品/频段聚合查询亦存在闭区间。 | PM 结果查询和聚合查询统一为半开区间；覆盖“结束时刻恰为次日零点”时不得多出下一桶的测试。 |
| P2 | 完整桶保障位置不同 | PM 连续任务按完成水位消费；首页直接读取聚合表，依赖上游不写半成品。 | Dashboard 服务按同一水位截断，或明确聚合表只能在完整桶后写入；覆盖 hourly 当前小时存在 15min 数据、但 hourly 尚未完成时首页必须为空。 |
| P2 | 指标集合与结果数量限制不同 | 首页按布局指标实时取数；PM 受任务 `MetricPaths`、启用状态与 10,000 行读取上限影响。 | 验收基线固定相同指标集；PM 明确截断状态，首页/PM 比对工具在截断时拒绝宣称一致。 |
| P2 | 首次加载时区依赖不同 | 首页周视图等待时区加载；天视图与 PM 初始筛选仍可能先使用未初始化缓存。 | 两侧均在已取得系统业务时区后构造请求；补首次加载时不得发 UTC 窗口的 Hook 测试。 |
| P3 | 缺点横轴策略不同 | 首页固定七日；PM 根据任务结果和用户筛选扩展桶轴。 | 将“固定最近七日”限定为首页周视图特性；跨页面比对时使用相同的完整日桶集合。 |

### 后续修复顺序

```text
1. 制式透传（P1，避免 LTE/gNB 混算）
2. 明确首页实时与 PM 快照的验收基线（P1）
3. 统一半开时间窗及完整桶水位（P2）
4. 收口首次加载的系统时区依赖（P2）
5. 增加跨页面 network/LTE/同 KPI/同七日窗口的逐桶契约测试（P2）
```

5. 次日完成 daily 聚合后确认窗口滚动：`07/13` 成为真实点，新增当天成为空的普通日期占位。

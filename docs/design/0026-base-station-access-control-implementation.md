# 基站接入控制实现设计

## 1. 目标与边界

本设计在当前 OMC 的 App、ACS、Worker 架构内覆盖 Redmine #31672、#51449、#45094、#31732、#31675、#21156、#21155 的核心业务：

- 管理员通过页面业务总开关启停接入控制；
- 按运营商维护策略、黑白名单和待审核候选；
- 基于 SN、ProductClass、IP、TAC、ECGI、GPS 等证据作出接入决定；
- 黑名单或规则拒绝后由 OMC 自动去激活基站 RF；
- 白名单跳过普通规则并默认接入；
- 只有已接入设备可以创建和出队普通设备任务；
- 支持查看决定、证据、任务和设备动作状态；
- OMC 只恢复由接入控制关闭的 RF，避免覆盖人工或其他业务状态。

不引入老需求之外的双人审批、维护窗口、部署模式或三进程动作开关。接入控制也不负责批量重评、批量名单、网段扫描或创建 ACS 认证账号。

## 2. 单一业务总开关

唯一开关保存在 `device_access_runtime_settings.enabled`，按运营商隔离，默认关闭。管理员在“设备 > 接入控制”页面直接操作，修改即时生效，不需要编辑 YAML、重建镜像或重启 App/ACS/Worker。

关闭时：

- 新 Inform 按兼容模式接入；
- 不生成新的接入决定、证据探测或 RF 动作；
- 普通设备任务不受接入控制阻挡；
- 历史决定、名单、策略和动作仍可查看维护；
- 关闭开关不会擅自恢复此前关闭的 RF。

开启时：

- 新 Inform、证据补齐和明确的单设备重评进入完整接入控制链路；
- 拒绝决定自动触发 RF 去激活；
- 接入状态同时约束任务创建和任务出队。

开关开启本身不触发全网批量重评，避免对存量基站造成突发动作。

## 3. 决策优先级

同一运营商作用域内按以下顺序求值：

1. 设备退役、撤销等硬拒绝状态；
2. 黑名单命中：拒绝并自动去激活；
3. 身份、归属等基础安全校验失败：拒绝；
4. 白名单命中：跳过普通接入规则并接入；
5. 已发布规则：单条规则内条件为 AND，多条规则之间为 OR；
6. 无已发布规则、无适用规则或没有规则命中：拒绝。

规则证据包括 SN、ProductClass、源 IP、TAC、ECGI 和 GPS。缺少可补采证据时，先产生待证据状态并通过 GPV 补采；补采后重新计算决定。决定必须保存所用证据和原因，不能只保存页面展示状态。

## 4. 南向闭环

### 4.1 拒绝

```text
Inform
  -> 采集/补齐接入证据
  -> 生成拒绝决定
  -> 创建幂等 RF_OFF 动作
  -> ACS 下发 SetParameterValues
  -> 记录设备回执
  -> GetParameterValues 回读
  -> 将动作标记为成功、失败或待重试
```

决定、任务和设备动作是三类不同事实：

- 决定说明“应否接入”；
- 任务说明“OMC 是否已调度南向命令”；
- 设备回执与 GPV 回读说明“设备是否实际执行”。

页面状态不得代替 CWMP 回执或 GPV 回读。

### 4.2 恢复

当设备从拒绝变为接入时，仅当存在接入控制成功执行的 RF_OFF 所有权记录，才创建 RF_ON 恢复动作。恢复同样要求 SPV 回执和 GPV 回读。人工关闭、设备自身关闭或其他业务关闭的 RF 不由接入控制自动打开。

### 4.3 幂等与重试

同一设备、决定版本和动作类型只能存在一个有效动作。失败动作通过 outbox 重试；进程重启后可继续处理。重复 Inform、重复事件或重复回执不得造成重复 RF 操作。

## 5. 任务保护

接入控制开启时，普通设备任务在两个位置检查接入状态：

- 创建任务前；
- Worker/ACS 出队执行前。

只有接入决定为 accepted 的设备可继续普通任务。接入证据探测、RF 去激活及其 GPV 回读属于接入控制自身任务，不受该保护反向阻断。开关关闭时普通任务保持原有行为。

## 6. 页面与权限

管理员菜单提供五个页签：

1. 接入状态；
2. 接入策略；
3. 接入名单；
4. 候选审核；
5. 动作状态。

页面顶部提供唯一业务总开关和运营商选择。列表、策略、名单、候选、决定详情、证据详情和动作均按运营商作用域隔离。用户可见文案使用 i18n；无权限账号访问接口返回 401/403，不能只依赖前端隐藏。

策略和名单可在总开关关闭时预先维护。启用确认必须明确提示：拒绝或黑名单命中会自动触发 RF 去激活。

## 7. 数据与组件职责

- App：业务开关、策略/名单/候选管理、决定与动作查询、任务创建保护；
- ACS：Inform 接入判断、证据采集、RF SPV/GPV、任务出队保护；
- Worker：证据和动作 outbox、重试、超时收敛；
- PostgreSQL：运行开关、策略、名单、候选、决定、证据、动作和 outbox 的事实源；
- NATS/Redis：事件与既有任务协作，不作为最终业务事实源。

## 8. 正式使用流程

1. 管理员选择运营商；
2. 在总开关关闭状态下配置并发布规则，维护黑白名单；
3. 核对规则范围和 RF 影响提示；
4. 在页面开启业务总开关；
5. 新接入设备按优先级自动判定；
6. 白名单设备接入，黑名单或不满足规则的设备自动去激活；
7. 管理员在决定、证据和动作详情中核对完整链路；
8. 需要停止业务时在页面关闭总开关，不修改部署配置。

## 9. 验收硬条件

- 页面总开关即时控制三个进程的业务行为；
- 默认关闭，无策略时开启后默认拒绝；
- 黑名单优先拒绝且自动去激活，白名单跳过普通规则；
- SN、IP、ProductClass、TAC、ECGI、GPS 证据和多小区数据可追溯；
- 普通任务创建和出队均受保护；
- RF_OFF/RF_ON 均有 SPV 回执、GPV 回读和最终状态；
- 恢复后设备回到操作前 RF 状态；
- 决定、任务、设备动作分别取证；
- 不要求双账号审批、维护窗口或重新部署。

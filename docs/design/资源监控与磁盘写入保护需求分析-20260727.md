# OMC 资源监控、队列积压与磁盘写入保护需求分析

> **文档版本**：v1.1  
> **创建日期**：2026-07-27  
> **现场核验日期**：2026-07-28  
> **文档状态**：需求分析 / Grafana现场核验完成  
> **适用项目**：OMC（Operations, Management and Control）

## 1. 文档目的

本文档结合 OMC 当前部署、后端实现、监控配置和数据保留策略，梳理以下需求涉及的系统功能和改造边界：

1. 监控磁盘、CPU、内存等资源使用情况，并在 Grafana 中展示。
2. 监控业务队列积压情况，并在 Grafana 中展示。
3. 在 OMC 功能页面配置磁盘占用阈值；达到阈值后，控制文件、日志、上报数据等写入行为。
4. 梳理数据有效期和清理策略，为后续容量治理提供统一依据。

本文档是后续详细设计、开发任务、测试方案和运维手册的需求基线。

## 2. 范围与排除项

### 2.1 本期范围

| 范围 | 内容 |
|---|---|
| 基础资源 | 主机、容器、Go进程、PostgreSQL、TimescaleDB、Redis、MinIO及监控组件的CPU、内存、磁盘指标 |
| 存储容量 | PostgreSQL、TimescaleDB、Redis、NATS、MinIO、本地日志、Prometheus、Loki、Tempo等数据存储 |
| 队列积压 | NATS JetStream、Redis设备任务队列、PostgreSQL持久化队列和Outbox |
| 展示告警 | Prometheus采集、Grafana展示、Prometheus规则和Alertmanager告警 |
| 写入保护 | 文件上报、MinIO对象、日志、备份、Trace等写入入口的磁盘水位控制 |
| 有效期治理 | 文件、时序数据、日志、消息、任务和备份的保留期、容量和清理策略 |

### 2.2 明确排除项

应用进程内部的 Go Channel、Worker Channel、参数同步内存Channel、Trace本地Capture Queue等暂不纳入队列积压监控和Grafana展示范围。相关代码可以保留现有自身保护和丢弃计数，但不作为本需求的交付对象。

本期也不引入 Kafka、RabbitMQ 或新的消息中间件。当前运行时队列以 NATS JetStream、Redis 和 PostgreSQL 为准。

## 4. 功能需求

### 4.1 资源指标监控

#### 4.1.1 磁盘指标

系统应采集并展示：

- 文件系统总容量、已用容量、可用容量、使用率。
- inode总量、已用inode、可用inode和使用率。
- 磁盘容量增长速率。
- 预计耗尽时间。
- PostgreSQL、TimescaleDB、Redis、NATS、MinIO和监控数据卷的归属关系。
- MinIO集群总容量、可用容量和使用率。
- 数据库逻辑大小、主要表大小和物理文件系统使用率的对照关系。

磁盘指标必须以实际宿主机文件系统和数据卷为准，不能只展示数据库逻辑大小。

#### 4.1.2 CPU指标

系统应采集并展示：

- 主机CPU使用率。
- 容器CPU使用率和CPU限流时间。
- App、ACS、Worker等Go进程CPU使用率。
- PostgreSQL、TimescaleDB、Redis、NATS和MinIO容器CPU使用率。
- CPU持续高使用、CPU限流和异常突增告警。

#### 4.1.3 内存指标

系统应采集并展示：

- 主机内存使用率和可用内存。
- 容器内存使用量、内存上限和使用率。
- 容器OOM次数。
- Redis已用内存、最大内存和淘汰/拒绝情况。
- Go进程常驻内存、堆内存、GC和线程信息。
- 内存持续高使用和容器接近上限告警。

### 4.2 队列积压监控

本需求只监控持久化或外部可观察队列，不监控应用内存队列。

#### 4.2.1 NATS JetStream

每个Stream和Consumer至少应展示：

- Stream消息数量和消息字节数。
- Consumer待确认消息数。
- 最老未确认消息年龄。
- 消费速率、生产速率和确认速率。
- 重投递数量。
- Consumer断开、消费停止和Ack超时。
- Stream `MaxAge`、`MaxBytes`、存储类型和当前使用量。
- 消息恢复、重建或积压持续增长情况。

PM队列已有部分积压指标和告警；其他业务Stream需要统一补齐。[PM队列指标](/Users/a1/Desktop/vscode/gitlab/omcgo/internal/core/event/metrics.go:1)

#### 4.2.2 Redis设备任务队列

系统应展示：

- 全部设备任务队列总长度。
- 单设备队列长度。
- 队列长度Top N设备。
- 最老待执行任务年龄。
- 任务过期、恢复、重试和对账修复数量。
- Redis队列不可用、写入失败和消费失败。

Redis是设备任务运行时队列，PostgreSQL是任务持久化权威来源，两者需要分别展示并提供差异对账指标。

#### 4.2.3 PostgreSQL持久队列

至少应监控：

- `async_jobs`待执行、执行中、失败、僵尸任务数量。
- `parameter_sync_outbox`待投递、失败、死信数量。
- `northbound_outbox`待投递、处理中、失败、死信数量。
- PM/KPI导出任务数量和最老任务年龄。
- Trace导出任务数量和最老任务年龄。
- 备份任务数量和失败任务数量。
- 数据库队列持续增长和处理速率下降。

### 4.3 Grafana展示

Grafana至少提供以下仪表盘：

| 仪表盘 | 内容 |
|---|---|
| 资源总览 | CPU、内存、磁盘、容器健康状态和当前告警 |
| 存储详情 | 各数据卷、数据库、Redis、NATS、MinIO和监控存储容量 |
| 队列总览 | NATS、Redis设备任务、PostgreSQL持久队列总览 |
| NATS详情 | Stream、Consumer积压、消息年龄、消费速率 |
| 任务队列详情 | Redis设备任务和PostgreSQL任务状态 |
| PM/MR链路 | 文件上传、解析、入库、聚合和失败情况 |
| 数据保留与清理 | 各类数据保留期、清理数量、清理失败和预计释放空间 |

仪表盘应支持按环境、主机、容器、服务、数据卷、Stream、Consumer和业务类型筛选。

### 4.4 告警需求

#### 4.4.1 资源告警

- CPU使用率持续超过阈值。
- 内存使用率持续超过阈值。
- 容器接近内存上限或发生OOM。
- 磁盘可用空间低于告警阈值。
- 磁盘预计在指定时间内耗尽。
- inode不足。
- 数据库、Redis、NATS、MinIO或监控存储不可写。

#### 4.4.2 队列告警

- 队列长度超过配置阈值。
- 队列最老消息/任务年龄超过阈值。
- 消费速率低于生产速率并持续增长。
- Consumer断开或长时间没有确认。
- 任务进入死信、僵尸或反复重试状态。
- Redis运行时任务队列与PostgreSQL持久任务数量不一致。

### 4.5 OMC磁盘写入保护

#### 4.5.1 配置能力

OMC功能页面应允许具备权限的管理员配置磁盘保护策略。策略至少包括：

| 配置项 | 说明 |
|---|---|
| 目标 | 主机文件系统、数据卷或指定存储组件 |
| 告警阈值 | 达到后产生告警，但暂不阻断写入 |
| 写入阻断阈值 | 达到后禁止指定类型的新写入 |
| 恢复阈值 | 低于该值后恢复写入，必须低于阻断阈值 |
| 检查周期 | 磁盘水位采集和判断周期 |
| 保护范围 | 文件上报、日志、备份、Trace、报告、MinIO对象等 |
| 例外策略 | 是否允许管理员手动恢复或临时放行 |
| 生效范围 | 全局、组件、数据类型或数据卷 |

阈值使用“磁盘已用百分比”配置，同时在页面展示总容量、已用容量和剩余容量，避免只配置百分比而无法判断实际空间。

#### 4.5.2 写入控制对象

达到写入阻断阈值后，至少控制以下写入入口：

- PM/MR原始文件上传到MinIO。
- 设备上报文件接收和落盘。
- 固件、配置文件、证书、许可证和备份文件写入。
- Trace文件和报告文件写入。
- 站点日志、协议日志和应用日志写入。
- 需要写入高水位数据卷的异步任务。

数据库自身WAL、Docker日志和监控系统内部写入无法完全由业务页面阻断，因此必须同时保留底层磁盘告警和运维处置机制。

#### 4.5.3 阻断行为

不同写入类型应有明确行为：

| 写入类型 | 阻断行为 |
|---|---|
| 文件上传 | 拒绝接收并返回明确业务错误，不生成不完整对象 |
| PM/MR上报 | 暂停接收或转为可恢复的待处理状态，并产生告警 |
| 备份/报告/Trace | 新任务不再创建或进入暂停状态 |
| 普通日志 | 继续保留错误日志，限制普通日志写入并避免无限重试 |
| 危险高频写入 | 限流、降级或暂停，防止磁盘继续快速增长 |
| 已经开始的写入 | 由组件完成当前事务或安全终止，不产生孤儿元数据 |

写入阻断和恢复都必须产生审计记录及Prometheus指标，例如目标、数据类型、触发原因、阻断次数和恢复时间。

### 4.6 有效期和容量治理

每类数据应建立统一策略，至少包括：

- 保留天数。
- 最大容量或最大对象数。
- 清理周期和每批清理数量。
- 清理失败重试策略。
- 删除对象与删除数据库元数据的顺序。
- 孤儿对象和孤儿元数据处理策略。
- 清理前预警和预计释放空间。

现有策略需要纳入统一矩阵：MinIO原始PM/MR文件、TSDB时序数据、告警历史、应用日志、协议日志、NATS消息、Redis任务详情、备份、Prometheus、Loki和Tempo数据。

MinIO当前只有原始PM/MR文件具备默认生命周期，其他桶需要逐项确认，避免对象长期增长。[MinIO生命周期实现](/Users/a1/Desktop/vscode/gitlab/omcgo/internal/core/components/minio/minio.go:157)

## 5. 权限和审计需求

磁盘保护配置属于系统级运维配置，应满足：

- 仅系统管理员或具备对应权限的角色可查看、修改和手动解除保护。
- 修改前校验阈值关系：恢复阈值必须低于阻断阈值。
- 配置变更记录操作人、时间、原值、新值和变更原因。
- 配置生效后显示当前策略状态和最后一次检查结果。
- 显示当前处于告警、阻断、恢复中的存储目标。
- 手动放行必须设置有效时间并自动恢复保护状态。

## 6. 非功能需求

| 类型 | 要求 |
|---|---|
| 稳定性 | 监控系统或Prometheus短暂不可用时，不应导致业务写入逻辑异常崩溃 |
| 安全性 | 磁盘保护配置和手动放行必须经过权限校验和审计 |
| 实时性 | 资源和队列指标默认采集周期不超过30秒，写入保护判断不超过1分钟 |
| 可恢复性 | 写入阻断后，磁盘恢复到恢复阈值以下应支持自动恢复 |
| 一致性 | 文件对象、数据库元数据和任务状态不能出现不可追踪的部分成功 |
| 可运维性 | 每个阻断都能定位到存储目标、数据类型和触发指标 |
| 兼容性 | 不新增Kafka、RabbitMQ等消息中间件，不改变现有NATS、Redis和PostgreSQL职责 |

## 7. 验收标准

### 7.1 资源监控

- Grafana能展示主机、容器和主要服务的CPU、内存、磁盘使用率。
- 能区分PostgreSQL、TimescaleDB、Redis、NATS、MinIO和监控数据卷。
- 磁盘告警包含可用空间、使用率和预计耗尽时间。
- 容器内存接近上限、OOM和CPU限流能够告警。

### 7.2 队列监控

- Grafana能够展示所有纳入范围的NATS Stream和Consumer积压。
- Grafana能够展示Redis设备任务总量、单设备Top N和最老任务年龄。
- Grafana能够展示PostgreSQL异步任务、Outbox、导出和备份任务积压。
- 能够区分生产速率、消费速率、确认速率和失败/死信数量。
- 人工停止Consumer或制造积压后，能够在规定时间内看到指标和告警。

### 7.3 磁盘写入保护

- 管理员能够配置告警阈值、阻断阈值和恢复阈值。
- 达到阻断阈值后，指定文件和数据写入被拒绝、暂停或降级。
- 写入阻断状态在OMC页面、Grafana和告警通知中可见。
- 磁盘恢复后，业务能够按策略自动恢复。
- 写入阻断不会产生不可清理的MinIO孤儿对象或数据库孤儿记录。
- 所有配置变更、阻断和恢复均有审计记录。

## 8. 后续拆分建议

建议按以下顺序拆分开发任务：

1. **监控指标统一**：补齐NATS、Redis设备任务和PostgreSQL持久队列指标。
2. **Grafana仪表盘和告警**：建设资源、存储、队列和PM/MR链路面板。
3. **磁盘水位策略模型**：定义配置、权限、审计和状态机。
4. **写入准入控制**：先覆盖MinIO文件上传、设备上报和备份/报告，再覆盖日志和Trace。
5. **有效期和清理治理**：统一MinIO、TSDB、日志、消息、任务和备份的保留策略。
6. **容量保护验收**：执行磁盘高水位、队列积压、存储不可用和恢复演练。

详细的开发目标、指标、仪表盘、写入准入、有效期治理和验收设计见[资源监控与队列治理及磁盘写入保护功能设计-20260728.md](./资源监控与队列治理及磁盘写入保护功能设计-20260728.md)。

### 9.3 现场发现的面板问题

1. **容器标签不匹配**：现场cAdvisor目标为在线，但当前容器面板查询大量依赖`name`标签；实际实时样本主要带`id`等标签，因此需要按现场标签重新编写查询，不能只根据面板存在判断功能可用。
2. **NATS面板查询失效**：现有面板使用`nats_jetstream_consumer_num_pending{stream="omcgo"}`，现场查询结果为空；当前NATS exporter主要暴露`gnatsd_varz_*`和连接类指标，不能满足Consumer级积压监控。
3. **Operations面板存在Kubernetes遗留查询**：`Pod Count`、按Pod CPU/内存和部分Go运行时面板使用`namespace="omcgo"`，而现场数据为Docker Compose服务标签，需删除、改写或明确标记为Kubernetes专用面板。
4. **资源面板与写入保护未打通**：主机磁盘告警已经存在，但告警触发后不会自动阻止MinIO上传、文件上报、日志、备份或Trace写入。
5. **告警计算位置需要明确**：当前Grafana统一告警规则为空，实际告警来自Prometheus规则；后续设计应继续以Prometheus规则为主，Grafana负责展示，避免重复建设两套告警。

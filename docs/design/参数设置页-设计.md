# 参数设置页（快速设置）— 新 OMC 设计文档

> 状态：**v0.8**（架构改造：从 per-tech XML 切到 per-paramModel XML；tab 显示规则按 XML 存在性决定）
> 关联功能域：F02 数据模型与配置 / F06 OMC-R 设备详情
> 老版来源：`/cell/quicksettings/getParamNodeTreeAndData`（命名沿用"快速设置"）

---

## 1. 背景与目标

设备运维人员需要在设备详情页对常用小区参数和邻区配置做**业务化分组**的查看与下发，免去在原始参数树（664 对象）里翻找；改完一次性下发，过程对用户透明。

覆盖范围：**ENB（LTE / 4G）小区参数 16 项 + 邻区配置 23 项 + GNB（5G NR）小区参数 16 项，共 55 个叶子参数**（清单见 §2）。

**非目标**：
- 不重做参数树（保留原 `参数树` tab 的原始浏览职责）
- 不做全量参数表单化（只覆盖 §2 列出的 55 项）
- 不引入字段级权限、变更审批、灰度下发等附加保护机制（保持简单方案）

---

## 2. 参数清单

> **注**：本节为参数清单**资料**，便于评审与对照；实施时整理为 XML 配置文件放到 `omcgo/data/quicksettings/{enb,gnb}.xml`，由后端 dictloader 框架加载、REST 接口暴露给前端（详见 §9.2.3 配置外部化与 §9.2.4 后端 Loader）。前端**不**硬编码参数清单。
>
> 所有路径中的 `{i}` 在实际请求时替换为具体实例号（FAPService 实例 / 子对象索引）。
> BLQ 设备 `standard_path = private_path`，无路径转换；GNB 的若干参数有 standard ↔ private 翻译，由后端 Translator 处理（前端不感知）。
>
> **GNB 路径约定**：GNB 设备的 FAPService 仅有 1 个实例，§2.2.1 中标准路径里的 `FAPService.{i}` 在请求时**固定为 `FAPService.1`**（资料表中保留 `{i}` 是为对照标准模型）；`NumOfTxAtenna` 的标准路径形似 LTE 路径（`...CellConfig.LTE.RAN.PHY.AntennaInfo.AntennaPortsCount`），属规范历史原因，实际下发的私有路径由 Translator 翻译为正确的 NR 路径，前端只需按标准路径写入即可。

## 3. 与设备详情页现有 tab 的关系

设备详情页当前 5 个 tab：`详情` / `参数树` / `活动告警` / `KPI` / `许可证列表`。

**决策：新增 1 个 tab，初步命名 `快速设置`**（命名沿用老版接口 `quicksettings`，最终命名见 §8-Q1）。

不放进现有 tab 的理由：

| Tab | 当前职责 | 不适合的理由 |
|---|---|---|
| 详情 | 静态键值对概览（身份/状态/位置） | 30+ 字段表单 + 邻区 CRUD 表格会破坏"一眼看完"价值 |
| 参数树 | 全量 TR-069 原始对象树（664 对象） | 业务分组表单 vs 原始平铺树，交互范式不同 |
| 活动告警 / KPI / 许可证 | 各自独立领域 | 无关联 |

## 4. Tab 内部结构

按设备制式（`基站制式` 字段：`lte` / `nr`）渲染不同分组：

```
[快速设置]
├─ ENB（基站制式 = lte）
│   ├─ 小区参数           ← 16 字段，2-3 列网格表单（tab 级 Save）
│   └─ 邻区配置
│      ├─ 异频邻区频点列表 ← 9 字段，表格 + 行级增删改 + 行级 Save
│      └─ 邻区列表         ← 14 字段，表格 + 行级增删改 + 行级 Save
└─ GNB（基站制式 = nr）
    └─ 小区参数           ← 16 字段，2-3 列网格表单
```

未列出的分组在对应制式下直接不渲染（如 GNB 暂无邻区配置规划，就不显示该节）。

## 5. 数据通路

复用现有"参数树"已建好的数据链路：

- **读**：复用现有 `GetParameterValues` 入库后的设备参数表，按 §2 列出的 standard_path 过滤渲染
- **写**：批量 `SetParameterValues` 下发到设备（走 Task 队列）；多实例列表的新增走 `AddObject` + `SetParameterValues` 两步（详见 §6）
- **同步**：复用参数树 tab 的"同步参数"按钮，**同步范围为设备全量参数**（其中包含本 tab 的 55 项），无需为「快速设置」单独建同步入口；本 tab 顶部 Toolbar 仅放同一个按钮便于操作

不另起一份"快速设置专用"的数据缓存或表。

## 6. 关键 UI 决策

| 议题 | 决策 |
|---|---|
| **FAPService 实例选择（ENB）** | ENB 设备 tab 顶部加 FAPService 实例下拉（默认 `#1`，设备最多 12 个），切换后表单与列表值跟着变 |
| **FAPService 实例选择（GNB）** | GNB 设备 FAPService 固定为 `1`，**不显示**该下拉 |
| **CellConfig 索引（GNB）** | GNB 各参数路径含 `CellConfig.{i}`（NR 小区索引）。v1 PR 落地时按实际设备数据形态决定 UX：单小区设备锁定 `1`，多小区设备追加"小区下拉"。非阻塞项，详见 §9.5 |
| **路径占位符 `{i}` 替换** | 渲染时：外层 `FAPService.{i}` → ENB 用顶部下拉值 / GNB 固定 `1`；单实例分组内的子对象 `{i}` 按当前选择填充；多实例列表的内层 `{i}` 由表格行驱动 |
| **standard_path / private_path 翻译** | 前端只感知 standard_path；后端 Translator 负责双向翻译（已存在的 T-0098 机制） |
| **同步入口** | 复用参数树的"同步参数"按钮（同步范围为设备全量参数），本 tab Toolbar 放同一入口 |
| **下发交互（单实例分组）** | ENB / GNB 小区参数等单实例表单：tab 顶部一个 Save 按钮，提交该表单全部字段变更，作为一个批量 SetParameterValues 任务下发 |
| **下发交互（多实例列表）** | 异频邻区频点列表、邻区列表：**行级 Save**。每行独立编辑 → 行内 Save 触发该行一次 SetParameterValues；**新增行：先 `AddObject` 创建空实例 → 再 `SetParameterValues` 写值（两步）**；删除行走 `DeleteObject`。行间互不影响，一行失败不阻塞其他行 |
| **任务结果反馈** | 单实例 Save 与列表行级 Save 都走 Task 队列，结果在通知中心查看 |
| **Tab 命名** | `快速设置` / `Quick Settings`（i18n namespace `device.quickSettings`） |
| **失败处理** | 一次 Save 部分失败时**不回滚**已成功项，按字段标红展示失败结果（**适用于单实例表单与多实例行内**，规则一致），由用户决定重试或修正 |
| **重试行为** | 失败标红后，行内/表单仍保留**用户上次输入值**；点击"重试"使用该输入值原样重发 SetParameterValues |
| **与配置模板/基线关系** | v1 解耦，模板侧不集成本 tab；后续可作为独立增强探索 |
| **UI 库选型** | 保持 Ant Design `Form` Grid + `Table`，**不引入** `ProForm` / `EditableProTable`（与参数树 tab 风格统一） |

## 7. 字段元数据来源

字段的**类型、取值范围、枚举映射、中英文名、单位**来自 OMC 内部的 `standard_params` 字典（T-0098 后建立）。前端不硬编码这些元属性，全部通过字典 API 拉取。

字典缺口已知项见 §2.3。

### 9.5 风险与开放项

- **字段中英文 label 来源**：v1 走 XML 的 `titleZh` / `titleEn`（不进 i18n 文件）；后续 `standard_params` 补齐 zh/en label 后可改为从 schema 拉取再次精简
- **`EnbCellType` 显示**：v1 BLQ.xml 按 `U_INT` + `min=0` + `max=1` 补齐（v0.7 计划 `enum` 因 `param_mappings` schema 现状不支持，实施期回退到 U_INT，详 §9.2.2 说明）；v1 前端渲染数字输入框（输入限定 0/1）；显示"宏站/微站"需后续 ① 扩 `param_mappings` 表支持 enum 字段 ② `standard_params` 补 label map，两者均不在 v1 范围，留独立 Task
- **GNB CellConfig.{i} 索引 UX**：GNB 各路径含 `CellConfig.{i}`（NR 小区索引），v1 实施 PR 落地时按实际设备数据形态决定：单小区设备直接锁定 `1`；若实际存在多小区，再追加"小区下拉"。不阻塞 v1 上线
- **53 项字典覆盖核验**：实施过程中按 `useParameterSchema` 返回检测，发现新缺口归并到字典补齐 PR（不阻塞 v1 上线）
- **多 FAPService 实例 UX（ENB）**：12 个实例下拉够用；若实际超过 20 个再考虑实例搜索
- **XML schema 草案最终化**：§9.2.3 的 XML 结构为草案，最终元素/属性命名以实施 PR 为准；建议落地前加一个 schema 单测样例文件防止后续无意改动

# MML 多实例查询与邻频分组代码审查报告

## 审查范围

审查暂存区中的 7 个文件，覆盖：

- 邻频、异频 MML 分组及增量 SQL
- MML 动态实例路径组装
- ACS GPV 9005 自愈与结果保存
- 相关单元测试

## 六维审查

### 1. 架构影响

修改保持 MML fanout、ACS handler、任务结果查询和数据库 seed 的既有职责边界，没有新增跨进程接口或改变任务数据结构。ACS 仍负责任务续查，MML 仍负责参数路径组装。

### 2. 业务逻辑

已修复现场根因：带 `{i}` 的叶子参数不再折叠为 `Device.Services.FAPService.`，避免 GPV 查询整个 FAPService 子树并触发未选中参数的 9005。未绑定实例的动态路径会在组装阶段被校验拒绝；明确选择实例后使用具体路径下发。

MML GPV 9005 仍会剔除坏路径并创建同 `source_id` 的续查任务，同时保存原始 Fault 和参数故障详情，便于结果接口展示恢复过程。

### 3. 资源与安全

本次 Go 逻辑仅处理内存中的路径和 JSON，不新增文件、连接或 goroutine 资源。路径仍经过既有合法根、占位符和字符校验，未放宽 TR-069 路径校验。

### 4. 兼容性

无实例占位符的历史具体路径行为保持不变。依赖动态实例路径的调用方必须先提供 `instance_selectors`；这是有意的行为约束，避免把用户选择扩大成整棵设备对象树。邻频和异频命令分别归组，避免 `Mobility.InterFreq` 混入邻频。

### 5. 代码质量

函数接口变化已同步更新两个 Fault 入口，测试中的无用导入已清理，Go 文件已格式化。多实例 9005 采用部分成功语义，不再生成前序实例续查路径。

### 6. 验证情况

- `get_errors`：通过
- `git diff --check`：通过
- `gofmt`：已执行
- `go test ./internal/mml`：未完成

未完成原因：当前环境无法访问 `proxy.golang.org`，缺少的 Go 模块无法下载；不是测试断言失败。

## 审查结论

**综合评级：APPROVED_WITH_NOTES**

代码修改范围与问题根因匹配，可以提交。部署后应使用远程设备重新验证实际 GPV 请求的 `names`，确认不再出现 `Device.Services.FAPService.` 这类宽泛路径；同时在依赖缓存完整或网络可用环境补跑 MML 和 ACS 单元测试。

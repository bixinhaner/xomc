# 0006 — 引入通用时间基准计数器「统计时长」，所有按时间归一化指标统一用它做分母

## Status

Accepted。决策于 2026-06-15 定稿（issue #389 阶段1），经一轮 grill/brainstorming 逐点锁定。

> 本决策建立在 ADR 0004（三库导入范式）之上：新指标按既有范式登记进 Indicator 库三制式 XML。

## Context

主仪表板「可用性」面板长期显示「暂无聚合数据」。坐实根因：老版 OMC 里「小区可用率」不是独立 KPI，而是拿「小区在服时长」计数器按 `在服时长 ÷ 统计周期 × 100` 现场算的；老版的统计周期是程序传入的**固定常量**（不参与聚合）。新版迁移时丢了这套「按时间归一化」算法，仪表板把该指标留空、什么都不接。而真站其实完整上报了「小区在服时长」（满在服 = 900 秒/周期），数据齐全——纯属功能缺口。

直接照搬老版「把周期写死成 900 常量」会在新版的多小区、多粒度聚合体系下失真：

- 常量分母不随粒度（小时/天/周/月）放大，聚合后比率算错。
- 常量分母按「小区数」放大也无从谈起——全网维度多个小区累加时，分子累加、分母却是单个常量，比率失真。
- 某小区某时段停报时，固定分母会把它当成「满可用」稀释整体可用率。

需要一个能在任意粒度、任意维度都给出**正确分母**的机制，且不为此去改公式引擎 / 聚合内核 / 在服时长计数器的累加语义。

## Decision

引入一个**全系统通用的时间基准计数器「统计时长」（StatisDuration）**，作为所有「按时间归一化」指标的统一分母：

1. **合成累加计数器**：解析每个性能文件时，由解析层为每个小区补一条「统计时长」，值 = 文件头里的**真实采集周期**（当前 900 秒，取文件实际值、不写死，将来周期变化也自动正确）。它是 `statisType=sum` 累加型，跟随现有累加聚合一路滚动（单小区小时=3600、天=86400、全网=所有小区累加）。设备不上报，纯由解析层注入。
2. **小区可用率 = 在服时长 ÷ 统计时长 × 100**，新增为派生指标（`statisType=pct`）。因分子（在服时长）与分母（统计时长）都是**同源累加量**，比率在任意粒度、任意维度都成立——粒度、小区数、停报全部自动消解。
3. **公式引擎 / 聚合内核零改动**：因为「统计时长」就是个普通累加计数器，不需要在聚合阶段额外统计采样数。
4. **在服时长保持累加语义不变**：它是原始计数器，不为凑算法去改它的聚合方式。
5. **命名约定（强约束）**：命名为「统计时长」、明确「累计」语义，**不叫「周期」**——避免被误当成固定 900 常量、在聚合后误用算错。**今后所有「按时间归一化」的指标，分母一律用「统计时长」，禁止再把采集周期写死成秒数常量。**
6. **三制式登记**：「统计时长」与「小区可用率」在 4G(ENB) / 5G(GNB) / GSM 指标库各自登记。
7. **仪表板别名接通**：把仪表板「可用性」别名（LTE_CELL_AVAILABLE，原 KCode 留空、返回空序列的硬缺口）接到新建的 LTE「小区可用率」指标编号上。

## Consequences

- 主仪表板可用性面板可出图；真站在服时长齐全，改完后该站可用率稳定 ≈ 100%。
- 后续所有按时间归一化指标（吞吐率等）有了统一、正确、可聚合的分母，根除「写死周期常量」一类隐患。迁移存量归一化指标到此分母是后续工作（本单只接「小区可用率」一个消费者验证机制跑通）。
- 历史数据不回填——可用率仅对改完后的新上报数据生效。
- **引用方注意**：「统计时长」是累计量、不是固定 900。任何拿它做分母的公式都应假定它随粒度/小区数放大，禁止再把它当常量或回退成写死秒数。
- 范围裁剪：接入性、移动性两个空 KPI 属数据原因（真站不报相关计数器 / 业务量恒 0），不在本决策范围。

## 阶段1 落地说明（本单已实现部分）

- 指标库三制式 XML 各登记两指标：4G `C000060273`（统计时长）/ `K900010076`（小区可用率，公式引用在服时长 `C000060216`）；5G `C010120025` / `KGNB0570`；GSM `CGSM0080001` / `KGSM0143`。
- 仪表板别名 LTE_CELL_AVAILABLE → `K900010076`。
- **解析层注入「统计时长」在阶段2 实现**（本单不改解析层）。5G/GSM 当前缺「小区在服时长」原始计数器（仅 4G 上报），其可用率出数同样取决于在服时长是否上报——属后续/数据问题。

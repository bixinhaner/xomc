# OMC 邮件通知配置与验收

本文给测试、交付和运维同事使用，不要求了解代码。

只需要完成常规配置和验收时，可直接阅读[《邮件通知快速操作手册》](email-notification-quick-guide.md)；本文保留完整的环境、升级和故障边界说明。

## 1. 先向客户或邮箱管理员索取什么

请索取一套“系统发件账号”，不要使用员工个人邮箱。需要确认：

| 项目 | 示例 | 说明 |
|---|---|---|
| SMTP 主机 | `smtp.customer.example` | 由邮箱管理员提供，不要照抄旧 Office365 地址 |
| SMTP 端口 | `587` | 常见还有 465、客户内网 25，以管理员答复为准 |
| 安全模式 | `STARTTLS` | 可选 STARTTLS、隐式 TLS、无 TLS |
| 是否认证 | `是` | 客户内网可信 SMTP 可能不认证 |
| 用户名 | `omc-notify@customer.example` | 通常是完整邮箱地址 |
| 密码/授权码 | 由管理员单独提供 | 不写进文档、工单、Git 或聊天记录 |
| 发件地址 | `omc-notify@customer.example` | 某些服务要求与用户名相同 |
| 发件名称 | `Customer OMC` | 收件箱显示名 |
| 允许来源 | OMC 服务器 IP 或网段 | 如邮箱侧有白名单，需登记各环境出口 IP |
| 附件限制 | 例如 20 MB | OMC 当前也限制单个 KPI 邮件附件不超过 20 MB |

还要请管理员确认：SMTP AUTH 是否开启、该账号是否允许程序发送、每分钟/每天限额、外部收件域限制，以及测试与生产是否允许共用发件账号。

## 2. 账号和多服务器的关系

- 发件账号属于一个逻辑 OMC，不属于某个 app/worker 容器，也不是收件人。
- 同一套 OMC 的多台 app/worker 共用 PostgreSQL 中的邮件配置，只配置一次，不需要逐容器设置。
- 个人测试、公共测试、生产通常是三套独立 OMC/数据库，因此每个环境各配置一次。
- 是否让多个环境共用一个发件账号由客户邮箱管理员决定。生产建议使用独立系统账号，便于审计和限流。
- 配置保存后 app 与 worker 每次发送都会读取共享配置，不要求逐台重启。

## 3. 三种常见配置参考

以下只是格式示例，主机、端口和开关必须以客户邮箱管理员提供的信息为准。

| 场景 | 端口 | 安全模式 | 认证 |
|---|---:|---|---|
| 阿里企业邮箱（管理员提供 465/SSL） | 465 | 隐式 TLS | 开启 |
| 提供 587/STARTTLS 的企业邮箱 | 587 | STARTTLS | 开启 |
| 客户封闭内网 SMTP Relay | 25 | 无 TLS | 常见为关闭，需服务器 IP 白名单 |

系统不再写死 `smtp.office365.com`。更换邮箱服务商只改系统设置，不改业务代码。
无 TLS 模式只支持不认证的受控内网 Relay；如果邮箱服务器要求账号认证，必须选择 STARTTLS 或隐式 TLS。

## 4. 页面配置

1. 使用 `super_admin` 登录 OMC。
2. 打开“系统管理 → 系统设置 → 邮件通知”。
3. 填写管理员提供的 SMTP 信息并保存。
4. 密码保存后不会回显；页面显示“已配置”即正常。修改其他字段时密码留空会保留原密码。
5. 在“测试邮件”中只填写本次获准的测试收件人，点击测试。
6. 确认收件箱的 From、主题、时间和正文，再进入业务配置。

测试按钮只发给当次填写的一个地址，不会读取告警模板或 KPI 模板的收件人。

## 5. 业务收件人在哪里配置

### 告警邮件

打开“告警管理 → 告警邮件订阅”：

- 全局设置保存默认业务收件人；
- 每个订阅可保存自己的收件人，并决定是否合并默认收件人；
- 订阅还定义告警范围、Real Time/10/30/60 分钟周期和容忍时长；
- 发件账号仍使用系统设置，不在订阅里重复填写。
- 旧告警过滤规则中的 `notify_email` 已退役，升级协调会把每条旧规则自动转换为 Real Time 告警邮件订阅，保留显式收件人及告警标识、来源、设备和设备组范围；迁移后的名称以 `Legacy` 开头，可在“告警邮件订阅”中复核和调整，不要继续维护旧动作。
- 旧规则缺少有效收件人或无法关联创建者时仍会迁移，但保持禁用，避免升级时误发。

### KPI 定时报表

打开“性能管理 → 指标查询”，先新建查询模板并保存设备、指标等查询范围，再选择该模板，在右侧查询操作栏点击“定时报表”。这与老项目“模板 → Regular Report”的业务名称和使用顺序一致，但新项目把入口放在查询主操作区，不再要求从模板的“更多”菜单查找。

在独立的“KPI 定时报表”抽屉中设置：

- 启用、发送时间；
- Day、Hour、15Min，可多选；
- 邮件开关和收件人。
- 抽屉顶部只读显示模板中的设备数和指标数；需要调整报表范围时点击“编辑查询范围”，不要在定时报表中重复选择。
- 启用报表前必须至少选择一台设备和一个指标；空指标配置不会退化为全量指标导出。

到点后 worker 生成最近一个完整周期的 CSV，上传共享对象存储，再作为附件逐个收件人发送。某个地址失败时只重试该地址，不重复生成 CSV，也不重发已经成功的地址。

统计窗口按 OMC 系统时区：15Min 取最近完成的 15 分钟，Hour 取最近完成的自然小时，Day 取前一个自然日。

告警聚合邮件和 KPI 定时报表的运行结果统一在“通知中心 → 邮件发送记录”查看。普通用户只能看到自己创建的告警邮件订阅、自己拥有的 KPI 模板所产生的记录；超级管理员可以查看全部。打开详情可以核对每个收件人的状态、尝试次数和最后错误。

SMTP 在网络超时等“服务端是否已接收未知”的场景无法提供严格的端到端 exactly-once。OMC 对同一投递重试时复用稳定的 `Message-ID`，并且不会重发数据库中已经成功的收件人；邮箱服务器是否进一步去重由客户邮件系统决定。

告警邮件任务入队时会固化当时的订阅筛选范围和最终收件人。之后编辑订阅或默认收件人不会改变已经排队的任务；关闭全局邮件业务或禁用订阅仍会阻止未执行任务继续发送。

## 6. 脚本配置（多环境推荐）

脚本位置：`deployments/release/bundle/deploy/configure-email.sh`。每个环境执行一次，配置写入该环境的共享数据库。

```bash
export OMC_URL='https://omc-test.customer.example'
export ADMIN_TOKEN='由管理员生成的临时管理令牌'
export SMTP_HOST='smtp.customer.example'
export SMTP_PORT='587'
export SMTP_SECURITY_MODE='starttls'
export SMTP_AUTH_ENABLED='true'
export SMTP_USERNAME='omc-notify@customer.example'
export SMTP_PASSWORD='通过安全渠道取得的密码或授权码'
export SMTP_FROM_ADDRESS='omc-notify@customer.example'
export SMTP_FROM_NAME='Customer OMC'
export SEND_TEST_EMAIL='true'
export TEST_RECIPIENT='本次获准的测试收件人'

./configure-email.sh
unset SMTP_PASSWORD ADMIN_TOKEN
```

只修改主机、端口等非密码字段时，可不提供密码并设置 `KEEP_EXISTING_PASSWORD=true`。首次部署认证 SMTP 时必须提供密码。

从旧版本升级时，若数据库/YAML 尚未配置且仍保留 `OMC_SMTP_*` 环境变量，新版本会暂时读取这些变量作为兼容兜底。完成页面或脚本配置并验证后，应从部署清单中移除旧环境变量，避免长期维护两套来源。

### 已有测试环境升级注意事项

104 等已经运行过旧版 `000001` 基线的环境，不能只替换 App、Worker 和 Web 镜像。发布前先备份主库，然后按项目标准部署流程执行 `migrate-schema` 和 `migrate-seed`；`migrate-seed` 会运行基线协调，补齐邮件业务表、SMTP 默认配置、API 端点、内置角色权限和菜单，并幂等转换遗留 `notify_email` 规则。迁移成功后再启动或重启 App、Worker、Web，使权限缓存加载新数据。

升级后应先只读核对：6 张邮件业务表、10 项 `notification.email` 配置、9 个邮件 API 端点和“告警邮件订阅”菜单均存在；每条遗留 `notify_email` 规则最多对应一条 `Legacy` 订阅；Worker 日志应出现 `realtime alarm email subscriber started`，不得出现 `filtered consumer not unique`。转换本身不会写入真实 SMTP 密码或直接发送邮件；若存在可用的启用旧规则，告警邮件业务总开关会随迁移开启，因此启动 Worker 前必须先复核迁移后的范围和收件人。迁移失败时停止启动业务服务，保留日志并从发布前备份恢复，不要手工绕过迁移状态。

## 7. 上线验收清单

- [ ] SMTP 信息来自客户邮箱管理员，未沿用 Office365 旧配置。
- [ ] 发件账号是系统公共账号，不是个人账号。
- [ ] 密码/授权码未进入 Git、工单、日志和截图。
- [ ] 只向获准的测试地址发送一封通道测试邮件。
- [ ] 告警默认收件人、订阅收件人与发件账号没有混淆。
- [ ] KPI 模板的周期、系统时区和收件人已复核。
- [ ] KPI 定时报表至少选择一台授权设备和一个指标。
- [ ] 多节点读取同一个 PostgreSQL 和共享对象存储。
- [ ] 已有环境已备份数据库并成功执行 `migrate-schema`、`migrate-seed` 基线协调。
- [ ] 遗留 `notify_email` 已逐条核对迁移数量、启用状态、范围和收件人。
- [ ] 测试完成后删除临时订阅/模板，或恢复原配置。

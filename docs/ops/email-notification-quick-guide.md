# OMC 邮件通知快速操作手册

本文给测试、交付和现场运维同事使用，只覆盖邮件通知，不包含短信。完整的 SMTP 参数、升级协调和故障边界见[《OMC 邮件通知配置与验收》](email-notification-configuration.md)。

## 一、使用前确认

- 使用系统公共发件账号，不使用个人邮箱作为发件账号。
- 从邮箱管理员处取得 SMTP 主机、端口、安全模式、认证方式、用户名、密码或授权码、发件地址。
- 取得允许接收测试邮件的邮箱地址；没有收件人授权时不要发送真实邮件。
- 确认 OMC 系统时区正确。KPI 定时报表按系统时区计算最近一个完整统计周期。

## 二、配置并测试邮件通道

1. 使用管理员账号登录 OMC。
2. 打开“系统管理 → 系统配置 → 通知设置”。
3. 开启“邮件通知服务”，填写 SMTP 参数并保存。
4. 密码保存后只显示“已配置”；修改其他字段时密码留空会保留原密码。
5. 在“测试邮件”中填写本次获准的单一收件人并发送。
6. 收件箱确认 From、主题、正文和时间均正确后，再配置业务邮件。

测试邮件只验证 SMTP 通道，不读取告警订阅或 KPI 模板的收件人。

## 三、配置告警邮件

1. 打开“告警管理 → 告警邮件订阅”。
2. 开启全局告警邮件业务。
3. 新建订阅并填写名称、告警范围、设备范围、周期和收件人。
4. Real Time 用于告警产生或清除后异步发送；10/30/60 分钟用于周期聚合。
5. 保存后通过一条已授权的测试告警验证产生、清除和发送记录。

发件账号只在系统通知设置中配置；订阅中的地址都是收件人。

## 四、配置 KPI 邮件定时报表

新项目沿用老项目“查询模板 → Regular Report”的业务习惯，并将入口放在查询主操作区。

1. 打开“性能管理 → 指标查询”。
2. 点击“新建查询模板”，填写模板名称、设备类型、设备、指标、粒度和人工查询时间范围，然后保存。
3. 在左侧选择刚保存的模板，再点击右侧查询操作栏的“定时报表”。
4. 在抽屉顶部核对报表范围中的设备数和指标数；范围不正确时点击“编辑查询范围”。
5. 开启定时报表，配置发送时间和 Day、Hour、15Min 中的一个或多个统计周期。
6. 开启邮件发送，填写收件人并保存。
7. 模板旁出现“报表已启用”状态，表示计划已生效。

定时任务生成的是最近一个完整周期的 CSV：

| 周期 | 统计窗口 |
|---|---|
| 15Min | 计划时间前最近完成的 15 分钟 |
| Hour | 最近完成的自然小时 |
| Day | 前一个自然日 |

模板中用于人工查询的“近 3 小时”等时间范围不参与定时报表窗口计算。启用报表时必须至少选择一台授权设备和一个明确指标。

## 五、查看结果

1. 打开“通知中心 → 邮件发送记录”。
2. 按业务类型查看“告警邮件”或“KPI 定时报表”。
3. 核对计划执行时间、统计范围、任务状态、成功/失败数量。
4. 打开详情，核对每个收件人的发送状态、尝试次数和最后错误。

页面显示“发送成功”表示 SMTP 服务已接受邮件；是否进入最终收件箱仍需收件人确认，并检查垃圾邮件规则。

## 六、常见问题

| 现象 | 优先检查 |
|---|---|
| 测试邮件失败 | SMTP 主机、端口、安全模式、认证方式、账号授权和网络白名单 |
| 业务任务没有执行 | 邮件总通道、告警业务/订阅或 KPI 定时报表是否启用，计划时间与系统时区是否正确 |
| KPI 报表无法启用 | 模板是否至少选择一台设备和一个指标，周期和收件人是否完整 |
| 任务部分失败 | 在发送记录详情查看失败地址；系统只重试失败收件人 |
| 收件箱没有邮件 | 先确认发送记录，再检查垃圾邮件、邮箱限流和收件域策略 |

## 七、验收结束

- 删除为验收创建的临时告警订阅和 KPI 查询模板。
- 恢复验收前的邮件总通道、告警邮件业务开关和测试告警状态。
- 保留邮件发送记录作为验收证据。
- 不在验收报告、截图、日志或 Git 中记录 SMTP 密码或授权码。

# 前端弹出层显示异常修复总结

## 现象

- 点击后看起来“没有弹层”
- 但实际展开态已经生效，DOM 里也有菜单节点

这类问题通常不是“没渲染”，而是：

1. 弹层定位跑到屏幕外
2. 弹层被别的层盖住
3. 浏览器还在跑旧资源

## 本次最终修复

保留的文件：

- /home/baicells/goomc/omcmb/webcode/src/components/Layout/Header/UserDropdown.tsx
- /home/baicells/goomc/omcmb/webcode/src/components/Layout/Header/Header.module.css
- /home/baicells/goomc/omcmb/webcode/src/components/Layout/AppShell.module.css

处理分两步：

1. 把用户菜单从 Ant Design Dropdown 改成组件内本地渲染菜单
- 直接挂在按钮旁边
- 用 menuOpen 控制开关
- 用 absolute 定位
- 补上点击外部关闭、Escape 关闭

2. 给 AppShell 的 header 建立有效层级
- position: relative
- z-index: 20

## 根因

不是一个问题，而是两个问题叠加：

1. 原 Dropdown 方案在部分浏览器里定位不稳定，菜单会跑到可视区域外
2. 改成本地菜单后，菜单又被外层布局的 tabBar/content 层盖住

所以这次能真正修好，是因为同时解决了：

- 定位异常
- 层级遮挡

## 复用结论

其他页面如果也有类似问题，优先检查这四件事：

1. 当前浏览器加载的是不是最新前端资源
2. 弹层是不是已经真正进入展开态
3. 弹层位置是不是已经跑出可视区域
4. 弹层区域的最上层元素是不是它自己

其中最有用的判断方法是：

- 看 aria-expanded
- 看 getBoundingClientRect
- 用 elementFromPoint 判断弹层是不是被盖住

## 适用建议

对顶部头像菜单、更多操作菜单、卡片右上角菜单这类固定位置的小弹层，优先考虑：

1. 用本地绝对定位方案，少依赖通用浮层库
2. 让弹层所在外层容器主动建立层叠上下文
3. 验证是否修好时，以“用户实际可见”为准，不只看 DOM

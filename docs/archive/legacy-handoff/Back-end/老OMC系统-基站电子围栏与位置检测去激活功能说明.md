# 老 OMC 电子围栏与位置检测业务记录

> 文档性质：老项目事实与 189 环境现场记录
> 现场版本：13.0.5
> 现场日期：2026-07-29
> 边界：本文件只记录老系统已经观察到的业务、页面、参数和接口，不描述新项目架构。

## 1. 业务范围

老 OMC 的位置安全业务包含两类规则：

1. 固定安装点偏移检测；
2. 多边形电子围栏越界检测。

业务目标是识别基站位置异常，并按策略进行告警、去激活或恢复。电子围栏不负责首次
接入资格判断，也不能用设备在线状态或 `op_state` 代替位置安全状态。

需求单 #105820 明确描述：

- OMC 配置合法区域；
- 基站离开区域并持续一段时间后，OMC 通知基站去激活 IPSec 和射频，并产生告警；
- 基站回到合法区域后，OMC 通知安全网关激活 IPSec，并恢复相关业务、清除告警；
- 位置检测还应支持固定安装点偏移规则。

189 现场只证明了围栏配置、设备绑定、地图展示和配置审计，没有取得安全网关 IPSec、
RF 控制及自动恢复的完整运行证据。

## 2. 关键业务规则

1. 围栏归属运营商，用户只能操作授权运营商和设备范围。
2. 围栏至少包含名称、启用状态、多边形坐标和绑定设备。
3. 设备离开围栏不解除绑定。
4. 运营商级开关关闭后，围栏停止显示和后续判断，但不等于设备已恢复。
5. 单围栏禁用只停止该规则的后续判断，不等于批量激活设备。
6. 删除围栏不能被理解为仅删除地图图形，绑定和设备处置必须另行确认。
7. 无效、缺失或异常 GPS 不能直接当作安全位置。
8. 重复位置样本不应重复触发控制动作。
9. 只有明确由位置策略关闭的设备，才可能按策略恢复。
10. 页面提示保存成功，只表示请求被受理，不表示异步绑定、判定和设备控制已经完成。

## 3. 客户端操作流程

### 3.1 进入功能

1. 登录 OMC 客户端；
2. 进入 **eNB 监控/拓扑地图**；
3. 在地图右上方打开 **Geo-fence**；
4. 面板显示运营商级开关、新增按钮、围栏列表和搜索框。

工具是否显示受系统功能配置控制，具体操作还受用户权限和运营商数据范围限制。

### 3.2 运营商级开关

开启：

1. 单击关闭状态的 `Geo-fence Enable`；
2. 在确认框中确认；
3. 成功后重新加载并绘制当前运营商已启用围栏；
4. 失败时恢复原开关状态并提示错误。

关闭：

1. 单击已开启的开关并确认；
2. 客户端提交关闭请求；
3. 地图移除围栏，新增、编辑、删除和单围栏开关不可用；
4. 失败时恢复原状态。

关闭页面显示或运营商级开关不代表关联设备已经恢复或激活。

### 3.3 新增围栏

1. 确认运营商级开关开启；
2. 单击新增/绘制；
3. 选择多边形方式，在地图依次单击至少三个点；
4. 完成绘制后打开配置面板；
5. 填写启用状态和围栏名称；
6. 核对系统按区域识别的设备；
7. 按设备编码或主机名搜索；
8. 可批量输入多个 SN；
9. 移除不应绑定的设备；
10. 单击确定保存。

批量 SN 页面提示支持分号、空格和换行，旧前端实际还接受逗号，并在提交前拼成分号
分隔字符串。未手工传入设备时，老客户端会按当前地图设备位置计算候选设备。

### 3.4 查询与定位

- 按围栏名称搜索；
- 查看围栏启用状态；
- 双击已启用围栏，地图定位到围栏；
- 单击地图围栏查看绑定设备；
- 按设备 SN 或名称搜索；
- 查看设备状态、设备编码和主机名；
- 导出围栏关联设备。

已禁用围栏不在地图绘制，双击也不定位。

### 3.5 编辑围栏

1. 在列表单击编辑；
2. 加载名称、状态、坐标和绑定设备；
3. 名称或状态可直接修改；
4. 区域变化时单击重绘并重新绘制多边形；
5. 重新核对自动识别和手工维护的设备范围；
6. 保存。

重新绘制区域和修改设备列表是两个独立动作。区域变化后必须重新核对绑定设备。

### 3.6 单围栏启停

- 启用后，围栏重新显示并参与后续位置判断；
- 禁用后，围栏从有效地图图层移除，不再参与后续判断；
- 请求失败时客户端恢复原状态；
- 禁用不隐式恢复或重新激活设备。

### 3.7 删除围栏

1. 核对围栏名称、区域和绑定设备；
2. 单击删除并二次确认；
3. 成功后从列表和地图移除；
4. 继续确认绑定和设备后续处置。

生产操作前应导出设备清单。老页面的物理删除语义不能直接复制到需要审计的新系统。

### 3.8 操作后确认

管理员不能只看成功提示，还应确认：

- 列表中的名称、状态和坐标正确；
- 地图显示与围栏状态一致；
- 绑定设备完整，失败 SN 已处理；
- 设备当前位置和位置事件符合预期；
- 控制任务是否发送并收到回执；
- 禁用或删除后是否需要人工恢复。

## 4. 189 环境现场证据

现场先只读摸排；在用户明确授权后，使用临时围栏和指定测试设备完成了一次可恢复的
“创建—编辑—批量绑定—启用—停用—删除”验证。验证结束后删除临时围栏，将 `fence3`
恢复为原来的 15 台绑定设备并关闭，`fench2` 始终保持开启。没有确认告警，也没有修改
设备业务参数。

### 4.1 页面与数据

- 地址：`http://172.21.172.189:8081/`
- 页面版本：13.0.5
- 入口：登录后进入 **Map**，顶部打开 **Geo-fence**
- 运营商级开关：现场为开启
- `fence3`：停用，绑定 15 台设备
- `fench2`：启用，绑定 11 台设备
- 双击 `fench2` 可定位到橙色虚线多边形
- 停用围栏不绘制且不能双击定位

### 4.1.1 创建到删除实测流程（2026-08-04）

1. 在 Map 的 **Geo-fence** 面板点击新增并绘制多边形；
2. 新建页面自动计算区域内设备，本次临时区域为 `Total 0`；
3. 输入名称 `105820-flow-verify-0804`，保存后列表增加到 3 条；
4. 编辑并改名为 `105820-flow-verify-0804-edit`；
5. 批量输入一个有效 SN 和一个不存在的 SN 时，页面弹出 `Input Failed` 并提供失败文件下载，
   主列表没有接纳有效项，表现为整次输入失败；
6. 只输入有效 SN 后设备进入列表。批量窗口会继承上一次设备搜索条件，导致列表显示
   `Total 0`，清空搜索条件后才显示真实绑定数，这是老页面状态泄漏缺陷；
7. 保存、再次编辑、继续添加第二台设备后列表为 `Total 2`；
8. 单围栏启用、停用直接执行并提示 `Fence status updated successfully`，没有二次确认；
9. 删除时弹窗明确提示围栏内所有设备将自动去激活；确认后临时围栏从列表和地图消失；
10. 删除临时围栏后，把测试前属于 `fence3` 的两台设备重新批量绑定回去，回查为
    `Total 15`，最后将 `fence3` 恢复为关闭。

这次操作还确认了一个核心模型事实：设备被手工加入新围栏后，会从原围栏设备清单消失；
例如临时围栏接收两台设备后，`fence3` 从 15 台变为 13 台，删除临时围栏不会自动把设备
放回原围栏。老系统的有效归属是**单设备单一当前围栏**，页面短时看到的重复清单或缓存
不能解释为多个围栏同时生效。

同日又用未绑定且离线的测试站 `1202000240194DP0015`（`172.24.224.27`）复核：自动候选为
空时可通过 Batch Input 加入，随后保存、启用、停用并删除临时围栏 `codex-test-0804`，列表
从 2 条增至 3 条再恢复为 2 条，`fence3/fench2` 数量和状态未变化。该设备始终离线、Inactive、
Unregistered，因此本次只能证明配置和控制入口被触发，不能据此声称设备已收到或完成去激活。

### 4.2 编辑字段

`fench2` 的 Modify 页面包含：

- Enable
- Fence Name：必填，最大 50 字符
- Redraw the fence
- Device List
- `Serial Number / Cell Name` 搜索
- Batch Input
- 从当前清单移除设备
- OK / Cancel

后端批量绑定结果包含 `successDevices` 和 `failedDevices`，失败 SN 可以下载。

旧客户端有两个不能照搬的缺陷：

1. 自动候选再次过滤为 `device.type === 'enb'` 且非 GSM，可能排除需求要求的 2G/5G；
2. 未重绘的普通编辑可能依赖为空的 `originalFenceId`，批量绑定不能依赖这种临时状态。
3. 批量窗口和设备列表搜索条件会跨操作残留，保存和验收必须清空过滤条件后回查总数；
4. 老页面批量输入混合有效/无效 SN 时表现为整次失败，与第三方位置接口的逐项部分成功
   语义不同，二者不能共用一套事务约定。

### 4.3 页面接口

| 功能 | 方法与路径 | 关键字段 |
|---|---|---|
| 查询运营商开关 | `POST /fence/queryOperatorSwitch` | 响应 `fenceSwitch` |
| 修改运营商开关 | `POST /fence/operatorSwitch` | `switch: 0/1` |
| 查询围栏列表 | `POST /fence/queryFenceList` | `fenceId/fenceName/fenceCoords/fenceStatus/deviceList` |
| 修改单围栏状态 | `POST /fence/updateFenceStatus` | `fenceId/fenceStatus` |
| 查询绑定设备 | `POST /fence/queryDevicesByFence` | `fenceId`，返回 SN、主机名、网元类型和状态 |
| 新增/编辑/删除 | `POST /fence/manage` | `operateType: 1/2/3` |
| 批量绑定 | `POST /fence/batchBindDevices` | `fenceId/deviceSns` |
| 导出设备 | `POST /fence/exportFenceDevices` | `fenceId` |

`/fence/manage` 保存字段：

```text
operateType, fenceId, fenceName, fenceStatus,
type=Polygon, fenceCoords, devices[]
```

现场曾出现开关提示成功、重新登录后状态不同，因此新系统必须以保存后的服务端回查为准。

### 4.4 日志与告警

Operation Logs 使用 `Geofence` 查询到 23 条，覆盖：

- Add/Modify/Delete Geofence；
- 单围栏 Enable/Disable；
- Operator-level Enable/Disable；
- 用户、来源 IP、操作明细、结果、失败原因和起止时间。

查询接口：

```text
POST /system/operatorLog/getOperationLogPageList.action
```

主要参数：

```text
timeZone, userCode, operateIp, logName, detail, result,
reason, startTime, endTime, searchText
```

Alarm Library 按 `fence` 检索为 0；按 `GPS` 检索有 6 条设备 GPS 类定义。绑定设备
`12020007592481D0013` 可见普通告警 `11500 Radio enable close` 和
`11184 Cell unavailable`，但无法证明它们由哪一个围栏或哪次位置判定触发。

### 4.5 未取得的运行证据

现场尚未证明：

- 真实越界/回区位置样本、来源和采样时间；
- 命中的围栏版本与连续采样判定；
- 安全网关 IPSec 冻结、释放、恢复请求和回执；
- 设备侧 IPSec、RF 任务及终态；
- 位置安全专用告警的产生和清除；
- 部分成功、超时、重试、补偿、对账和人工恢复。

已新增取得的运行证据：

- `POST /fence/batchUpdateDeviceLocation` 无需页面会话即可访问；
- Word 规范字段 `vesselName/updateTime` 和历史截图字段 `serialName/updatetime` 均被接口接收；
- 不存在的 SN 返回 HTTP 200、顶层 `success=true`，并在 `failedDevices` 中逐项返回
  `Device not found in OMC system`；
- 有效 SN 返回 `totalCount=1, successCount=1, failCount=0`，地图设备卡可回查到新经纬度；
- 在线实验室设备会很快通过自身 GPS/TR-069 把第三方写入位置覆盖回设备上报值。因此本环境
  不等价于“不能自主上报 GPS 的船载基站”，不能用它证明位置持续越界后的最终控制结果。

因此老页面只能作为配置和交互事实来源，不能作为完整控制链已经运行的证据。

### 4.6 老源码静态证据

仓库中的老 Web 源码镜像补充证明了两点：

- 资源文案包含“位置变化后去激活基站”和“重启后位置不匹配则去激活”的语义；
- 围栏启用、删除文案会描述设备激活/去激活，但页面保存接口本身仍只提交围栏配置。

这部分只能证明产品意图，不能证明控制实现。`FenceClient.java` 和
`FenceController.java` 已被 Esafenet 加密，无法从源码取得安全网关请求字段、认证、
回执或幂等协议。仓库中的 `SecGWServer1/2/3` 是下发给基站的南向配置参数，也不是安全
网关控制 API。新项目不得据此猜测接口，且仍以“禁用、解绑、归档不隐式恢复设备”为
安全边界。

需求单标题为 **【浙江联通】基于皮基站地理位置的接入管控**，状态为 CLOSED，目标验证版本为
`BaiOMC_12.3.5`。需求单自测结果声明了以下 7 项通过，但“自测声明”不等同于本次现场取得的
可复验证据，必须分开记录：

| # | 需求单验收标准 | 老项目自测声明 | 本文取得的证据 | 新项目结论 |

| 5 | 第三方平台批量上报位置并触发激活、去激活正常 | 通过 | 已实测两套字段别名、未知/有效 SN 响应和地图位置回查；在线测试站的设备 GPS 会迅速覆盖第三方位置，未取得稳定越界后的控制回执 | **部分完成**：位置入口契约已证实，仍缺无 GPS 测试站上的去激活、告警、回围激活和回执关联 |

| 7 | web 进程日志打印第三方接口记录正常 | 通过 | 仅有附件截图，未取得脱敏原始日志、请求 ID、响应码和失败日志 | **未完成/不可证**：新项目必须先取得第三方协议，再定义结构化入口日志和敏感字段脱敏标准 |

严格验收结论：需求单的管理面第 1–4、6 项有较充分的老系统页面或新项目实现依据；第 5 项是
核心控制闭环，当前只能判定为 Observe 阶段完成，不能判定为“激活/去激活正常”；第 7 项只有
自测声明和截图，不能作为新项目上线证据。需求单关联的后续问题单 `#107427`（名称过长）、
`#107428`（设备状态离线）、`#107434`（国际化提示）和 `#107503`（回围未激活）说明原验收
之后仍存在回归缺陷，后续开发必须把它们作为回归用例，而不是只看主单 CLOSED 状态。

#### 4.7.1 证据等级

- **A：可复现运行证据**：脱敏请求/响应、设备或网关回执、数据库状态、告警状态和日志可关联到同一位置样本。
- **B：现场页面或日志证据**：能证明配置或结果存在，但不能证明完整控制链。
- **C：自测声明、截图或产品意图**：只能作为待验证线索。

需求单第 5 项的位置接入达到 B 级，控制终态仍只有 C 级；第 7 项仍只有 C 级。新项目的
`enforce` 门禁必须要求控制终态达到 A 级证据。

#### 4.7.2 第三方位置上报规范已知内容

需求单附件 **《第三方平台批量位置上报接口设计及规范说明》** 已明确给出位置上报接口，
不能再表述为“没有第三方位置协议”。已知契约如下：

| 项目 | 规范内容 |
|---|---|
| 接口 | `POST /fence/batchUpdateDeviceLocation` |
| 请求体 | `{ "devices": [...] }`，建议单次最多 1000 个对象 |
| 设备字段 | `vesselName`、`serialNumber`、`longitude`、`latitude`、`updateTime` |
| 标识 | `serialNumber` 对应 OMC 的 `serial_number` |
| 坐标 | 字符串格式，范围经度 `-180..180`、纬度 `-90..90`，建议保留 4 位小数 |
| 时间 | `yyyy-MM-dd HH:mm:ss`，示例为 `2025-11-25 19:55:00` |
| 处理 | OMC 接收后参数校验，按每批 100 个异步处理 |
| 响应 | 返回 `success`、`message`，成功时返回 `totalCount`、`successCount`、`failCount` 和 `failedDevices` |
| 失败项 | 每项包含 `serialNumber` 和 `reason`，例如设备不存在或坐标越界 |
| 调用建议 | 每 10 分钟上报发生位置变化的设备，最小间隔不低于 1 分钟 |

189 实测同时接受附件规范的 `vesselName/updateTime` 和截图中的
`serialName/updatetime`。新项目对外文档只保留前者作为规范字段；若为老调用方兼容后者，
必须在 Adapter 层显式归一化并补契约测试，不能让拼写差异渗入领域模型。

当前项目已实现该路径（受认证保护的 `/fence/batchUpdateDeviceLocation`），并复用
`device_location_observations` 和 Outbox 进入现有围栏判定链；仍需补持久化批次幂等、可恢复异步
作业和控制执行结果关联。因此第三方位置上报是**规范已知、入口已实现、控制闭环未完成**。

该附件没有明确给出安全网关 IPSec 请求、设备 IPSec/RF 参数下发、执行回执或控制幂等协议；
这些仍需从详细设计文档和老项目可运行实现中单独核实。

## 5. 新项目必须保留的业务结果

1. Map 内进入电子围栏管理；
2. 系统/运营商开关；
3. 围栏绘制、列表、搜索、定位、编辑、启停和软删除；
4. SN 搜索、批量输入、绑定结果和绑定设备查询；手工加入新围栏时显式预览并确认从原围栏改绑；
5. 保存后回查服务端权威状态；
6. 位置样本可追溯到规则版本和判定结果；
7. 越界控制、通知和恢复分别记录状态，不能用一个成功提示代替；
8. 禁用、解绑或归档不得隐式激活设备；
9. 不同运营商和设备权限范围严格隔离；同一设备同一时刻只允许一个多边形围栏有效归属。

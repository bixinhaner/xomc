# 基站配置文件备份与恢复功能流程

> 文档范围：涵盖任务创建、TR-069 交互、文件传输及状态流转全过程，不包含具体代码实现。

---

## 一、功能概述

配置文件备份与恢复功能支持将基站（eNB）的当前运行配置导出为文件保存在 OMC 服务器上（备份），并在需要时将已保存的配置文件重新下发到基站使其恢复生效（恢复）。支持手动触发和周期性自动备份两种方式。

---

## 二、系统分层架构

```
┌────────────────────────────────────────────┐
│  前端 Web 界面                              │  用户操作入口
├────────────────────────────────────────────┤
│  OMCWebServer（REST API 层）               │  任务创建、查询、文件导入导出
├────────────────────────────────────────────┤
│  cellHandler（业务逻辑层）                 │  任务调度、状态管理、RPC调用
├────────────────────────────────────────────┤
│  FileUploadServer（文件处理层）            │  接收设备上传文件、格式解析
├────────────────────────────────────────────┤
│  TR069Server / cpeHandler（协议层）        │  TR-069 SOAP 消息收发
├────────────────────────────────────────────┤
│  基站设备                                  │  执行备份/恢复，上报结果
└────────────────────────────────────────────┘
```

## 三、配置文件类型（FileType）

TR-069 协议中，文件类型通过 `FileType` 参数区分：

| FileType 值 | 含义 | 适用场景 |
|---|---|---|
| `1 Firmware Upgrade Image` | 固件升级镜像 | 版本升级 |
| `3 Vendor Configuration File` | 厂商配置文件 | **配置备份 / 恢复** |
| `4 Vendor Log File` | 日志文件 | 日志采集 |

配置文件备份与恢复统一使用 `FileType = "3 Vendor Configuration File"`。

## 四、备份流程

### 4.1 整体流程

```
用户创建任务
    │
    ▼
OMCWebServer 接收请求，写入数据库
（backup_restore_task，task_type=1，task_status=0）
    │
    ▼
定时任务 BackupRestoreTaskJob 扫描待执行任务
（task_status=0 → 2）
    │
    ▼
cellHandler 构建备份参数，通过 RPC 调用 TR069Server
    │
    ▼
TR069Server 向基站发送 TR-069 Upload RPC
（命令基站将当前配置文件上传到 OMC 的 FTP 服务器）
    │
    ▼
基站执行配置导出，将配置文件上传至 FTP
    │
    ▼
基站上报 TransferComplete 事件
    │
    ▼
TR069Server / FileUploadServer 接收并处理结果
    │
    ▼
更新 backup_restore_task 和 backup_restore_file 表
（task_status=4，task_result=1成功 / 2失败）
    │
    ▼
前端查询展示结果
```

### 4.2 TR-069 交互：Upload RPC（备份时 OMC 命令设备上传配置）

OMC 向基站下发 `Upload` 请求，命令基站将配置文件主动推送到 OMC 的 FTP 服务器：

| 参数 | 值 / 说明 |
|---|---|
| CommandKey | `{cellCode}_BACKUP`（用于关联 TransferComplete 响应） |
| FileType | `3 Vendor Configuration File` |
| URL | `ftp://{ftp_server}/{backup_dir}/{filename}` |
| Username / Password | FTP 认证信息（来自系统配置） |
| DelaySeconds | 延迟执行秒数（通常为 0） |

### 4.3 TR-069 交互：TransferComplete 事件（备份结果上报）

基站执行完毕后，通过 Inform 上报 TransferComplete：

| 参数 | 说明 |
|---|---|
| CommandKey | 与 Upload 请求中的 CommandKey 对应 |
| FaultCode | `0` = 成功，非 `0` = 失败错误码 |
| FaultString | 失败时的错误描述 |
| StartTime / CompleteTime | 传输时间戳 |

## 五、恢复流程

### 5.1 整体流程

```
用户选择已备份文件，创建恢复任务
    │
    ▼
OMCWebServer 接收请求，写入数据库
（backup_restore_task，task_type=2，task_status=0）
    │
    ▼
定时任务 BackupRestoreTaskJob 扫描待执行任务
（task_status=0 → 2）
    │
    ▼
cellHandler 构建恢复参数，通过 RPC 调用 TR069Server
    │
    ▼
TR069Server 向基站发送 TR-069 Download RPC
（命令基站从 OMC FTP 服务器下载并应用配置文件）
    │
    ▼
基站从 FTP 下载配置文件，验证完整性（MD5），应用配置
基站可能执行重启
    │
    ▼
基站上报 TransferComplete 事件
    │
    ▼
TR069Server 处理结果，更新任务状态
（task_status=4，task_result=1成功 / 2失败）
    │
    ▼
前端查询展示结果
```

### 5.2 TR-069 交互：Download RPC（恢复时 OMC 命令设备下载配置）

OMC 向基站下发 `Download` 请求，命令基站从 FTP 服务器拉取配置文件：

| 参数 | 值 / 说明 |
|---|---|
| CommandKey | `{cellCode}_RESTORE`（用于关联 TransferComplete 响应） |
| FileType | `3 Vendor Configuration File` |
| URL | `ftp://{ftp_server}/{restore_dir}/{filename}` |
| Username / Password | FTP 认证信息 |
| FileSize | 文件大小（字节） |
| TargetFileName | 设备侧存储路径 |
| DelaySeconds | 延迟执行秒数 |

> **备注**：备份是设备主动上传（Upload），恢复是设备主动下载（Download）。两者名称以**设备视角**命名。

## 六、任务状态流转

```
创建任务
  task_status = 0（待执行）
       │
       ▼ 定时任务扫描触发
  task_status = 2（执行中）
       │
   ┌───┴───┐
   ▼       ▼
成功      失败
task_result=1  task_result=2
       │
       ▼
  task_status = 4（已结束）

可中途操作：
  暂停  → task_status = 3 / 6（暂停中）
  终止  → task_status = 5（终止中）
```

| task_status | 含义 |
|---|---|
| 0 | 待执行 |
| 1 | 等待中 |
| 2 | 执行中 |
| 3 | 已暂停 |
| 4 | 已结束 |
| 5 | 终止中 |
| 6 | 暂停中 |

| task_result | 含义 |
|---|---|
| 1 | 成功 |
| 2 | 失败 |

| task_type | 含义 |
|---|---|
| 1 | 备份 |
| 2 | 恢复 |

## 七、核心数据库表

### 7.1 backup_restore_task（任务记录）

| 字段 | 说明 |
|---|---|
| task_id | 主键，自增 |
| task_name | 任务名称 |
| task_type | 1=备份，2=恢复 |
| task_status | 任务状态（见上表） |
| task_result | 任务结果（1成功/2失败） |
| start_time / end_time | 执行时间 |
| create_time / create_user | 创建信息 |
| operator_code | 运营商编码 |

### 7.2 backup_restore_file（备份文件元数据）

| 字段 | 说明 |
|---|---|
| serial_number | 基站序列号 |
| file_name | 备份文件名 |
| update_time | 最新更新时间 |
| md5 | 文件 MD5 校验值 |
| file_size | 文件大小（字节） |
| operator_code | 运营商编码 |

### 7.3 backup_period_task（周期备份任务）

| 字段 | 说明 |
|---|---|
| task_id | 主键 |
| task_name | 任务名称 |
| cron_expression | Cron 表达式（定时规则） |
| is_enable | 是否启用（0/1） |
| create_time | 创建时间 |

---

## 八、周期备份

- 用户在 Web 界面配置 Cron 表达式，设置定时自动备份规则。
- `BackupPeriodTaskJob` 按 Cron 规则定期自动为已配置的基站创建备份任务，后续流程与手动备份相同。
- 过期的备份任务记录由 `DeleteExpireBackupRestoreJob` 定期清理。

## 十、Web REST API 端点

| 接口路径 | 方法 | 说明 |
|---|---|---|
| `/task/enb/config/backupRestore/addBackupRestoreTask` | POST | 创建备份或恢复任务 |
| `/task/enb/config/backupRestore/queryCellInfos` | POST | 查询可操作的基站信息 |
| `/task/enb/config/backupRestore/queryTaskList` | POST | 查询任务列表 |
| `/task/enb/config/backupRestore/queryTaskDeviceList` | POST | 查询任务下各设备执行状态 |
| `/task/enb/config/backupRestore/getProductType` | GET | 获取基站产品类型 |
| `/task/enb/config/backupRestore/single/importFile` | POST | 从本地导入配置文件（用于恢复） |
| `/task/enb/config/backupRestore/single/exportFile` | GET | 导出备份文件到本地 |
| `/task/enb/config/backupRestore/periodTask` | POST | 周期备份任务管理 |
| `/task/enb/config/backupRestore/terminateTask` | POST | 终止任务 |

# 设备数据查询

## 1. 功能概述

KPI VIEW 页面中，按设备维度查询 KPI 性能数据，支持表格视图和图表视图两种展示方式。

**表格视图**：分页展示各基站在一个时间周期内的指标值，支持按设备组、基站名称、序列号等条件筛选。

**图表视图**：展示选定基站在一段时间序列上的指标趋势，支持按天/周/月/年切换时间范围，自动填充时间缺口。

ENB/GSM 设备的查询由 OMCWebServer 通过 RPC 转发至 OMCParseKpiFile 模块处理；GNB 设备的查询由 OMCWebServer 本地处理。

---

## 2. 核心概念

### 2.1 PM 模板属性

PM 模板定义了查询的维度和范围，关键字段：

| 字段 | 说明 |
|-----|------|
| `statis_period` | 数据粒度（15/60/1440/10080/43200 分钟） |
| `statis_days` | 指定统计的星期几（逗号分隔，1=周一，7=周日），仅 15/60 粒度生效 |
| `statis_time` | 指定统计的小时（逗号分隔，如 "8,9,10"），仅 15/60 粒度生效 |
| `select_device_type` | 设备关联方式：`"1"` 按设备组关联，`"2"` 按单个设备关联 |
| `indicator_level` | 指标级别：`device`（设备级）、`plmn`（PLMN 级）、`device,plmn`（混合，ENB/GSM 专用） |
| `auto_access_device_group` | 模板关联的设备组 ID 列表（逗号分隔），`select_device_type=1` 时使用 |
| `device_type` | 设备类型：`GSM`（仅 BSC 设备）或 `ENB`（仅 4G 设备），为空时不区分 |

ENB/GSM 模板存储在 `small_cell.perf_template` 表，GNB 模板存储在 `small_cell.gnb_perf_template` 表。

### 2.2 设备标识（uniqueId）

图表视图中用 `uniqueId` 标识每条数据曲线对应的设备/小区，计算规则因设备类型而异（详见 5.4 节）。

### 2.3 指标级别与查询表选择

**ENB/GSM：**

ENB/GSM 的指标分两个级别存储在不同表中，查询时需根据模板的 `indicator_level` 选择：

| indicator_level | 说明 | 查询表 |
|----------------|------|--------|
| `device` | 设备级指标 | 设备维度表 |
| `plmn` | PLMN 级指标 | PLMN 维度表 |
| `device,plmn` | 混合级别 | 两套表均查询 |

当 `indicator_level = plmn` 且模板关联的设备同时包含 BSC（GSM）和非 BSC（4G ENB）设备时，查询需分两路：
- **BSC 设备**：其 PLMN 级数据存储在设备维度表中（`indicator_level='both'`），查询时追加 `bts_id` 存在性过滤
- **非 BSC 设备**：其 PLMN 级数据存储在 PLMN 维度表中，无额外过滤

两路结果合并返回。

**GNB：**

GNB 不区分指标级别，只有一套固定表，查询时无需考虑级别。

### 2.4 全运营商模板

系统内置一个特殊的"全运营商模板"（模板 ID 为固定常量）。当用户为超级管理员且使用全运营商模板时：
- 不做设备组维度限制，允许查询所有运营商的数据
- 若前端额外传入了 `operatorCode`，则仅查询该运营商下属的设备组

非超级管理员或非全运营商模板时，按用户权限和模板关联的设备组过滤。

### 2.5 数据保留时长限制

查询时系统会根据粒度自动限制可查询的时间范围长度：

| 粒度 | 保留时长配置项 |
|------|--------------|
| 15min | `holdTimeFor15m`（天） |
| 60min | `holdTimeFor60m`（天） |
| 1440 / 10080 / 43200 | `holdTimeFor24h`（天） |

时间范围调整规则：
- 用户传入的开始/结束时间从运营商时区转换为 UTC
- 两者都为空：结束时间取服务器当前 UTC 时间，开始时间 = 结束时间 - 保留天数
- 仅开始时间为空：开始时间 = 结束时间 - 保留天数
- 仅结束时间为空：结束时间 = 开始时间 + 保留天数
- 两者都传入：若间隔超过保留天数，截断结束时间 = 开始时间 + 保留天数

## 3. 数据表结构

### 3.1 MongoDB 设备维度数据表

| 粒度 | 固定表 | 按天分表 |
|------|--------|---------|
| 15min | `pm_value_15` | `pm_15min_yyyy_MM_dd` |
| 小时 | `pm_value_60` | `pm_hour_yyyy_MM_dd` |
| 天 | `pm_value_1440` | — |
| 周 | `pm_value_10080` | — |
| 月 | `pm_value_43200` | — |

**ENB/GSM PLMN 维度表（`pm` 数据库）：**

| 粒度 | 固定表 | 按天分表 |
|------|--------|---------|
| 15min | `pm_value_15_plmn` | `pm_15min_plmn_yyyy_MM_dd` |
| 小时 | `pm_value_60_plmn` | `pm_hour_plmn_yyyy_MM_dd` |

## 4. 表格数据查询

### 4.1 ENB/GSM 表格查询

**接口地址：** `POST /pm/template/getTemplateDataPage`

> 注：该接口由 OMCWebServer 接收请求后，通过 RPC 转发至 OMCParseKpiFile 模块处理。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| tempId | String | 是 | PM 模板 ID |
| timeZone | String | 是 | UTC 时区偏移量（分钟） |
| language | String | 否 | 语言代码 |
| reportPeriod | String | 是 | 数据粒度：15/60/1440/10080/43200 |
| startTime | String | 是 | 查询开始时间，格式 `yyyy-MM-dd HH:mm:ss` |
| endTime | String | 是 | 查询结束时间，格式 `yyyy-MM-dd HH:mm:ss` |
| operatorCode | String | 是 | 运营商编码 |
| groupId | String | 否 | 设备组 ID 过滤 |
| searchText | String | 否 | 按序列号或基站名称模糊搜索 |
| serialNumber | String | 否 | 按序列号搜索 |
| hostName | String | 否 | 按基站名称搜索 |
| cell_code_str | String | 是 | 基站编码（逗号分隔） |
| limit_num | String | 是 | 设备数量限制 |
| page | int | 是 | 当前页码 |
| rows | int | 是 | 每页条数 |

**返回值：**

```json
{
  "total": 100,
  "rows": [
    {
      "id": "文档ID",
      "serialNumber": "序列号",
      "hostName": "主机名",
      "groupName": "设备组名称",
      "startTime": "开始时间（用户时区）",
      "endTime": "结束时间（用户时区）",
      "timeLevel": "粒度",
      "eci": "...",
      "cellId": "...",
      "enodeId": "...",
      "plmnId": "...",
      "K900010006": "指标值",
      "...": "其他指标字段"
    }
  ]
}
```

**完整处理流程：**

```
1. 准备指标列表
   从模板关联的指标表中获取指标 ID 列表
   ↓
2. 准备模板信息
   查询模板属性（粒度、周、小时、设备关联方式、指标级别、设备类型）
   ↓
3. 构建 MongoDB 投影字段
   基础字段 + 模板关联的所有指标 ID
   PLMN 级模板额外包含 plmnId
   ↓
4. 构建时间过滤条件
   将用户时间转为 UTC，构建 start_time 范围过滤
   若模板配置了周/小时且粒度为 15/60，追加周小时过滤
   ↓
5. 构建设备类型过滤
   仅按设备组关联（select_device_type=1）时：
   GSM 设备追加 bts_id 存在性过滤
   ENB 设备追加 bts_id 不存在过滤
   ↓
6. 判断全运营商模板
   ↓
7. 构建设备组过滤
   根据模板类型和用户权限，确定 group_id 过滤范围
   ↓
8. 构建基站编码过滤
   通过 MySQL 查询满足条件的基站编码列表
   ↓
9. 构建待查询分表列表
   根据时间范围、粒度、指标级别确定 MongoDB 集合列表
   PLMN 级模板需区分 BSC 和非 BSC 设备分别构建
   ↓
10. 执行分页查询
    依次查询各分表，跨表分页
    ↓
11. 处理查询结果
    补充基站基础信息、时区转换、指标值处理
    ↓
12. 补充平台信息
    为每条数据补充基站平台类型
```

**步骤 4 周小时过滤详解：**

仅在以下条件同时满足时生效：
- 模板 `statis_days`（周）和 `statis_time`（小时）均非空
- `reportPeriod` 为 `15` 或 `60`

算法：
1. 将 UTC 时间范围转换为运营商本地时间
2. 遍历时间范围内的每一天，计算星期几（ISO-8601：1=周一，7=周日）
3. 如果该天匹配 `statis_days` 中配置的星期几：
   - 对 `statis_time` 中配置的每个小时，生成一个时间窗口 `[小时开始, 小时开始+1小时-1个周期]`
   - 将窗口转回 UTC
4. 将所有匹配的窗口构建为 MongoDB `$or` 条件：每个窗口为 `{start_time: {$gte: 窗口开始, $lte: 窗口结束}}`
5. 若无匹配窗口，设置不可能条件 `{1: 0}`，确保不返回数据

**步骤 7 设备组过滤规则：**

| 场景 | 过滤逻辑 |
|------|---------|
| 全运营商模板 + 超管 + 未传 operatorCode | 不过滤设备组 |
| 全运营商模板 + 超管 + 传了 operatorCode | 按 operatorCode 查询下属设备组 |
| `select_device_type=1`（按设备组） | 取模板关联的设备组 ID 列表；若用户额外传了 groupId，取交集 |
| `select_device_type≠1` + 用户传了 groupId | 使用用户的 groupId |
| 其他 | 不过滤设备组 |

**步骤 8 基站编码过滤规则：**

通过 MySQL 查询 `small_cell_infos` 表确定最终要查询的基站列表：

- 基础条件：`is_gnb != '1'`（ENB/GSM）、`device_status = 2`（在线）
- 按设备组关联（`select_device_type=1`）时：JOIN `rela_device_group_cell`，按 group_id 过滤
- 按设备关联（`select_device_type=2`）时：JOIN `perf_template_rel_device`，按 temp_id 过滤
- 支持按 `serialNumber`、`hostName`、`searchText`（模糊匹配序列号和主机名）进一步筛选
- 支持 `cell_code_str`（逗号分隔的基站编码列表）直接限定范围
- 支持 `limit_num` 限制返回设备数量
- 查询结果为空时返回空数据；结果超过配置阈值时抛出"搜索范围过大"提示

**步骤 9 分表列表构建：**

| indicator_level | 查询表 |
|----------------|--------|
| `device` | 仅设备维度表 |
| `plmn` + 纯 BSC 设备 | 仅设备维度表（BSC 的 PLMN 数据存在设备表中） |
| `plmn` + 纯非 BSC 设备 | 仅 PLMN 维度表 |
| `plmn` + BSC 与非 BSC 混合 | 两套表均查询（设置混合查询标记） |
| `device,plmn` | 仅设备维度表 |

设备类型判断优先级：
1. 模板 `device_type` 字段（`GSM` / `ENB`）
2. 遍历基站编码列表，逐个查询平台类型（BSC 或非 BSC）
3. 无基站编码列表时，默认视为两种都有

**步骤 10 混合查询处理：**

当混合查询标记为 true 时，查询分表阶段对非 PLMN 表追加 `bts_id` 存在性过滤，确保只返回 BSC（GSM）设备的记录，避免 4G 设备级数据污染 PLMN 级模板的查询结果。

**步骤 12 平台信息补充：**

查询每条数据的基站平台类型，并做以下字段处理：
- **BSC 平台**：`cellId` 显示为 `bts_id` 或 `bts_id (bts序列号)`
- **BM 平台**：若 `cellId` 为纯数字，计算 `enodeId = cellId / 256`，`cellId = cellId % 256`
- **CA 类型平台**：`eci` 字段拼接主辅小区标识

### 4.2 GNB 表格查询

**接口地址：** `POST /gnb/pm/template/getTemplateDataPage`

> 注：该接口由 OMCWebServer 本地处理，不经过 RPC。

**请求参数与返回值：**

参数与 ENB 基本一致（见 4.1 节），返回值结构相同，额外包含 `nrCGI` 字段，不包含 `eci`、`cellId`、`enodeId` 字段。

**完整处理流程：**

```
1. 映射粒度到集合名
   reportPeriod → GNB 固定集合名（如 60 → gnb_pm_value_60）
   ↓
2. 准备模板信息和指标列表
   查询 gnb_perf_template 表
   ↓
3. 构建 MongoDB 投影字段
   基础字段（含 nrCGI、plmnId）+ 指标 ID
   ↓
4. 构建时间过滤条件
   与 ENB 相同的时间范围 + 周小时过滤逻辑
   ↓
5. 查询符合条件的基站列表
   通过 MySQL 查询 gnb_perf_template_rel_device 或按设备组关联
   ↓
6. 模糊搜索处理
   若有 searchText，额外在 MongoDB 中搜索匹配的 nrCGI/plmnId/serial_number
   ↓
7. 构建基站编码过滤
   {small_cell_code: {$in: 基站编码列表}}
   ↓
8. 执行分页查询
   在单个 GNB 固定表中查询
   ↓
9. 处理查询结果
   补充基站信息、时区转换、指标值处理
   ↓
10. 补充平台信息
```

**步骤 1 粒度到集合名映射：**

| reportPeriod | 集合名 |
|-------------|--------|
| 15 | `gnb_pm_value_15` |
| 60 | `gnb_pm_value_60` |
| 1440 | `gnb_pm_value_1440` |
| 10080 | `gnb_pm_value_week` |
| 43200 | `gnb_pm_value_month` |

**步骤 5 基站列表查询：**

基础 SQL：
```sql
SELECT sci.small_cell_code, sci.serial_number, sci.host_name,
       rdgc.group_id, sci.CELL_IDENTITY cellId
FROM small_cell.small_cell_infos sci
INNER JOIN small_cell.rela_device_group_cell rdgc
       ON sci.small_cell_code = rdgc.small_cell_code
WHERE sci.is_gnb = '1' AND sci.device_status = 2
```

- 按设备关联（`relType=2`）时：追加 JOIN `gnb_perf_template_rel_device`
- 按设备组关联时：按模板关联的设备组 ID 列表过滤
- 支持 groupId、serialNumber、hostName、searchText 筛选
- 支持 limit_num 限制数量
- 结果按序列号排序
- CA 类型平台的 `cellId` 会拼接辅助标识

### 4.3 共性逻辑

#### 4.3.1 时间过滤构建

1. 调用数据保留时长限制逻辑（见 2.5 节），确定最终查询时间范围（UTC）
2. 构建 MongoDB 条件：`start_time: {$gte: minStartTime, $lte: maxStartTime}`
3. `maxStartTime` 计算：
   - 月粒度（43200）：将 endTime 转为运营商时区后向前推 1 个自然月，再转回 UTC
   - 其他粒度：`endTime - reportPeriod 分钟`

#### 4.3.2 结果处理

对所有查询结果做以下统一处理：

1. **补充基站基础信息**：通过 `small_cell_code` 关联 MySQL 查询序列号、主机名、设备组名称等
2. **时区转换**：将 `start_time`/`end_time`（UTC）转为运营商本地时间
3. **字段重命名**：`start_time` → `startTime`，`end_time` → `endTime`
4. **补充字段**：`timeLevel` = reportPeriod，`id` = MongoDB 文档 ID
5. **指标值处理**：
   - 字段不存在：跳过
   - 值为空：替换为 `"-"`
   - 值为 Decimal128 且为 NaN：替换为 `"N/A"`
   - 值为 Decimal128 且正常：转为字符串

## 5. 图表数据查询

### 5.1 ENB/GSM 图表查询

**接口地址：** `POST /pm/template/getChartDataList`

> 注：该接口由 OMCWebServer 接收请求后，通过 RPC 转发至 OMCParseKpiFile 模块处理。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| tempId | String | 是 | PM 模板 ID |
| timeZone | String | 是 | UTC 时区偏移量（分钟） |
| startTime | String | 是 | 起始日期，格式因 timeRange 而异 |
| timeRange | String | 是 | 时间范围：`0`=天，`1`=周，`2`=月，`3`=年 |
| enbCodeList | String | 是 | JSON 数组，每项含 `smallCellCode` 字段 |
| kpiIdList | String | 是 | 逗号分隔的指标 ID 列表 |
| enbLimitNum | String | 是 | 最大设备数量 |
| kpiLimitNum | String | 是 | 最大指标数量 |

**返回值：**

```json
[
  {
    "uniqueId": "smallCellCode-plmnId",
    "smallCellCode": "基站编码",
    "serialNumber": "序列号",
    "hostName": "主机名",
    "startTime": "开始时间（用户时区）",
    "endTime": "结束时间（用户时区）",
    "K900010006": "指标值",
    "...": "其他指标字段"
  }
]
```

**完整处理流程：**

```
1. 解析请求参数
   解析 enbCodeList（JSON → 基站编码列表）
   ↓
2. 查询模板信息
   获取 statis_period、indicator_level
   ↓
3. 确定查询粒度
   timeRange = 0：使用模板原始粒度
   timeRange ≠ 0：强制使用 1440（天粒度）
   ↓
4. 计算图表时间范围
   根据 timeRange 计算本地起止时间，转为 UTC
   ↓
5. 构建时间槽位映射
   从 startTime 到 maxStartTime，按粒度生成所有时间槽
   ↓
6. 查询 MongoDB 数据
   根据指标级别选择分表列表（与表格查询相同的分表规则）
   PLMN 级模板区分 BSC/非 BSC 两路查询
   ↓
7. 按设备分组
   以 bts_id + "-" + plmnId 为分组键整理数据
   ↓
8. 填充时间缺口
   对缺失的时间槽补充空数据（指标值为 "-"）
   ↓
9. 计算 uniqueId、时区转换
   生成最终结果列表
```

**步骤 4 时间范围计算：**

| timeRange | startTime 输入格式 | 计算方式 |
|-----------|-------------------|---------|
| 0（天） | `yyyy-MM-dd` | endTime = startTime + 1 天 |
| 1（周） | `yyyy-MM-dd` | endTime = startTime + 7 天 |
| 2（月） | `yyyy-MM-dd` | 补充 "-01"，endTime = startTime + 1 个月 |
| 3（年） | `yyyy-MM-dd` | 补充 "-01-01"，endTime = startTime + 1 年 |

计算出的本地时间均转为 UTC 后用于 MongoDB 查询。

### 5.2 GNB 图表查询

**接口地址：** `POST /gnb/pm/template/getChartDataList`

> 注：该接口由 OMCWebServer 本地处理。

**请求参数：**

与 ENB 基本一致，`enbCodeList` 的每项含 `smallCellCode` 和 `cellId` 字段。

**返回值：**

与 ENB 结构一致，`uniqueId` = `smallCellCode-nrCGI`。

**完整处理流程：**

```
1. 解析请求参数
   解析 enbCodeList（JSON → 基站编码+nrCGI 列表）
   ↓
2. 查询模板信息
   获取 statis_period、selDeviceType
   ↓
3. 确定查询粒度（同 ENB）
   ↓
4. 计算图表时间范围（同 ENB）
   ↓
5. 构建 MongoDB 过滤条件
   以 small_cell_code + nrCGI 对构建 $or 条件
   ↓
6. 查询 GNB 固定表
   ↓
7. 按设备分组
   以 smallCellCode 为键，值为时间→数据列表映射
   ↓
8. 填充时间缺口
   对缺失的时间槽补充空数据
   ↓
9. 计算 uniqueId、时区转换
```

**步骤 5 GNB 设备过滤差异：**

GNB 的 `enbCodeList` 中每个条目包含 `smallCellCode` 和 `cellId`（即 nrCGI）。构建 MongoDB 查询条件为 `$or` 列表，每个条目对应一组 `{small_cell_code: code, nrCGI: cellId}` 条件，精确匹配到小区级别。

### 5.3 ENB/GSM 与 GNB 图表查询差异

| 维度 | ENB/GSM | GNB |
|------|---------|-----|
| 处理方式 | RPC 转发至 OMCParseKpiFile | OMCWebServer 本地处理 |
| 模板表 | `perf_template` | `gnb_perf_template` |
| 数据表选择 | 按指标级别区分设备表/PLMN 表，15min/小时用分表 | 单一固定表 |
| BSC 混合处理 | PLMN 级模板需区分 BSC/非 BSC 两路查询 | 不涉及 |
| 设备过滤 | 仅按 `smallCellCode` 过滤 | 按 `smallCellCode` + `nrCGI` 精确匹配 |
| 分组键 | `bts_id + "-" + plmnId` | `smallCellCode`（含 nrCGI 子列表） |
| uniqueId | 见 5.4 节 | 见 5.4 节 |

### 5.4 uniqueId 计算规则

图表结果中的 `uniqueId` 用于标识一条独立的曲线，按以下规则计算：

**ENB/GSM：**

| 条件 | uniqueId |
|------|----------|
| 数据有 `bts_id` | `smallCellCode + "-" + btsId` |
| 数据无 `bts_id` 但有 `plmnId` | `smallCellCode + "-" + plmnId` |
| 以上均无 | `smallCellCode` |

特殊场景：当数据记录本身无 `plmnId` 和 `bts_id`，但查询条件（`enbCodeList`）中包含这些字段时，会为每个查询条件复制一份数据，分别设置不同的 `uniqueId`。

**GNB：**

| 条件 | uniqueId |
|------|----------|
| 数据有 `nrCGI` 且非空 | `smallCellCode + "-" + nrCGI` |
| 无 nrCGI | `smallCellCode` |

### 5.5 时间缺口填充逻辑

图表要求在时间轴上连续展示，因此需要对缺失的时间点进行填充。

**填充步骤：**

1. **构建时间槽映射**：根据查询的起止时间和粒度，生成所有时间点，每个时间点对应一个 `[startTime, endTime]` 区间
2. **匹配实际数据**：将 MongoDB 查询到的实际数据按时间点和设备标识分配到对应的时间槽中
3. **填充缺失槽位**：遍历所有时间槽，对于某个设备标识在该时间槽中无数据的：
   - 复制一条基础信息（`smallCellCode`、`serialNumber`、`hostName` 等）
   - 所有指标值设为 `"-"`（表示无数据）
4. **时区转换**：将所有时间槽的 UTC 时间转为运营商本地时间
5. **设置 uniqueId**：按 5.4 节规则为每条数据计算 `uniqueId`

**GNB 特殊处理：** 由于 GNB 一个基站可能有多个小区（不同的 nrCGI），每个时间槽内可能包含多条数据，填充时按小区维度独立填充。

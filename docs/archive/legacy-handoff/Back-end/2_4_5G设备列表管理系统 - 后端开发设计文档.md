# 2/4/5G设备列表管理系统 - 后端开发设计文档（更新版）

## 1. 文档概述

### 1.1 文档目的

本文档明确2/4/5G共用设备列表管理系统的后端开发规范、数据模型设计、接口定义、业务逻辑规则及非功能需求，作为后端开发、测试、运维人员的核心参考依据，保障系统功能落地的规范性和可维护性。

### 1.2 核心目标

- 支撑2/4/5G设备的统一列表管理，满足多网元设备数据的整合展示与操作；
- 实现灵活的查询、列自定义、设备操作及数据导出能力；
- 保障接口的高性能、高可用性，适配设备数据量增长的业务场景。

### 1.3 范围界定

本文档聚焦后端开发层面，涵盖设备列表的**数据存储、接口设计、业务逻辑、权限控制（基础）、性能优化**，前端交互细节不在本文档范围内。

## 2. 数据模型设计

### 2.1 核心数据表

#### 2.1.1 设备基础信息表（device_info）

|字段名|数据类型|字段说明|约束/备注|
|---|---|---|---|
|id|BIGINT|主键ID|自增，非空|
|sn|VARCHAR(64)|设备序列号|唯一索引（uk_sn），非空，设备唯一标识|
|connect_status|VARCHAR(32)|连接状态|枚举：在线/离线/异常/未激活/维护中；非空；单字段索引（idx_connect_status）|
|oui|VARCHAR(64)|组织唯一标识符|非空，关联设备厂商OUI编码库|

|product_type|VARCHAR(32)|产品类型|枚举：2G/4G/5G/融合型；非空；单字段索引（idx_product_type）；精准查询维度|
|model_name|VARCHAR(64)|设备型号|非空，如“BTS3900”“AAU5613”|

|eci|VARCHAR(64)|ECI标识|非空，演进型小区标识，5G设备核心属性|
|pci|VARCHAR(64)|PCI值|非空，物理小区标识，用于区分同频小区|
|cell_id|VARCHAR(64)|小区ID|非空，小区唯一标识|
|freq_point|VARCHAR(32)|频点|非空，单位：MHz，如5G n78频段（3500MHz）|
|bandwidth|DECIMAL(8,2)|带宽|非空，单位：MHz；保留2位小数|

|rf_status|VARCHAR(32)|射频状态|枚举：开启/关闭/异常；非空；单字段索引（idx_rf_status）；精准查询维度|
|cell_status|VARCHAR(32)|小区状态|枚举：正常/故障/未配置/退服；非空；单字段索引（idx_cell_status）；精准查询|
|mme_status|VARCHAR(32)|MME状态|枚举：正常/异常/未连接；4G核心网关联属性|
|sync_status|VARCHAR(32)|同步状态|枚举：GPS同步/北斗同步/NTP同步/异常；非空；含同步源+同步状态描述|
|plmn|VARCHAR(32)|PLMN编码|非空，公共陆地移动网络编码（如46000）|
|mac|VARCHAR(64)|MAC地址|非空，设备网卡物理地址，敏感字段需加密存储|
|software_version|VARCHAR(64)|软件版本|非空；模糊查询；组合索引（idx_search_fuzzy）成员|

|kpi_status|VARCHAR(32)|KPI状态|枚举：正常/异常/无数据；非空|

|first_online_time|DATETIME|第一次上线时间|可空，设备首次接入平台时间|
|last_online_time|DATETIME|最近上线时间|可空，设备最近一次接入平台时间|
|last_offline_time|DATETIME|最后下线时间|可空，设备最近一次断开连接时间|
|heartbeat_time|DATETIME|最后心跳时间|非空；时间索引（idx_heartbeat_time）；设备存活状态判断依据|
|longitude|DECIMAL(10,6)|经度|可空，地理坐标，保留6位小数，敏感字段|
|latitude|DECIMAL(10,6)|纬度|可空，地理坐标，保留6位小数，敏感字段|
|height|DECIMAL(10,2)|高度|可空，单位：米，保留2位小数|
|project_status|VARCHAR(32)|工程状态|枚举：在建/已交付/运维中/停用；非空|
|device_group|VARCHAR(64)|设备组|可空，设备组ID；模糊查询；组合索引（idx_search_fuzzy）成员|
|address|VARCHAR(256)|设备物理地址|可空，详细部署地址（如XX市XX区XX基站）|
|site|VARCHAR(64)|所属站点|可空，站点ID，关联站点管理表|
|remark|VARCHAR(512)|备注信息|可空，设备运维备注、特殊说明等|
|network_type|VARCHAR(8)|网络类型|枚举：2G/4G/5G；非空；单字段索引（idx_network_type）；核心区分维度|
|create_time|DATETIME|创建时间|非空，默认当前时间|
|update_time|DATETIME|更新时间|非空，自动更新|

|updater|VARCHAR(64)|更新人|非空，更新人用户ID，关联用户表|
|is_delete|TINYINT(1)|逻辑删除标识|非空，枚举：0（未删除）/1（已删除）；默认0；优化删除性能|
|ext_json|TEXT|扩展字段JSON|可空，存储个性化/新增属性（如5G NR版本、4G LTE版本），适配可扩展性需求|

#### 2.1.2 扩展表（关联详情模块）

- 设备告警表（device_alarm）：存储设备告警信息，关联sn字段；
- 设备KPI数据表（device_kpi）：存储设备KPI指标数据，按时间维度归档；
- 设备License表（device_license）：存储设备License授权信息，关联sn字段；
- 设备参数配置表（device_param）：存储设备可配置参数，支持参数的增改查。

### 2.2 索引设计

为保障查询性能，针对核心查询维度建立以下索引：

1. 唯一索引：uk_sn（sn）- 设备唯一标识，加速单设备查询；
2. 组合索引：idx_search_fuzzy（name, sn, ip, device_group, software_version）- 优化模糊查询；
3. 单字段索引：idx_manufacturer（manufacturer）、idx_product_type（product_type）、idx_network_type（network_type）、idx_connect_status（connect_status）、idx_rf_status（rf_status）、idx_cell_status（cell_status）- 优化精准查询；
4. 时间索引：idx_heartbeat_time（heartbeat_time）- 优化设备在线状态筛选。

## 3. 接口设计

### 3.1 接口规范

- 遵循RESTful设计风格，请求方式与语义匹配（GET查询、PUT更新、POST操作、DELETE删除）；
- 接口前缀：/api/v1/device；
- 统一返回格式：
    ```JSON
    {
      "code": 200, // 状态码，200成功/4xx客户端错误/5xx服务端错误
      "msg": "操作成功", // 提示信息
      "data": {} // 业务数据，按需返回
    }
    ```
- 分页参数统一：pageNum（页码，默认1）、pageSize（页大小，默认10）。

### 3.2 核心接口定义

#### 3.2.1 设备列表查询接口

- 接口路径：/list
- 请求方式：GET
- 请求参数：

|参数名|类型|说明|是否必传|
|---|---|---|---|
|pageNum|INT|页码|否|
|pageSize|INT|页大小|否|
|keyword|STRING|模糊查询关键词（匹配名称/SN/IP/设备组/软件版本）|否|
|manufacturer|STRING|制造商（精准匹配）|否|
|productType|STRING|产品类型（精准匹配）|否|
|networkType|STRING|网络类型（2G/4G/5G，精准匹配）|否|
|connectStatus|STRING|连接状态（精准匹配）|否|
|cellStatus|STRING|小区状态（精准匹配）|否|
|rfStatus|STRING|射频状态（精准匹配）|否|

- 返回数据：分页结果（total：总条数，list：设备列表数据）。

#### 3.2.2 设备列配置接口

- 接口路径：/column/config
- 请求方式：POST
- 请求参数：

|参数名|类型|说明|是否必传|
|---|---|---|---|
|userId|STRING|用户ID（关联用户自定义列配置）|是|
|showColumns|LIST<STRING>|显示列字段名列表（如["sn","name","ip"]）|是|

- 接口说明：存储用户自定义的列显示配置，支持用户个性化展示设备列表字段。

#### 3.2.3 设备详情查询接口

- 接口路径：/detail/{sn}
- 请求方式：GET
- 路径参数：sn（设备序列号）
- 返回数据：包含设备基础信息、告警摘要、KPI数据快照、License信息、参数配置列表等聚合数据。

#### 3.2.4 设备操作接口

|操作类型|接口路径|请求方式|核心参数|接口说明|
|---|---|---|---|---|
|激活/去激活|/operate/active/{sn}|PUT|active（布尔值：true/false）|变更设备激活状态|
|重启|/operate/restart/{sn}|POST|-|触发设备重启，异步返回结果|
|日志收集|/operate/log/{sn}|POST|logType、startTime、endTime|指定时间段收集设备日志|
|同步参数|/operate/sync-params/{sn}|POST|-|同步设备最新参数至平台|
|射频开关|/operate/rf-switch/{sn}|PUT|status（布尔值：true/false）|开启/关闭设备射频功能|
|报文收集|/operate/packet/{sn}|POST|collectTime（收集时长）|指定时长收集设备报文数据|

#### 3.2.5 设备参数配置接口

- 接口路径：/param/config/{sn}
- 请求方式：PUT
- 请求参数：params（JSON对象，包含需配置的参数键值对）
- 接口说明：校验参数合法性后，下发配置至设备并更新数据库。

#### 3.2.6 数据导出接口

|导出类型|接口路径|请求方式|核心参数|接口说明|
|---|---|---|---|---|
|全量导出|/export/all|GET|exportType（csv/excel）|导出所有设备数据|
|条件导出|/export/condition|POST|exportType + 列表查询参数|导出符合查询条件的设备数据|

- 返回数据：文件流（前端直接触发下载）。

### 3.3 枚举值查询接口

- 接口路径：/enums
- 请求方式：GET
- 返回数据：包含制造商、产品类型、网络类型、各状态类等枚举值列表，用于前端下拉选单渲染。

## 4. 核心业务逻辑

### 4.1 多网共用逻辑

- 通过`network_type`字段区分2G/4G/5G设备，所有接口默认支持按该字段筛选；
- 设备列表查询时，若未指定网络类型，默认返回全类型设备，保障2/4/5G设备统一展示；
- 设备操作逻辑与网络类型解耦，通用操作（如重启、日志收集）适配所有网络类型设备，差异化操作通过产品类型/厂商维度区分。

### 4.2 查询逻辑

#### 4.2.1 模糊查询

- 对`name、sn、ip、device_group、software_version`字段进行拼接，通过模糊匹配实现关键词检索；
- 优化：对高频查询的模糊关键词做缓存，减少数据库查询压力。

#### 4.2.2 精准查询

- 所有精准查询字段均匹配枚举值，前端仅展示后端返回的枚举选项，避免非法参数；
- 多条件精准查询为“且”逻辑，需同时满足所有选中条件。

### 4.3 列自定义逻辑

- 按用户维度存储列配置，优先读取用户自定义配置，无配置时使用系统默认列；
- 列配置存储字段名，前端根据字段名映射显示名称，保障前后端字段一致性。

### 4.4 导出逻辑

- 全量导出：分页读取全量设备数据，避免一次性加载导致内存溢出；
- 条件导出：先执行查询条件筛选数据，再导出结果集；
- 格式支持：CSV格式采用字符流写入，EXCEL格式采用分片写入（适配大数据量）；
- 异步处理：大文件导出（数据量>1万条）采用异步任务，返回任务ID，前端轮询获取导出状态，完成后下载文件。

### 4.5 设备操作逻辑

- 所有设备操作均需校验设备SN合法性，不存在则返回错误；
- 耗时操作（如重启、日志收集、报文收集）采用异步线程池处理，避免接口超时；
- 操作结果需记录日志（操作人、操作时间、操作类型、设备SN、结果），便于追溯；
- 新增字段相关操作适配：如频点、带宽、发射功率等字段的修改需同步校验数据格式（如数值范围、单位合法性），ext_json字段支持自定义键值对的增删改查。

## 5. 非功能需求

### 5.1 性能要求

- 列表查询接口响应时间≤500ms（数据量≤10万条）；
- 单设备操作接口响应时间≤1s（同步操作），异步操作任务提交≤500ms；
- 导出接口支持单次导出≤10万条数据，无内存溢出；
- 新增字段（如ext_json）的查询/更新操作需保障性能，避免大字段拖慢整体查询效率。

### 5.2 可靠性要求

- 设备操作接口需做幂等性设计，避免重复操作；
- 数据库操作需加事务控制，关键操作（如参数配置、新增字段数据写入）保障数据一致性；
- 接口异常需有兜底逻辑，如设备离线时操作失败，返回明确的提示信息；
- 逻辑删除字段（is_delete）操作需保障数据溯源，删除操作仅标记状态，不物理删除。

### 5.3 安全性要求

- 所有接口需做权限校验，仅授权用户可执行设备操作；
- 设备SN、IP、MAC、经纬度等敏感信息传输需加密；
- 操作日志需完整记录，支持审计追溯；
- 敏感字段（mac、longitude、latitude）存储时需加密，查询返回时按需解密。

### 5.4 可扩展性要求

- ext_json扩展字段支持新增设备属性的快速接入，无需大规模修改表结构；
- 接口设计预留版本号（/v1/），便于后续接口迭代；
- 设备操作逻辑抽象为接口，新增操作类型时可快速扩展；
- 新增字段（如freq_point、bandwidth等）的校验规则支持配置化，便于适配不同厂商设备的参数差异。

## 6. 版本规划

### V1版本（核心功能）

- 完成设备列表查询（模糊+精准）、列自定义、基础设备操作（详情、激活/去激活、重启）、全量/条件导出（CSV/EXCEL）；
- 实现设备详情基础信息展示（含新增的频点、带宽、发射功率等字段）、简单参数配置；
- 支持逻辑删除、扩展字段（ext_json）的基础读写能力。

### V2版本（功能扩展）

- 新增字段排序功能（支持所有可排序字段的升序/降序，含新增的数值型字段如bandwidth、transmit_power）；
- 完善详情模块：告警、KPI数据、License信息的完整展示；
- 优化导出性能，支持更大数据量导出；
- 新增设备操作的批量处理能力；
- 完善ext_json扩展字段的检索、筛选能力。

## 7. 总结

### 核心设计要点

1. 数据模型层面：
   - 补全频点、带宽、发射功率等核心业务字段，完善字段约束与索引设计；
   - 新增逻辑删除（is_delete）和扩展字段（ext_json），兼顾数据溯源与可扩展性；
   - 通过`network_type`字段实现2/4/5G设备统一管理，针对查询维度建立专属索引保障性能。
2. 接口层面：
   - 遵循RESTful规范，区分查询/操作/导出类接口，统一返回格式，适配前端灵活的交互需求；
   - 新增字段相关的参数校验逻辑，保障数据合法性。
3. 业务逻辑层面：
   - 模糊查询拼接多字段、精准查询匹配枚举值、导出逻辑异步分片处理，兼顾功能与性能；
   - 敏感字段（MAC、经纬度）的加密存储与传输，保障数据安全。

### 关键约束

1. 所有设备操作需做权限校验和幂等性设计，保障操作安全；
2. 大数据量导出需采用异步+分片方式，避免内存溢出；
3. 多网设备逻辑解耦，通用操作适配全类型设备，差异化操作通过维度筛选区分；
4. 扩展字段（ext_json）的使用需规范键名，避免数据混乱；
5. 敏感字段的加密/解密需统一算法，保障数据一致性。

### 4.3 已识别的差异与注意事项

#### 1. 命名规范转换

系统自动进行 camelCase ↔ snake_case 转换：

**转换层:** `/src/services/http.ts` (HTTP拦截器)

- 请求: 前端代码使用 camelCase → HTTP库转换为 snake_case → 后端接收
- 响应: 后端返回 snake_case → HTTP库转换为 camelCase → 前端使用

**示例:**
```
前端: { pageSize: 20 }
后端: { page_size: 20 }
```

#### 2. 状态映射

**连接状态映射** (deviceApi.ts 第131-147行):

```typescript
function mapStatus(status: string): Device['connStatus'] {
  switch (status) {
    case 'online':
    case 'active':
      return 'online';
    case 'offline':
    case 'registered':
    case 'discovered':
    case 'provisioning':
    case 'maintenance':
    case 'decommissioned':
    default:
      return 'offline';
  }
}
```

**告警级别:** 前端本地设置为 'none'（未来由告警模块填充）

#### 3. 分组层级约束

数据库层面强制约束 (migrations/000065_enhance_device_groups.up.sql):

```sql
-- 层级约束：只允许 1 和 2
ALTER TABLE device_groups
    ADD CONSTRAINT chk_dg_level CHECK (level IN (1, 2));

-- 层级与父子关系一致性：一级无父，二级必有父
ALTER TABLE device_groups
    ADD CONSTRAINT chk_dg_level_parent
    CHECK ((level = 1 AND parent_id IS NULL) OR (level = 2 AND parent_id IS NOT NULL));

-- 同一父节点下名称唯一
CREATE UNIQUE INDEX idx_dg_name_parent
    ON device_groups (name, COALESCE(parent_id, '00000000-0000-0000-0000-000000000000'::uuid));

-- 设备只能归属一个组（新增唯一约束）
ALTER TABLE device_group_members
    ADD CONSTRAINT uq_dgm_device UNIQUE (device_id);
```

### 5.3 设备生命周期

```
设备注册流程:
1. 预注册 (device_registrations)
   ├─ 检查SN唯一性
   ├─ 保存注册信息
   └─ 分配默认分组(optional)

2. 首次INFORM
   ├─ devices表中创建记录 (status='discovered')
   ├─ 提取参数到device_parameters表
   └─ 自动分配到预注册分组或默认分组

3. 完成配置 (provisioning)
   ├─ status变为'active'
   └─ 设备就绪

4. 分组管理
   ├─ 添加到指定分组 (device_group_members)
   ├─ 可移动到其他分组
   └─ 删除分组时自动回归到"未分组设备"
```

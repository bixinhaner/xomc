- **失败**：页面无数据、PromQL 返回空序列，或返回值的统计对象与功能定义不一致。属于必须修复的实现/部署问题。

- **共享修复**：同一根因影响多个编号时，每个编号仍单独列出，修复实施时只建立一个代码变更和一组回归测试，避免重复修改。

### F-07（清单 34）容器 CPU 使用 vs 限额

- **修复前现象**：面板的 usage/limit 两条查询没有锁定同一容器粒度；在单容器现场虽可能显示 6/10 核，但多容器或无限额容器会使限额被错误稀释，不能证明 CPU 使用与配置限额正确对齐。
- **期望**：同时展示 CPU 实际用量和配置限额。
- **证据/根因**：usage 查询按 `service` 聚合，但旧限额查询先分别 `sum(quota)`、`sum(period)` 再相除，未按容器配对；`quota <= 0` 的无限额容器仍可能贡献 period，造成限额口径错误。
- **修复**：usage 保持 `sum by (service) (rate(...))`；限额改为 `sum by (service) ((quota > 0) / period)`，在容器粒度先完成 quota/period 配对并排除无限额容器；不使用 `or` 掩盖任一侧缺失。
- **代码范围**：`deployments/monitoring/grafana/dashboards/omc-resources.json`。

## 1. 验收目标

本方案用于判断新 OMC 是否完整覆盖老项目的基站接入控制核心业务，并验证重构后的可靠性、安全性和可审计性。验收不以“页面有按钮”“接口返回200”或“数据库有一条记录”为通过标准，必须验证：

```text
策略/名单配置
→ 真实触发
→ 身份与证据采集
→ 接入决定
→ 普通任务门禁
→ 设备RF动作及回读
→ 事件与通知状态
→ 审计查询
→ 修复/回滚/重新评估
```

每个阶段分别留证，不能用后续结果倒推前序阶段已经成功。

## 2. 验收范围

### 2.1 必须覆盖

- `AC-01～AC-52` 全部能力；
- 老项目黑名单、白名单、规则、接入状态及批量治理操作；
- 总开关、身份、特殊平台、优先级、默认动作和系统异常策略；
- SN、TAC、ECGI、IP、GPS 正反例和缺失/读取失败分支；
- 首次 Inform、BOOT、断链重连、上线恢复、名单/策略/候选/身份变更和手工重评；
- 决定、任务门禁、RF隔离/恢复、自动重试、死信和人工修复；
- 位置/电子围栏不能越过接入状态重新激活设备；
- 事件、通知失败隔离、运营商/设备组/RBAC、审计和原始SOAP；
- 老数据迁移预演与新旧判定双算。

### 2.2 明确排除

- `AC-53`：老项目独立 EGW/ECI 接入控制；
- 邮件、短信供应商通道本身；但事件、通知状态和失败隔离必须验收；
- 复杂多级审批和高级策略编排；
- 与基站接入控制无关的普通设备管理功能。

## 3. 验收结论分级

| 等级 | 条件 | 可使用口径 |
|---|---|---|
| A：完整通过 | AC-01～AC-52全部通过，无P0/P1缺陷 | 完整覆盖老项目接入控制核心能力 |
| B：核心闭环通过 | 判定、门禁、RF、安全恢复通过，但存在批量治理/审计等缺口 | 核心判定闭环通过，不能称全量覆盖 |
| C：条件通过 | 无安全放行错误，但存在可规避可靠性缺陷 | 仅限灰度，不得正式放行 |
| D：不通过 | 错误放行、越权、重复RF动作、无法恢复或证据缺失 | 不得发布 |

以下任一情况直接判为 D：

- 黑名单设备被接受；
- 黑名单设备继续进入普通规则求值，或未触发小区去激活；
- 白名单设备继续进入普通规则求值，或被普通规则阻止激活；
- 跨运营商查询或修改成功；
- 拒绝/吊销设备被普通任务、位置或围栏重新激活；
- 重复/并发 Inform 产生重复RF动作；
- 页面显示动作成功但设备回读不一致；
- 通知失败导致拒绝动作未执行或决定被改变；
- 覆盖导入只生效一部分且无法回滚；
- 缺少决定、动作或关键操作审计，无法说明设备为何被处置。

## 4. 环境与安全前置条件

### 4.1 环境

- 目标环境：104；
- 老系统对照：80/189，仅在用户明确授权的设备和网段内操作；
- 104部署版本、Git提交、镜像摘要、Schema版本和配置摘要已记录；
- App、ACS、Worker、Web、PostgreSQL、Redis、NATS和任务服务健康；
- 各运营商接入开关、默认动作、失败模式和动作重试开关已记录原值。

### 4.2 测试设备

至少准备：

1. 一台允许执行 RF 隔离/恢复的已登记设备；
2. 一台用于白名单、黑名单、吊销和默认拒绝切换的设备；
3. 一台未知或可清理预登记关系的候选设备；
4. 一台可模拟离线、超时、Fault和错误回读的 CWMP 模拟器或专用设备。

所有真实设备必须记录 SN、运营商、型号、IP、原始RF路径和值、当前任务和恢复方式。不得操作未在授权清单中的设备；189仅使用事先确认的允许网段。

### 4.3 账号

- 管理员：完整策略、名单、动作修复权限；
- 运营商管理员：仅本运营商完整权限；
- 操作员：只允许部分变更；
- 查看者：只读；
- 不同运营商账号：用于隔离验证。

### 4.4 证据

测试前开启受控 TR069 跟踪，统一记录：

- `request_id/decision_id/action_id/device_task_id/event_id/import_batch_id`；
- 原始 Inform、GPV、SPV、Fault和回读SOAP；
- API请求/响应和服务端请求ID；
- 决定、检查、证据、动作、尝试、Outbox和通知数据库记录；
- 页面截图和设备最终物理状态；
- 操作人、时间、策略版本、名单批次和清理结果。

敏感凭据不得进入报告；SOAP中的认证信息必须脱敏。

## 5. 入场门禁

执行真实设备验收前必须全部满足：

- 后端定向、race、集成和全量测试通过；
- 前端 lint、typecheck、unit test和build通过；
- 空库安装和Schema重复reconcile通过；
- AC需求总账已冻结；
- 导入模板和错误码文档已评审；
- 测试设备、账号、回滚路径和跟踪容量已确认；
- 自动重试、批量治理和通知事件均有独立开关；
- 不存在会影响验收的未清理策略草稿、测试名单或待执行RF动作。

## 7. 非功能验收

### 7.1 容量和时延

- 10,000行名单preview和commit不超配置时限，不造成App长时间阻塞；
- 策略发布的大范围重评分页执行，不能在单HTTP请求内展开全量设备；
- 状态查询和汇总在目标数据规模下走预期索引；
- Worker重启后Outbox、重评和动作积压持续收敛；
- 自动重试有全局和运营商并发上限，不能压垮ACS。

### 7.2 稳定性

- App、ACS、Worker任一实例滚动重启不丢决定和动作；
- Redis不可用时安全状态不被放宽；
- NATS短时不可用时Outbox可恢复；
- PostgreSQL事务失败不产生半批名单或无决定动作。

### 7.3 安全

- 文件名、表头、SN、IP、GPS、排序和过滤字段严格校验；
- 导入文件不可触发公式注入或超大压缩包资源耗尽；
- 导出CSV对公式前缀做安全处理；
- 所有变更按运营商、设备组和权限限制；
- 白名单、覆盖导入、回滚、人工修复均二次确认并审计。

## 9. 清理与回退

验收完成或中途停止时：

1. 停止新的故障注入和自动重试；
2. 恢复各运营商接入开关、默认动作和失败模式；
3. 停用或回滚所有测试名单批次；
4. 发布验收前策略内容的新版本，保留审计；
5. 清理待审核候选和未完成测试草稿；
6. 等待决定、Outbox、动作和通知队列收敛；
7. 按测试前记录恢复设备RF，只恢复验收实际拥有的变更；
8. 对每台设备执行GPV回读并核对在线/激活状态；
9. 关闭额外TR069跟踪并保存证据；
10. 输出最终差异清单，任何未恢复项必须显著标红。

不得通过删除决定、动作或审计记录伪造清理完成。

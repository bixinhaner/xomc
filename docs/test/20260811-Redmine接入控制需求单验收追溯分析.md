# Redmine 接入控制需求单验收追溯分析

## 1. 最终业务口径

Redmine #31672、#51449、#45094、#31732、#31675、#21156、#21155 共同描述一条接入控制业务链。客户后续确认覆盖早期“只拒绝接入”的描述：不满足条件的基站由 OMC 主动去激活；黑名单设备接入后立即去激活；白名单设备默认接入并跳过普通 TAC、ECGI、IP、GPS 规则。

```text
页面开启业务总开关
  -> 基站 Inform
  -> 黑白名单与规则判定
  -> accepted：允许普通任务和后续业务
  -> rejected：OMC 自动 RF_OFF
  -> SPV 设备回执
  -> GPV 回读确认
```

老 OMC 核心流程没有双账号审批、维护窗口、observe/enforce 部署模式或三进程动作开关，这些均不是本需求验收条件。

## 2. 需求追溯矩阵

| #51449 | 状态和名单显示基站名称；删除时防误操作 | 状态/名单/动作显示设备名称，停用和删除确认 | 页面、API、操作前后名单记录 |

## 3. 判定规则

- 黑名单优先于白名单，命中后立即拒绝并自动去激活；
- 白名单默认接入并跳过普通 TAC、ECGI、IP、GPS 规则，但不跳过基础身份和归属校验；
- 单条规则内启用的条件为 AND，多条适用规则之间为 OR；
- SN 条件为空表示不按 SN 限定；
- 多小区 TAC、ECGI 按实际小区证据求值；
- 无已发布策略、无适用规则或没有规则命中时拒绝；
- GPS 空值是否允许由策略明确配置。

## 4. 动作与恢复

- 拒绝决定自动创建幂等 RF_OFF 动作；
- 动作成功必须同时具备设备 SPV 回执和 GPV 回读；
- 页面显示 rejected 不能证明设备已经去激活；
- 设备恢复接入后，仅恢复由接入控制成功关闭的 RF；
- 人工或其他业务关闭的 RF 不得自动打开；
- 下发失败、超时或无回执时，动作保持 failed/pending_retry 并保存原因和重试次数。

## 5. 放行条件

完整验收至少证明：

1. 页面唯一业务总开关即时生效，无需修改部署配置；
2. 黑名单、白名单、普通规则优先级正确；
3. SN、IP、ProductClass、TAC、ECGI、GPS 和多小区证据可追溯；
4. 拒绝后真实 RF_OFF 完成 SPV、GPV 闭环；
5. 恢复接入后 RF 回到操作前状态且不越权恢复；
6. 普通任务创建和出队双重保护有效；
7. 基站名称、删除提示、候选审核、动作状态、运营商隔离、RBAC 和 i18n 正确。

真实 RF 关闭、设备回执、GPV 回读和恢复任一未执行，只能标记“阻塞/未执行”，不能宣称完整验收通过。

## DA104-DB-001：数据库基线未对齐

### 现场现象

- `GET /api/v1/device-access/policies?page=1&page_size=20` 返回 500；
- 导入历史接口返回 500；
- 接入名单接口仍返回 200；
- 后台动作恢复查询报 `device_access_actions.candidate_id` 不存在。

### 根因

104 已运行新接口和新动作查询，但运行数据库没有使用同版本迁移制品执行主库基线重放。MR !670 已在 `000001_init_schema.sql` 中折回新增结构，并由 `omcgo-migrate` 的 `MainReconcile` 机制为已记录版本 1 的存量库幂等补齐；本次不是新增业务代码缺失。

### 修复与验证

2026-08-20 使用 MR !670 当前分支的迁移程序对 104 主库执行：

```text
goose: no migrations to run. current version: 1
Migration complete. Version: 1
```

迁移程序在 Goose 检查前已执行存量基线重放。随后只读验证：

```text
candidate_id=true import_batches=true failure_mode=true
policies_query=ok rows=1
imports_query=ok rows=0
```

结论：导致 500 的缺表/缺列已补齐；重新部署同版本 App/Worker 后复测实际 HTTP 状态码和响应体。

## DA104-UI-001：中英文资源混装

### 现场现象

104 的 AccessControl 页面 chunk 已引用 `deviceAccess.downloadTemplate`、`deviceAccess.importHistory`、`deviceAccess.summary.*` 等新 key，但主 bundle 中缺少对应中英文消息，控制台报告 `MISSING_TRANSLATION`。

### 根因

Web 未以 MR !670 的同一源码状态进行完整生产构建，导致新页面 chunk 与旧 i18n 主 bundle 混装。MR !670 当前源码中的 `zh-CN`、`en-US` 均已包含相关消息。

### 本地验证

- `npm run build` 通过；
- 生产 bundle `index-DV6HYkHv.js` 同时包含：
  - `下载名单模板` / `Download List Template`；
  - `导入历史` / `Import History`；
  - `加入黑名单` / `Add to Denylist`。

### 部署要求

必须从 MR !670 当前提交一次性构建并部署 App、Worker、ACS、Web 和 migrate 制品，不复用旧 Web 静态目录；部署后强制重建 Web 容器并确认服务端 `index.html` 引用的新主 bundle 与 AccessControl chunk 来自同一次构建。

## 复测门槛

1. `policies`、`imports`、`access-list` 均返回 200；
2. 策略列表至少可读取现有 1 条记录，空导入历史返回空列表而不是 500；
3. 接入控制五个页签在中文、英文下均无裸露 `deviceAccess.*`；
4. 浏览器控制台无 `MISSING_TRANSLATION`；
5. App/Worker 日志不再出现接入控制缺表、缺列错误。

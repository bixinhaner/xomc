# OMC 前后端整合 — 开发实施计划

## Context

OMC 项目前端 (omcmb: React 19 + Ant Design + TypeScript) 拥有 94 个路由页面、18 个 mock 服务模块，所有 API 调用均为本地 mock 数据。后端 (omcgo: Go + Gin) 提供 82 个 REST API 端点，覆盖 10 个功能域，但未配置 CORS，前后端从未对接。

本计划基于《前后端整合方案.md》，将整合工作拆分为**前端、后端、对接**三条并行开发轨道，按周 Sprint 迭代推进。

### 3.3 数据格式差异处理

| 差异 | 处理方案 | 处理位置 |
|------|---------|---------|
| 分页 `pageSize` vs `page_size` | 拦截器 camelCase → snake_case | `src/services/http.ts` |
| 错误格式不统一 | 拦截器兼容两种格式 | `src/services/http.ts` |
| severity 数字 vs 字符串 | API 层映射 | `src/services/api/alarmApi.ts` |
| 运营商编码 | API 层映射 (中文→cmcc/ctcc/cucc) | 各 `*Api.ts` |
| ID 格式 (UUID) | 前端统一用 string 接收 | 无需处理 |
| 时间格式 | ISO 8601 ≈ RFC3339, 基本兼容 | 无需处理 |

### 3.4 关键阻塞依赖链

```
路径1 (认证, Week 1-2):
  BE-0.1(CORS) → FE-0.3(Proxy) → M0联调 → BE-1.1(/auth/me) → FE-1.1(authApi) → FE-1.2(login) → M1联调

路径2 (Dashboard, Week 5, 最晚阻塞):
  BE-4.1(Dashboard API) → FE-4.6(Dashboard 对接)

路径3 (设备 CRUD, Week 5):
  BE-4.2(POST/PUT/DELETE) → FE-4.7(设备 CRUD 对接)
```

**非阻塞并行:**
- 前端 Sprint 1~3 的 API 层编码可先用 mock 模式开发, 后端就绪后切换
- 前端 Sprint 4 新页面 (FE-4.1~4.5) 与后端 Sprint 4 API 补充完全并行

### 3.5 渐进式迁移策略

每个 hook 文件迁移模式:
```
阶段1 (现状): import { xxxService } from '@/mock/services/xxxService'
阶段2 (开发期): VITE_USE_MOCK ? mockService : realApi   ← 可随时回退
阶段3 (稳定后): import { xxxApi } from '@/services/api/xxxApi'
```

Mock 层**不删除**, 作为独立开发/演示备用方案。

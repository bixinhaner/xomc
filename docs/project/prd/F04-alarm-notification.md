# PRD：邮件通知业务闭环

**PRD ID**：F04-email-notification

**功能域**：系统设置、告警管理、KPI 性能管理

**关联问题**：GitLab #283

**状态**：已按老 OMC 13.0.5、历史需求单和当前代码重新复核

**最后更新**：2026-08-17

## 1. 结论

本需求不是“把 Office365 写死改成阿里企业邮箱”，也不是“告警规则命中后同步发送一封邮件”。正确的业务模型分四层：

1. **邮件通道**：每个逻辑 OMC 配置一套客户可用的 SMTP 连接；不限定阿里、Office365、163 或其他服务商。
2. **业务订阅**：告警模板和 KPI 查询模板分别定义发送条件、周期与收件人。
3. **异步任务**：告警聚合邮件和 KPI 报表邮件由后台任务生成，不能阻塞告警入库或 KPI 查询。
4. **发送记录**：记录每次任务、每个收件人的结果，支持成功、失败、部分成功与排障信息。

公司内部邮箱只用于内部测试。客户交付时，由客户提供其 SMTP 服务和业务收件人。发件账号可以在同一逻辑 OMC 的多个应用节点间共用；不同 OMC 部署是否共用账号由客户邮件策略决定，系统不强制“一台服务器一个账号”。

### 2.2 老 OMC 文档与 189 环境实证

2026-08-17 在 `172.21.172.189:8081` 只读核对到以下真实流程：

- System Settings → Notification Setting 配置发送通道：开关、发件邮箱、密码、SMTP Host、Port、TEST。
- Alarm → Notification Setting 配置全局邮件开关、默认收件人和模板列表。
- 告警模板配置包括：启用、发送周期、Tolerance Duration、模板收件人、是否通知默认收件人。
- 发送周期和 Tolerance Duration 的页面选项均为：Real Time、10 Minute、30 Minute、60 Minute。
- KPI View → 模板 → Regular Report 配置：启用、发送时间、Day/Hour/15Min、Email/FTP 和各自参数。
- KPI 邮件收件人与告警收件人相互独立。

老代码文档确认告警链路是：模板启用 → 定时任务 → 方法队列 → 查询模板/权限/活动与清除告警 → 生成 HTML → SMTP → 发送记录。新项目不照搬 Quartz、临时表和逐地址同步发送，但必须保留其业务能力。

### 2.3 实施前主线存在的问题

- `internal/alarm/email_dispatcher.go` 与 `internal/notification/email_sender.go` 有两套 SMTP 实现，TLS、认证和消息能力不一致。
- `notify_email` 原先在告警过滤处理路径同步直发，失败只写日志，会拖慢业务并且没有可靠记录；本次将其退役为历史只读值，新建/修改不再接受，运行时也不发送，并在升级协调时幂等转换为 Real Time 告警邮件订阅，避免旧配置静默失效或与订阅链路重复发信。
- 告警标题和内容不符合 #31315/#31316，也没有按模板周期聚合活动/清除告警。
- 系统设置中已有邮件/短信假 UI，但未接真实后端；测试按钮用定时器伪造成功。
- KPI Regular Report 邮件订阅在本次实施前尚未落地。
- 旧 PRD 扩展了 Webhook、短信、运营商定制、DLQ 等未确认内容，已从本次范围移除。

| 角色 | 能力 |
|---|---|
| 超级管理员 | 查看/修改 SMTP 非敏感参数、轮换密码、启停邮件通道、向明确填写的单一地址发送测试邮件 |
| 告警模板管理员 | 启停告警邮件，配置周期、容忍时长、模板收件人、是否合并默认收件人 |
| KPI 模板所有者 | 为自己有权管理的 KPI 模板配置 Regular Report 和邮件收件人 |

所有写操作进入操作审计。SMTP 密码是 write-only，任何查询、日志、错误响应和审计详情都不得返回明文。

## 4. 业务配置模型

### 4.1 SMTP 通道（系统级）

字段：

| 字段 | 说明 |
|---|---|
| Enabled | 邮件发送总通道开关 |
| Host / Port | SMTP 地址与端口 |
| Security Mode | `none`、`starttls`、`implicit_tls` |
| Auth Enabled | 是否认证 |
| Username / Password | 认证信息；Password 只写不读 |
| From Address | SMTP envelope/header 发件地址 |
| From Name | 可选的展示名称，建议包含 OMC 名称 |
| Timeout | 单次 SMTP 会话超时，使用系统安全默认值 |

约束：

- 不硬编码邮箱服务商域名、端口或账号。
- `none` 只用于客户受控内网 SMTP，页面必须提示明文风险。
- 开启认证时用户名必填；密码首次配置必填，后续留空表示保留原密码。
- 开启认证时必须使用 `starttls` 或 `implicit_tls`，不允许远程明文认证。
- 启用通道前必须保证 Host、Port、From 和安全模式合法。
- 测试邮件收件人由管理员当次输入，不自动使用告警默认收件人或历史地址。
- 测试邮件只验证当前已保存配置；未保存表单不能绕过审计直接发信。

### 4.2 多服务器与多 OMC

- 同一套 OMC 的 app/worker 多节点共享 PostgreSQL、对象存储和一套 SMTP 业务配置，不需要逐节点手工配置。
- SMTP 参数（含 write-only 密码）保存在当前逻辑 OMC 的共享 PostgreSQL 中，由 app/worker 运行时读取；不需要逐节点手工配置。
- 不同测试环境、客户环境是不同逻辑 OMC，各自配置 SMTP；可以按管理员策略共用测试发件账号，但生产默认使用客户提供的系统公共邮箱。
- 邮件主题和正文携带 OMC 名称、环境标识、设备与告警/报表信息，用来区分来源；不靠“每台服务器一个邮箱账号”区分。

### 4.3 告警邮件订阅

告警邮件配置挂在告警视图/订阅模板上，而不是复用“忽略、确认、清除”过滤动作。

字段：

- Enabled：模板邮件开关；
- Interval：Real Time / 10 / 30 / 60 Minute；
- Tolerance Duration：Real Time / 10 / 30 / 60 Minute；
- Recipients：模板收件人，多地址去空格、校验、去重；
- Include Default Recipients：是否合并当前 OMC 的默认收件人；
- 继续复用模板既有的告警标识、级别、类型、设备/设备组和用户可见范围。
- 每次后台发送前重新校验模板创建者当前的设备权限；账号停用、设备或设备组权限撤销后立即拒绝读取和发送，不把保存时权限当作永久授权。

默认收件人是 OMC 侧配置的业务地址，不是发件账号。有效收件人集合为：

```text
unique(template_recipients + default_recipients when include_default=true)
```

若有效收件人为空，模板不能启用邮件。

告警任务入队时固化订阅筛选范围和最终收件人，后续编辑只影响新任务；任务执行前仍检查全局开关、订阅启用状态和创建者当前设备权限，使配置一致性与撤权安全同时成立。周期订阅在启用落入某个自然桶中间时，首个窗口从实际启用时间开始截断，不能丢弃该桶内启用后的告警。

Tolerance Duration 表示告警进入邮件统计窗口前的最短等待时间。告警在等待期内清除时，不静默丢弃，而是作为清除告警进入聚合邮件，同时展示产生时间与清除时间。依据是 #31315/#31316 明确要求活动告警和清除告警不拆分、两类时间在同一封邮件中表达；189 的模板页面也将发送周期和容忍时长作为两个独立字段。

本次不基于 Tolerance Duration 扩展复杂降噪、重复计数或告警升级策略。

### 4.4 告警邮件内容

邮件标题：

```text
[<OMC名称>] 告警通知 / Alarm Notification
```

正文按一封邮件聚合模板本周期内的告警，至少包含：

- OMC 名称与统计时间范围；
- 活动告警数、清除告警数和各级别汇总；
- 告警标识、级别、可能原因、设备标识、产生时间、清除时间；
- 描述、处理建议；
- 时区明确按系统时区展示。

同一告警在同一模板和统计窗口只出现一次。产生与清除状态在同一内容模型表达，不拆成两个互相矛盾的标题。

### 4.5 KPI Regular Report

KPI 邮件配置挂在 KPI 查询模板：

- Enable；
- Send Time；
- Period：Day / Hour / 15Min，可多选；
- Email 开关和收件人；
- 至少一台已授权设备和一个明确指标；启用态不允许空指标退化为全量导出；
- FTP 是并列出口，不作为邮件发送前提。

任务到点后异步生成报告文件，上传共享对象存储，再把文件作为附件发送。多节点只允许一个 worker 取得同一 `template + scheduled_at + period` 任务；重试不得重复生成或重复发送数据库中已经成功的收件人。

统计窗口按 OMC 系统时区取最近一个完整周期：`15Min` 为计划时间前最近完成的 15 分钟，`Hour` 为最近完成的自然小时，`Day` 为前一个自然日。模板原先用于人工查询的时间范围不参与定时报表窗口计算，避免“每天发送近 30 天”这类不确定口径。

本期邮件出口不修改现有 FTP 配置和任务；两者互不依赖，FTP 不作为邮件发送前置条件。

## 5. 发送任务与记录

统一任务状态：`pending → processing → sent/partial_failed/failed`。

每次任务记录：业务类型、模板、统计窗口、计划时间、实际时间、内容摘要、附件对象键、尝试次数和最终状态。每个收件人另有投递明细；日志只记录脱敏地址，不记录密码和完整正文。

失败原则：

- 告警入库、告警状态更新、KPI 查询不因邮件失败而回滚；
- SMTP 临时失败按有限次数重试；永久地址错误只标记该收件人失败；
- 部分收件人成功时任务为 `partial_failed`，重试只处理失败收件人；
- 任务幂等键由业务类型、模板、统计窗口和周期构成。
- 同一投递重试复用稳定 `Message-ID`。SMTP 接收结果不确定时无法承诺严格 exactly-once，客户邮箱服务器是否按 `Message-ID` 去重取决于其策略。

## 6. 验收标准

### AC-1 SMTP 通道

- 管理员可配置任意服务商 SMTP；支持无认证、STARTTLS、隐式 TLS。
- 密码查询返回空值和“已配置”标志，API/日志中不出现明文。
- 测试邮件只发送到管理员当次填写的地址，并产生审计和发送记录。
- 禁用通道后，业务任务保留为可诊断失败/暂停状态，不丢失业务数据。

### AC-2 告警订阅

- 可配置默认收件人和模板收件人，并正确执行合并、去重。
- 只查询模板范围内且当前用户有权管理的设备告警。
- Real Time 也通过异步任务发送，不在告警接收事务内连接 SMTP。
- 10/30/60 分钟周期各自形成确定统计窗口，任务重复执行不重复发信。
- 周期中途启用时，首个部分窗口只包含启用后的告警且不会整桶遗漏。
- 排队任务使用入队时的筛选范围和收件人，后续编辑不改变该任务；禁用和撤权立即生效。
- 邮件同时正确展示活动与清除告警及描述、建议。

### AC-3 KPI 报表

- KPI 模板可分别选择 Day/Hour/15Min 和收件人。
- 启用 KPI 定时报表时必须选择设备和指标，空指标请求由前后端共同拒绝。
- 报告异步生成并以附件发送；HTTP 请求不等待生成完成。
- 双 worker 并发时同一计划任务只生成一次；任意 worker 都能读取共享附件。

### AC-4 多环境交付

- 新环境只需配置一次逻辑 OMC，不要求逐个 app/worker 容器手填。
- 同一发布包可用于个人测试、公共测试和生产，差异全部来自配置/密钥。
- 交付文档提供阿里企业邮箱、标准 STARTTLS、内网无认证 SMTP 三类示例，但不写死任何真实账号。

## 7. 本次明确不做

- 短信、Webhook、IM、语音、移动推送；
- Zed Mobile #98018；
- OMCMonitor CPE 导出 #62360；
- 新的运营商专属邮件格式；
- 联系人通讯录、值班轮换、告警升级、地理围栏统一通知平台；
- 为未确认需求新增 `000002+` 迁移。

## 8. 分阶段开发

1. **基线纠偏**：删除假成功 UI，统一 SMTP 传输实现，明确配置和密钥边界。
2. **SMTP 通道**：真实设置页、校验、测试发送、审计、运行时加载。
3. **告警订阅**：默认收件人、模板邮件字段、异步聚合任务、内容与记录。
4. **KPI 报表**：Regular Report 配置、异步附件、多节点幂等。
5. **交付验收**：本地 mock SMTP、双 worker 模拟、104 测试环境、客户配置文档。

每一阶段单独编译、单测和浏览器验收；上一阶段未通过不进入下一阶段。

## 9. 已关闭的业务边界

Tolerance Duration 对“在容忍时长内已清除”的短暂告警不做完全抑制，按清除告警进入聚合邮件。实现和测试应覆盖“产生后在容忍期内清除”的样例，并验证产生时间、清除时间、描述和处理建议均保留。

# Issue #291 仪表板关注事项 PRD

## 背景

仪表板需要在保留原有首页板块的前提下，补充“异常”和“待办”两个轻量入口，让运维人员登录后能先看到当前最需要处理的事项，并能跳转到原业务模块继续处理。

本需求不在首页实现新的处理闭环。首页只做只读汇总、少量预览和跳转，避免复制告警、接入控制等模块已有能力。

## 范围

### 异常

- 来源：当前告警模块中的活跃紧急告警和重要告警。
- 展示：仪表板“关注事项”区域展示异常总数和 1 条最高优先级预览。
- 查看全部：打开只显示异常的侧边抽屉。
- 点击条目：跳转到当前告警页面，并定位/打开对应告警详情。
- 处理动作：仍在告警模块完成。

### 待办

- 来源：接入控制模块中待审核、未过期、当前用户数据权限可见的候选设备。
- 展示：仪表板“关注事项”区域展示待办总数和 1 条最早进入队列的预览。
- 查看全部：打开只显示待办的侧边抽屉。
- 点击条目：跳转到接入控制候选设备页，并定位对应候选项。
- 处理动作：仍在接入控制模块完成审核。

## 非范围

- 不新增 Ops 运维任务审批待办。
- 不新增“四眼审批”、风险审批或其他处理流程。
- 不在首页合并疑似重复告警；重复治理由告警域负责。
- 不改变原首页 KPI、图表、趋势、网络制式等板块。
- 不改变告警确认、反确认、清除等既有业务规则。
- 不改变接入候选审核通过/拒绝的既有业务规则。

## UI 原则

- “关注事项”作为首页中部的紧凑模块，异常和待办左右两列展示。
- 每列只展示 1 条预览，避免页面过长。
- “查看全部”打开侧边抽屉，抽屉中只显示当前点击的分类，不显示另一个分类。
- 抽屉列表采用轻量卡片样式，分页固定在底部。
- 颜色遵循现有 Ant Design 主题 token，不使用突兀的白底或高饱和自定义色。

## 验收标准

- 首页原有板块仍完整保留。
- 异常数量等于当前用户可见的活跃紧急 + 重要告警数量。
- 待办数量等于当前用户可见的待审核、未过期候选设备数量。
- 首页每类最多展示 1 条预览。
- 点击异常预览或抽屉条目后进入当前告警页并打开对应告警详情。
- 点击待办预览或抽屉条目后进入接入控制候选设备页并定位对应候选项。
- 点击异常“查看全部”时抽屉只显示异常。
- 点击待办“查看全部”时抽屉只显示待办。
- 关注事项接口失败时只影响关注事项区域，不影响原首页模块加载。

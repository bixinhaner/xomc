# PRD 模板

> 复制此文件为 `F{NN}-{slug}.md`（如 `F04-alarm-notification.md`）使用。  
> 七要素齐全才算一份合格 PRD；缺任何一项都不得启动开发。  
> 守护人：产品经理（`CLAUDE.md §16.10`）

## 1. 业务背景（Why）

一句话说明为什么做。然后 2-3 段说明：
- 当前用户/运营场景痛点是什么
- 不做会发生什么
- 为什么现在做

**避免**："为了功能完整"、"补齐短板"这种空话。要说清楚**具体的运维/运营场景**。

---

## 2. 用户故事（Who / What）

格式：
> As a **{角色}**，I want **{动作}**，So that **{价值}**。

至少 3 条故事，覆盖主要用户角色：
- 运维人员
- 运营规划人员
- 系统管理员
- 客服/工单人员（如涉及）

---

## 3. 验收标准（Given/When/Then）

**必须可测**。每条标准形如：

```
Given: {前置状态}
When:  {触发动作}
Then:  {期望结果}
```

每条都对应至少一条 E2E 用例或单元测试。

**示例**：
```
Given: 设备 "D-001" 当前无活跃告警
When:  CPE 上报严重级别为 "critical" 的告警码 "POWER_FAIL"
Then:  - 告警在 3 秒内写入 alarm_active 表
       - 通知渠道（邮件）在 30 秒内收到通知
       - 通知内容含设备 SN、告警码、时间戳、运营商
       - SSE 推送到所有登录中的运维用户
```

## 4. 运营商差异矩阵

| 维度 | CMCC | CTCC | CUCC | 备注 |
|------|------|------|------|------|
| {差异点 1} | {做法 A} | {做法 B} | {做法 A} | |
| {差异点 2} | … | … | … | |

**关键约束**：所有差异必须通过 `internal/core/carrier/*` 适配器实现。PRD 中标注各运营商要求，不指定代码层的 `if` 判断。

若无差异，写"无 — 三家一致"。

---

## 5. 非目标（Non-Goals）

明确"这次不做"的清单，避免范围飘移：
- ✂️ 不做 X（原因：下个里程碑 / 已在 F0X）
- ✂️ 不做 Y（原因：ROI 太低 / 依赖未就绪）

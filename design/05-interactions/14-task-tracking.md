# 任务跟踪 (Task Tracking)

> OMC 统一网管系统 - 交互设计规范

## 概述

OMC 系统中许多操作需要较长时间执行 (如批量升级、配置同步、数据导出等)。这些长时间运行的任务需要统一的跟踪机制，让用户随时了解任务状态而不被阻塞。

---

## 1. 任务创建

### 1.1 任务创建流程

```
用户发起操作 (如: 批量升级 5 台设备)
    │
    ├── 操作耗时 < 3s → 同步等待, 直接返回结果
    │
    └── 操作耗时 > 3s → 异步任务模式:
        1. 后端创建任务 → 返回 taskId
        2. 前端 Toast: "任务已创建, 可在任务面板中查看进度"
        3. 任务面板右下角新增任务条目
        4. 用户可继续其他操作 (不被阻塞)
```

### 1.2 任务创建 Toast

```
┌──────────────────────────────────────────────────────┐
│ ✓ 批量升级任务已创建 (任务ID: TASK-20240115-001)     │
│                                     [查看任务面板]    │
└──────────────────────────────────────────────────────┘

类型: message.success() 或 notification.success()
自动关闭: 5s
操作: [查看任务面板] → 打开/展开任务面板
```

## 2. 任务状态 (Task States)

### 2.1 状态定义

| 状态 | 中文 | 英文 | 图标/颜色 | 说明 |
|------|------|------|----------|------|
| WAITING | 等待中 | Waiting | ⏳ 灰色 (#8C8C8C) | 任务已创建, 排队等待执行 |
| IN_PROGRESS | 进行中 | In Progress | ● 蓝色 (#1890FF) | 任务正在执行 |
| SUSPENDED | 暂停 | Suspended | ⏸ 橙色 (#FAAD14) | 任务被手动暂停 |
| COMPLETED | 已完成 | Completed | ✓ 绿色 (#52C41A) | 任务成功完成 |
| FAILED | 失败 | Failed | ✕ 红色 (#FF4D4F) | 任务执行失败 |
| TERMINATED | 已终止 | Terminated | ⏹ 灰色 (#8C8C8C) | 任务被手动终止 |

### 2.2 状态流转图

```
                    ┌──────────┐
                    │  等待中   │
                    │ WAITING  │
                    └────┬─────┘
                         │ 开始执行
                         ▼
              ┌──── 进行中 ◄────┐
              │   IN_PROGRESS   │
              │                 │
    ┌─────────┼─────────┐      │ 恢复
    │         │         │      │
    ▼         ▼         ▼      │
┌────────┐ ┌────────┐ ┌────────┐
│ 已完成  │ │  失败  │ │  暂停  │
│COMPLETED│ │ FAILED │ │SUSPENDED│
└────────┘ └────────┘ └────────┘
                │
                │ 重试
                ▼
           ┌────────┐
           │ 等待中  │
           │WAITING │
           └────────┘

    任何非终态 ──终止──► 已终止 (TERMINATED)
```

### 3.1 面板位置与触发

```
位置: 页面右下角浮动面板
触发: Header 中的任务图标 (带未完成任务数 Badge)

### 3.3 任务条目交互

| 操作 | 行为 |
|------|------|
| 点击任务条目 | 导航到任务关联的页面 (如升级任务 → 升级计划详情) |
| 暂停 | 暂停任务执行 (状态变为 SUSPENDED) |
| 恢复 | 恢复暂停的任务 (状态变为 IN_PROGRESS) |
| 终止 | 终止任务 (确认对话框 → 状态变为 TERMINATED) |
| 重试 | 重新执行失败的任务 (状态变为 WAITING) |
| 下载文件 | 下载导出任务生成的文件 |
| 删除 | 从面板中移除已完成/失败/终止的任务 |

## 4. 自动刷新

### 4.1 刷新策略

```
WebSocket 模式 (优先):
  - 任务状态变更通过 WebSocket 实时推送
  - 无额外 Polling

Polling 模式 (降级):
  - 面板展开时: 每 5s 刷新一次
  - 面板收起时: 每 15s 刷新一次 (减少请求)
  - 无进行中任务时: 停止 Polling
```

### 4.2 进度更新

```
进度条更新:
  - WebSocket: 实时推送进度百分比
  - Polling: 每次请求获取最新进度
  - 进度条动画: CSS transition 500ms ease-out (平滑过渡)
  - 数字更新: 渐变效果 (避免跳动)
```

## 5. 任务完成/失败通知

### 5.1 任务完成

```
通知方式: Notification (右下角弹出)

┌──────────────────────────────────────────────┐
│ ✓ 任务完成                              [X] │
│                                              │
│ 批量升级已完成                                │
│ 成功: 4 台  失败: 1 台                       │
│ 耗时: 5分23秒                                │
│                                              │
│ [查看详情]                                    │
└──────────────────────────────────────────────┘

自动关闭: 10s
操作: [查看详情] → 导航到任务详情
音效: 可选成功提示音 (用户配置)
```

### 5.2 任务失败

```
┌──────────────────────────────────────────────┐
│ ✕ 任务失败                              [X] │
│                                              │
│ 配置同步失败                                  │
│ 原因: 设备 eNodeB-003 连接超时               │
│                                              │
│ [查看详情]    [重试]                          │
└──────────────────────────────────────────────┘

自动关闭: 不自动关闭
操作: [查看详情] + [重试]
```

### 5.3 通知条件

```
规则:
  - 用户在当前页面: 显示 Notification
  - 用户不在当前页面 (切到其他 Tab): 浏览器 Notification API
  - 任务面板 Badge 数字更新
  - Header 任务图标闪烁提示 (可选)
```

```

  1. 如果目标页面是当前页面 → 滚动到相关记录
  2. 如果目标页面非当前页面 → 路由导航

## 9. 实现参考

### 任务状态管理

```typescript
// 推荐: 使用全局状态管理任务列表
interface Task {
  taskId: string;
  name: string;
  type: TaskType;
  status: TaskStatus;
  progress: number;        // 0-100
  currentStep?: string;    // 当前步骤描述
  createdAt: string;
  completedAt?: string;
  result?: TaskResult;
  navigateTo?: string;     // 关联页面路由
}

// Zustand Store
const useTaskStore = create<TaskStore>((set) => ({
  tasks: [],
  addTask: (task) => set((s) => ({ tasks: [task, ...s.tasks] })),
  updateTask: (taskId, updates) => set((s) => ({
    tasks: s.tasks.map(t => t.taskId === taskId ? { ...t, ...updates } : t),
  })),
  removeTask: (taskId) => set((s) => ({
    tasks: s.tasks.filter(t => t.taskId !== taskId),
  })),
}));
```

### WebSocket 任务更新

```typescript
// 监听任务状态变更
wsManager.on('task', (message) => {
  const { taskId, status, progress, currentStep } = message.data;
  useTaskStore.getState().updateTask(taskId, { status, progress, currentStep });

  // 任务完成/失败时弹出通知
  if (status === 'COMPLETED' || status === 'FAILED') {
    showTaskNotification(message.data);
  }
});
```

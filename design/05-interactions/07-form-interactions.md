# 表单交互 (Form Interactions)

> OMC 统一网管系统 - 交互设计规范

## 概述

表单是 OMC 系统中数据录入的核心交互方式，涵盖设备注册、配置修改、任务创建、规则设置等场景。本文定义统一的表单交互规范，确保所有表单的行为一致、用户体验可预测。

---

## 1. 必填字段标记 (Required Field Marking)

### 1.1 规范

```
标记方式: 红色星号 (*) 放在 Label 前面

示例:
  * 设备名称       [________________]
  * IP 地址        [________________]
    描述 (选填)     [________________]

规范:
  - 星号颜色: @error-color (#FF4D4F)
  - 星号位置: Label 文字之前, 间距 4px
  - 字体: 14px
  - 只有必填字段显示星号
  - 可选字段: 不加星号, 可在 Label 后加 "(选填)" 灰色文字
```

### 1.2 必填提示

```
必填字段未填写时的错误消息: "请输入{字段名}" 或 "请选择{字段名}"
不使用通用的 "此字段必填" — 消息需包含具体字段名
```

## 2. 行内验证 (Inline Validation)

### 2.1 验证时机

| 时机 | 行为 | 适用场景 |
|------|------|---------|
| onBlur (失焦) | 用户离开字段时验证 | 所有字段 (主要验证时机) |
| onChange (修改) | 仅在字段已有错误时实时验证 | 修正错误时即时反馈 |
| onSubmit (提交) | 验证全部字段 | 点击提交按钮时 |

### 2.2 验证流程

```
1. 用户填写字段 A, 移出焦点 (onBlur)
2. 验证字段 A
   ├── 验证通过: 无变化 (或显示绿色对勾, 可选)
   └── 验证失败:
       a. 输入框边框变红 (#FF4D4F)
       b. 字段下方显示红色错误文字
       c. 错误消息: 12px, color #FF4D4F, margin-top 4px
3. 用户修改字段 A 内容 (onChange)
   └── 已有错误 → 实时重新验证
       ├── 验证通过: 清除错误状态
       └── 验证失败: 更新错误消息
```

### 2.3 错误消息位置

```
┌─────────────────────────────────┐
│ * 设备名称                       │
│ ┌─────────────────────────────┐ │
│ │                             │ │  ← 红色边框
│ └─────────────────────────────┘ │
│ ⚠ 请输入设备名称                │  ← 错误消息 (12px, #FF4D4F)
│                                 │
│ * IP 地址                        │
│ ┌─────────────────────────────┐ │
│ │ 192.168.1.abc               │ │  ← 红色边框
│ └─────────────────────────────┘ │
│ ⚠ IP 地址格式不正确             │  ← 错误消息
└─────────────────────────────────┘

规范:
  - 位置: 输入框正下方
  - 间距: margin-top 4px
  - 字体: 12px
  - 颜色: #FF4D4F
  - 图标: 可选 WarningOutlined 图标
  - 同一字段最多显示 1 条错误消息 (优先级最高的那条)
```

## 3. 提交时错误汇总

### 3.1 提交验证流程

```
1. 用户点击 [提交/保存] 按钮
2. 前端验证全部字段
3. 如有错误:
   a. 按钮不进入 loading 状态
   b. 所有错误字段显示行内错误
   c. 字段 > 10 个时: 顶部显示错误汇总 Alert
   d. 页面滚动到第一个错误字段 (scrollIntoView + 聚焦)
4. 如无错误:
   a. 按钮进入 loading 状态
   b. 发送 API 请求
   c. 成功 → Toast + 关闭/跳转
   d. 失败 → Toast 错误消息, 按钮恢复
```

### 3.2 错误汇总 Alert

```
┌────────────────────────────────────────────────┐
│ ⚠ 提交失败，请修正以下 3 个错误:                │
│   · 设备名称 — 请输入设备名称                    │  ← 可点击, 跳转到对应字段
│   · IP 地址 — IP 地址格式不正确                  │
│   · 端口号 — 端口号必须在 1-65535 之间           │
└────────────────────────────────────────────────┘

组件: Alert type="error"
位置: 表单顶部 (Form 内第一个元素)
行为: 点击具体错误项 → 页面滚动到该字段并聚焦
```

## 4. 表单分区折叠/展开 (Form Section Collapse)

### 4.1 交互规范

```
┌────────────────────────────────────────────┐
│ ▼ 基本信息                                 │  ← 点击展开/折叠
├────────────────────────────────────────────┤
│ * 设备名称:  [________________]            │
│ * IP 地址:   [________________]            │
│   描述:      [________________]            │
├────────────────────────────────────────────┤
│ ▶ 高级设置                            (3) │  ← 折叠, 括号内为字段数
├────────────────────────────────────────────┤
│ ▼ 网络配置                                 │  ← 展开
├────────────────────────────────────────────┤
│ * 子网掩码:  [________________]            │
│   网关:      [________________]            │
└────────────────────────────────────────────┘

规范:
  - 分区标题: 16px, font-weight 600, @heading-color
  - 展开图标: ▶/▼ 旋转动画 200ms
  - 默认展开: "基本信息" 等主要分区
  - 默认折叠: "高级设置" 等次要分区
  - 折叠分区有错误时: 分区标题右侧显示红色圆点
  - 折叠动画: 高度过渡 200ms ease-out
```

## 5. 动态表单字段 (Dynamic Form Fields)

### 5.1 添加/删除行

```
┌────────────────────────────────────────────────────┐
│ DNS 服务器:                                        │
│ ┌─────────────────────┐                            │
│ │ 8.8.8.8             │  [删除]                    │
│ └─────────────────────┘                            │
│ ┌─────────────────────┐                            │
│ │ 8.8.4.4             │  [删除]                    │
│ └─────────────────────┘                            │
│ [+ 添加 DNS 服务器]                                 │
└────────────────────────────────────────────────────┘

[+ 添加] 按钮:
  - 类型: Dashed Button
  - 图标: PlusOutlined
  - 文字: "+ 添加{字段名}"
  - 点击后: 在列表末尾添加空行
  - 最大行数: 可配置限制 (如最多 5 个 DNS)

[删除] 按钮:
  - 类型: 红色 Text Button 或图标按钮 (DeleteOutlined)
  - 最少保留 1 行 (最后一行删除按钮禁用)
  - 删除无需确认 (可撤销: 数据未提交前可重新添加)
```

### 5.2 动态键值对

```
┌────────────────────────────────────────────────────────┐
│ 自定义参数:                                            │
│ ┌──────────────┐  ┌──────────────┐                    │
│ │ 参数名       │  │ 参数值       │  [删除]            │
│ └──────────────┘  └──────────────┘                    │
│ ┌──────────────┐  ┌──────────────┐                    │
│ │ 参数名       │  │ 参数值       │  [删除]            │
│ └──────────────┘  └──────────────┘                    │
│ [+ 添加参数]                                           │
└────────────────────────────────────────────────────────┘
```

## 6. 联动下拉 (Dependent Dropdowns)

### 6.1 交互规范

```
┌────────────────────────────────────────────────────┐
│ * 省份:    [广东省  ▾]                              │
│ * 城市:    [广州市  ▾]    ← 选项随省份变化          │
│ * 区域:    [天河区  ▾]    ← 选项随城市变化          │
└────────────────────────────────────────────────────┘

联动规则:
  1. 选择父级下拉 → 清空子级已选值 → 重新加载子级选项
  2. 父级未选择 → 子级禁用 (disabled), Placeholder: "请先选择{父级}"
  3. 子级选项加载中 → 显示 loading Spinner
  4. 子级选项加载失败 → 选项为空 + 错误提示

常见联动场景:
  - 省 → 市 → 区
  - 设备类型 → 设备型号
  - 基站 → 小区
  - 网元类型 → MML 命令分类 → MML 命令
```

## 7. 自动保存草稿 (Auto-save Draft)

### 7.1 交互规范

```
适用场景: 复杂表单 (字段 > 10 个, 如任务创建、计划配置)

策略:
  - 自动保存时机: 用户修改任意字段后 5s 无操作自动保存
  - 存储位置: localStorage (前端草稿)
  - Key: `omc_draft_{formKey}_{userId}`

用户提示:
  ┌───────────────────────────────────────────┐
  │ 已自动保存草稿 (14:30:25)                  │  ← 表单底部灰色文字
  └───────────────────────────────────────────┘

恢复草稿:
  打开表单时检测到草稿 → 弹出提示:
  ┌──────────────────────────────────────────────┐
  │ 检测到未提交的草稿 (保存于 2024-01-15 14:30) │
  │                                              │
  │ [恢复草稿]    [忽略并新建]                    │
  └──────────────────────────────────────────────┘

清除草稿:
  - 表单成功提交后自动清除
  - 用户点击 [忽略并新建] 时清除
```

## 8. 未保存变更提醒 (Unsaved Changes Warning)

### 8.1 交互规范

```
触发条件: 表单有修改 (dirty state) 且用户尝试离开

场景:
  - 点击侧边栏导航到其他页面
  - 点击浏览器后退按钮
  - 关闭 Modal/Drawer
  - 关闭浏览器标签页

提醒对话框:
  ┌──────────────────────────────────────────┐
  │ 未保存的更改                         [X] │
  ├──────────────────────────────────────────┤
  │                                          │
  │ 当前页面有未保存的更改，确定要离开吗?      │
  │ 离开后未保存的更改将丢失。                │
  │                                          │
  ├──────────────────────────────────────────┤
  │              [留在此页]    [不保存并离开]  │
  └──────────────────────────────────────────┘

按钮:
  [留在此页] Primary Button → 取消导航, 留在当前页面
  [不保存并离开] Default Button → 丢弃更改, 离开页面
```

### 8.2 Dirty State 检测

```typescript
// 方案: 比较初始值与当前值
const isDirty = !isEqual(initialValues, currentValues);

// 浏览器关闭/刷新拦截
window.addEventListener('beforeunload', (e) => {
  if (isDirty) {
    e.preventDefault();
    e.returnValue = ''; // 触发浏览器默认提示
  }
});

// React Router 路由拦截
<Prompt when={isDirty} message="有未保存的更改，确定离开?" />
```

## 9. 键盘交互 (Keyboard Interactions)

### 9.1 Tab 导航

```
规则:
  - Tab: 移动到下一个输入字段
  - Shift + Tab: 移动到上一个输入字段
  - Tab 顺序: 从上到下, 从左到右 (遵循视觉布局)
  - 跳过 disabled 和 readonly 字段
  - 隐藏/折叠区域内的字段不参与 Tab 顺序
```

### 9.2 Enter 提交

```
规则:
  - 在最后一个输入字段按 Enter → 触发表单提交
  - 在多行文本框 (Textarea) 中 Enter 为换行, 不触发提交
  - 在搜索框中 Enter → 触发搜索
  - Ctrl + Enter → 强制提交 (在 Textarea 中)
```

### 9.3 ESC 取消

```
规则:
  - ESC: 关闭当前 Modal/Drawer (如果表单在 Modal/Drawer 中)
  - 如果表单有未保存更改 → 先弹出未保存提醒
```

## 10. 表单布局规范

### 10.1 水平布局 (Horizontal)

```
┌────────────────────────────────────────────────────┐
│ * 设备名称:    [________________________]          │
│ * IP 地址:     [________________________]          │
│   描述:        [________________________]          │
└────────────────────────────────────────────────────┘

Label 位置: 输入框左侧
Label 宽度: 固定 120px, 文字右对齐
Label 与输入框间距: 8px
适用于: Modal 表单, Drawer 表单
```

### 10.2 垂直布局 (Vertical)

```
┌────────────────────────────────────────────────────┐
│ * 设备名称                                         │
│ [____________________________________________]     │
│                                                    │
│ * IP 地址                                          │
│ [____________________________________________]     │
│                                                    │
│   描述                                             │
│ [____________________________________________]     │
└────────────────────────────────────────────────────┘

Label 位置: 输入框上方
适用于: 全页表单, 字段名较长时
```

### 10.3 多列布局

```
┌────────────────────────────────────────────────────┐
│ * 设备名称: [____________]  * IP 地址: [__________]│
│ * 端口号:   [____________]    描述:    [__________]│
└────────────────────────────────────────────────────┘

使用 24 栏 Grid:
  - 2 列: 每个 Form.Item 占 12 栏
  - 3 列: 每个 Form.Item 占 8 栏
适用于: 字段多的全页表单
```

## 11. 实现参考

### Ant Design Form 关键配置

```typescript
<Form
  form={form}
  layout="horizontal"         // horizontal | vertical | inline
  labelCol={{ span: 6 }}      // Label 宽度 (24 栏制)
  wrapperCol={{ span: 18 }}   // 输入框宽度
  validateTrigger={['onBlur']} // 验证时机
  scrollToFirstError           // 提交时滚动到首个错误
  onFinish={handleSubmit}      // 验证通过后提交
  onFinishFailed={handleFailed} // 验证失败回调
>
  <Form.Item
    label="设备名称"
    name="deviceName"
    rules={[
      { required: true, message: '请输入设备名称' },
      { max: 64, message: '设备名称不能超过64个字符' },
    ]}
  >
    <Input placeholder="请输入设备名称" />
  </Form.Item>
</Form>
```

# 设备注册功能说明

## 功能概述

设备注册功能用于在基站上线前提前对其进行规划和管理。通过设备注册，管理员可以将设备按照不同的维度进行分组，便于后续的运维和管理。

当基站通过TR069协议与OMC系统连接时，系统会自动检查该基站是否已在系统中注册：
- **已注册**：保持其原有的设备组归属
- **未注册**：自动关联到默认的"default"设备组，由管理员后续手动进行分配

## 页面操作说明

### 设备组管理

#### 页面布局
- **左侧**：
  - 上方有搜索框，用于快速查找设备组（支持模糊搜索）
  - 下方是树形结构展示设备组（两级：一级设备组、二级设备组）
- **中间**：
  - 上方有搜索框，用于在设备列表中快速查找设备
  - 下方是表格展示当前选中设备组下的所有设备
- **右侧**：设备或设备组的详细信息面板（默认隐藏，需要时从右侧滑出展示）

#### 默认设备组

系统默认内置一个一级设备组，其下有一个内置的二级设备组。这两个内置的组不可删除、不可修改。

#### 二级设备组操作

| 操作按钮 | 功能描述 |
|--------|--------|
| 信息 | 查看设备组的名称、描述、下挂的设备等信息，只读模式 |
| 修改 | 修改设备组的名称和描述，并可勾选/去勾选设备以调整组下挂载的设备 |
| 删除 | 删除该设备组，组下的所有设备自动移动至默认的二级组下 |

#### 一级设备组操作

| 操作按钮 | 功能描述 |
|--------|--------|
| 添加 | 添加下一级的二级设备组 |
| 修改 | 修改一级设备组的名称 |
| 删除 | 删除该一级设备组，组下的所有二级设备组和设备都自动移至默认的一级组下 |

#### 设备添加

右上角的"添加设备"按钮用于向指定设备组中添加设备，支持两种方式：

**方式一：手动输入**
- 选择目标设备组（必须是二级设备组）
- 输入设备SN，多个设备之间用以下符号分隔：英文分号（;）、空格、换行符

**方式二：批量导入（Excel）**
- 点击"下载模板"获取导入模板
- 按照模板格式填写设备信息
- 上传文件，系统自动解析并入库

## 批量导入Excel模板说明

### 模板格式

Excel导入模板包含以下字段（**加粗为必填字段**）：

| 序号 | 字段名称 | 类型 | 范围/说明 | 验证规则 |
|-----|--------|------|---------|--------|
| 1 | **设备ID** | 文本 | - | 必填，长度≤32，全局唯一 |
| 2 | **安装经度** | 数值 | [-180, 180] | 浮点数，精度自动保留6位小数 |
| 3 | **安装纬度** | 数值 | [-90, 90] | 浮点数，精度自动保留6位小数 |
| 4 | **安装高度** | 数值 | [0, 99999999] | 非负整数 |
| 5 | **基站名称** | 文本 | - | 长度≤128 |
| 6 | **机械下倾角(°)** | 数值 | [0, 9] | 整数，1位数字 |
| 7 | **垂直3dB波束宽度** | 数值 | [1, 9] | 整数，1位数字 |
| 8 | **水平方位角(°)** | 数值 | [0, 359] | 整数 |
| 9 | 备注 | 文本 | - | 可选，长度≤512 |

### 数据验证规则

**合法性检查**：
- GPS坐标格式正确（经度: -180到180，纬度: -90到90）
- GPS坐标精度自动保留6位小数
- 高度值在合法范围内（0 ~ 99999999）
- 所有数值字段格式正确，无文本混入

**异常处理**：
- 任何不合法的数据行将被**完全丢弃**（不进行部分字段导入）
- 导入完成后会提示成功导入的记录数和失败的记录数
- 失败的行信息可下载查看，便于修正后重新导入

### 导入步骤

1. 点击"添加设备" → 选择"批量导入"
2. 点击"下载模板"获取Excel模板文件
3. 按照模板格式填写设备信息：
   - 一行一个设备
   - 必填字段不能为空
   - 数值字段需符合范围要求
4. 选择导入的目标设备组（必须是二级设备组）
5. 选择准备好的Excel文件并上传
6. 系统自动验证和导入数据
7. 查看导入结果统计

## 数据存储说明

设备注册数据在关系型数据库中存储，使用以下核心表：

| 表名 | 说明 |
|-----|------|
| device_group | 设备组表，存储设备组的层级关系和信息 |
| small_cell_infos | 设备信息表，存储基站的详细属性 |
| rela_device_group_cell | 设备与设备组的关系表，建立设备和设备组的关联 |

## 与其他模块的关联

### TR069 Server (ACS) 集成

由于设备量大，如果每次消息都查库检查设备注册状态，会对数据库造成过大压力。因此：

- **系统启动时**：将设备信息表、设备归属组关系加载到Redis缓存（缓存预热）
- **设备注册时**：先写入数据库，再同步更新Redis缓存
- **设备删除时**：先删除数据库记录，再同步清理Redis缓存
- **设备上线时**：ACS直接从Redis缓存中检查设备注册状态

设备注册模块与TR069 Server的交互流程：

1. **设备首次上线**
   - TR069 Server接收基站的首次连接请求
   - 系统从Redis缓存中检查该设备是否已注册

2. **已注册设备**
   - 保持该设备与现有设备组的关联关系不变
   - 继续按照原有的分组策略进行管理

3. **未注册设备**
   - 自动将设备关联到"default"默认设备组
   - 等待系统管理员进行后续的手动分组操作

### 系统管理员后续操作

管理员可以通过以下步骤对自动关联到"default"组的设备进行重新分组：

1. 登录OMC系统，进入设备注册界面
2. 在左侧设备组树中选择"default"组
3. 在中间表格中查看自动注册的设备
4. 手动将设备移动到适当的设备组

## 建议优化方向

### 当前设计限制
- 设备组采用固定两级的树形结构
- 所有设备都必须关联到二级设备组

### 优化建议
- 改为不固定级别的树形结构，支持任意深度的设备组嵌套
- 允许设备关联到任意级别的设备组，提供更灵活的分组策略

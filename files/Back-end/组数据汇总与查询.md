# 组数据汇总与查询

## 1. 功能概述

将 KPI 数据按设备组（device group）维度定时聚合为 15min/小时/天/周/月五种粒度的汇总数据，供组维度报表和图表查询使用。其中 15min 粒度的源数据为基站原始上报数据，其他粒度的源数据为已完成基站维度汇总的数据。

---

## 2. 核心概念

### 2.1 设备组层级

| 层级 | 说明 | 数据中的 group_id |
|------|------|------------------|
| 一级设备组（parent group） | 最上层分组，包含多个二级组 | `top_{一级组id}` |
| 二级设备组（sub group） | 直接关联基站的分组 | 原始 id 值 |

聚合时对每层分别运算：
- **二级组聚合**：将同一 `group_id` 下的所有基站数据合并
- **一级组聚合**：将某个一级组下属所有二级组的数据再合并，结果 `group_id` 标记为 `top_{一级组id}`

### 2.2 统计粒度

| 数值 | 粒度 | 说明 |
|-----|------|------|
| 15 | 15分钟 | 独立定时任务，有延迟配置 |
| 60 | 小时 | 随基站维度小时汇总任务一起触发 |
| 1440 | 天 | 随基站维度天汇总任务一起触发 |
| 10080 | 周 | 随基站维度周汇总任务一起触发，受 `kpiWeekAndMonthSwitch` 开关控制 |
| 43200 | 月 | 随基站维度月汇总任务一起触发，受 `kpiWeekAndMonthSwitch` 开关控制 |

### 2.3 指标统计类型

| 统计类型 | 说明 |
|--------|------|
| sum | 对多条数据的指标值求和 |
| avg | 对多条数据的指标值求平均 |
| max | 取多条数据的最大值 |
| min | 取多条数据的最小值 |
| pct | 公式型指标，处理方式因设备类型而异（见 5.8 节） |

### 2.4 指标级别（仅 ENB/GSM 适用）

| 级别 | 说明 |
|-----|------|
| device | 设备级指标 |
| plmn | PLMN 级指标 |
| both | 同时属于设备级和 PLMN 级（BSC/GSM 指标使用） |

GNB 不区分指标级别，只有一套表，只执行一次聚合。

## 4. 定时触发规则

### 4.1 各粒度定时任务一览

除 15min 粒度有独立定时任务外，其他粒度（60/1440/10080/43200）的组维度汇总在各粒度的基站维度汇总任务中顺序执行。

| 任务 | 设备类型 | 粒度 | 组汇总触发时机 | 开关控制 | 额外条件 |
|------|---------|------|--------------|---------|---------|
| 小时任务 | ENB/GSM | 60 | 基站维度小时汇总完成后 | 无 | 无 |
| 小时任务 | GNB | 60 | 基站维度小时汇总完成后 | 无 | 无 |
| 天任务 | ENB/GSM | 1440 | 基站维度天汇总完成后 | 无 | 无 |
| 天任务 | GNB | 1440 | 基站维度天汇总完成后 | 无 | 无 |
| 周任务 | ENB/GSM | 10080 | 基站维度周汇总完成后 | `kpiWeekAndMonthSwitch=1` | 无 |
| 周任务 | GNB | 10080 | 基站维度周汇总完成后 | `kpiWeekAndMonthSwitch=1` | 无 |
| 月任务 | ENB/GSM | 43200 | 基站维度月汇总完成后 | `kpiWeekAndMonthSwitch=1` | 当天是月第 1 天或最后一天 |
| 月任务 | GNB | 43200 | 基站维度月汇总完成后 | `kpiWeekAndMonthSwitch=1` | 当天是月第 1 天或最后一天 |

### 4.2 15min 粒度特殊说明

15min 粒度有独立的定时任务（`GroupData15MinStatisJob`），与基站维度 15min 数据入库是并行的。

**触发机制：**
1. 任务按计划时间触发（每个 15min 周期触发一次）
2. 取计划执行时间，减去延迟分钟数（配置项 `groupData15MinStatisDelayMin`，默认 5 分钟），得到统计周期结束时间
3. 依次执行 ENB/GSM 和 GNB 的 15min 组维度汇总
4. 记录 GNB 的数据结束时间

**延迟配置原因：** 15min 原始数据入库可能稍有滞后，等待一定时间后再聚合，确保数据完整性。

**注意：** ENB/GSM 的 15min 组维度汇总不记录 `perf_statis_data_end_time`，仅 GNB 记录。

### 4.3 周/月粒度开关控制

周粒度（10080）和月粒度（43200）的汇总需满足以下条件才执行：
- 系统参数表 `sys_settings` 中 `kpiWeekAndMonthSwitch` 值为 `1`
- 月粒度额外要求：当天（UTC 日期）是本月第 1 天或本月最后一天

### 4.4 运营商过滤规则

与基站维度汇总的规则相同：

1. 从 `operators_info` 表查询所有运营商的编码和时区
2. 将统计结束时间（UTC）转换为各运营商的本地时间
3. 按粒度判断运营商是否到统计时间点：

| 粒度 | 判断条件（运营商本地时间） |
|------|------------------------|
| 15min / 60min | 无限制，所有运营商参与 |
| 1440（天） | 小时数为 0 |
| 10080（周） | 星期一且小时数为 0 |
| 43200（月） | 每月 1 号且小时数为 0 |

未满足条件的运营商，本次不执行组维度汇总。

### 4.5 RPC 手动触发接口

支持通过 RPC 手动触发组维度汇总（仅 ENB/GSM）。

**接口地址：** `POST /rpc/kpiGroupData/triggerStatis`

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| endTime | String | 是 | 统计周期结束时间，格式 `yyyy-MM-dd HH:mm:ss` |
| period | int | 是 | 统计周期分钟数（15/60/1440/10080/43200） |

**返回值：**

```json
{ "success": true, "message": "..." }
```

```json
{ "success": false, "message": "错误原因" }
```

GNB 没有独立的 RPC 触发接口。

## 5. 组维度汇总算法

### 5.1 整体流程

```
1. 计算满足条件的运营商列表（按时区判断）
   ↓
2. 逐运营商处理：
   ↓
   2.1 计算该运营商本次统计的时间范围
   ↓
   2.2 准备设备组映射数据（group_id → group_name）
   ↓
   2.3 执行聚合（ENB 分两批：DEVICE + PLMN；GNB 只一次）
       ↓
       2.3.1 准备指标元数据（从指标定义表加载）
       ↓
       2.3.2 准备聚合分组阶段（group stage）
       ↓
       2.3.3 计算时间分片
       ↓
       2.3.4 查询一级设备组信息
       ↓
       2.3.5 聚合二级组数据
       ↓
       2.3.6 聚合一级组数据
       ↓
       2.3.7 处理结果（单位换算、空值处理、pct 公式计算）
       ↓
       2.3.8 批量 upsert 写入目标表
```

### 5.2 时间范围计算

**统计结束时间（endTime）：** 定时任务触发时取服务器 UTC 时间，秒/毫秒清零。

**统计开始时间（startTime）：**

| 粒度 | startTime 计算方式 |
|------|------------------|
| 15min / 60min / 1440 / 10080 | `endTime - period 分钟` |
| 43200（月） | 将 endTime 转为运营商时区后向前推 1 个自然月，再转回 UTC |

**聚合查询时的时间分片（TimeSegment）：**

聚合查询时，`segmentStart` 和 `segmentEnd` **始终是同一个值**（与 startTime 相同），即聚合查询只匹配 `start_time` 精确等于该时间点的源数据：

| 粒度 | segmentStart = segmentEnd 的计算方式 |
|------|-------------------------------------|
| 15min / 60min / 1440 / 10080 | `endTime - period 分钟` |
| 43200（月） | 将 endTime 转为运营商时区后向前推 1 个自然月，再转回 UTC |

MongoDB 查询条件为 `start_time $gte segmentStart AND start_time $lte segmentEnd`，因为两端相同，实际只匹配精确等于该时间点的数据。

### 5.3 指标元数据准备

**ENB/GSM：**

1. 从 `small_cell.perf_indicators` 查询指标定义
   - 关联 `indicator_unit` 表获取单位
   - 左关联 `indicator_group`（ENB 分组表）和 `indicator_group_gsm`（GSM 分组表），至少命中一张分组表
2. 根据当前聚合级别过滤指标：
   - DEVICE 级聚合：`indicator_level = 'device'` 或 `indicator_level = 'both'`
   - PLMN 级聚合：`indicator_level = 'plmn'`
3. 检查指标的测量定制开关（`enabled_pm_indicators` 表），未启用的指标跳过

**GNB：**

1. 从 `small_cell.gnb_perf_indicators` 查询指标定义
   - 关联 `indicator_unit` 表获取单位
   - 不做级别过滤（GNB 不区分级别）
   - 不检查测量定制开关
2. 将 pct 型指标（`statis_type='pct'` 且 `arithmetic != indicatorId`）分离到单独的 `pctKpiMap`，不参与 MongoDB 聚合阶段

### 5.4 设备组信息准备

为后续聚合结果填充 `group_name`，按当前处理的运营商查询其下属的设备组信息，构建以下映射：

| 映射 | Key | Value | 来源 |
|------|-----|-------|------|
| group_id → group_name | 二级组 ID | 组名称 | `device_group` 表 |
| group_id → operator_name | 二级组 ID | 运营商名称 | `device_group` 关联 `operators_info` |

此映射在运营商循环的外层准备，供后续 DEVICE 和 PLMN 两批聚合共用。

### 5.5 两层聚合算法

聚合使用 MongoDB 的 `$match → $group → $sort` 管道。

#### 5.5.1 二级组聚合

1. 构建 `$match` 条件：
   - `start_time` 在时间分片范围内
   - `group_id` 在该运营商下属的所有二级组 ID 列表中（`$in`，运营商过滤通过限制 group_id 列表隐式实现）
2. 构建 `$group` 阶段：
   - 按 `{groupId: "$group_id", startTime: "$start_time", endTime: "$end_time"}` 分组
   - 对每个指标按其 `statis_type` 聚合：
     - `sum` → `$sum`
     - `avg` → `$avg`
     - `max` → 先 `$convert` 转 decimal 再 `$max`
     - `min` → `$min`
     - `pct` → ENB 使用 `$avg`；GNB 不在此阶段处理
3. `$sort`：按 `startTime 降序, groupId 升序`
4. 结果中补充 `group_name`

#### 5.5.2 一级组聚合

1. 查询所有一级组及其下属二级组列表
2. 对每个一级组：
   - 构建 `$match` 条件：`group_id` 在该一级组下属的所有二级组 ID 中（`$in`）
   - `$group` 按 `{startTime: "$start_time", endTime: "$end_time"}` 分组（不按 group_id 分）
   - 聚合方式与二级组相同
3. 结果中：
   - `group_id` 设为 `top_{一级组id}`
   - `group_name` 设为一级组名称

### 5.6 ENB 两批处理（DEVICE + PLMN）

ENB/GSM 的组维度汇总分两批执行：

**第一批：DEVICE 级**
- 源数据表：设备维度的分表/固定表（见 3.1 节）
- 指标范围：`indicator_level = 'device'` 或 `'both'`（GSM 指标在此处理）
- 目标表：组汇总表（如 `pm_group_hour_yyyy_MM_dd`）

**第二批：PLMN 级**
- 源数据表：PLMN 维度的分表/固定表
- 指标范围：`indicator_level = 'plmn'`
- 目标表：与第一批相同的组汇总表（如 `pm_group_hour_yyyy_MM_dd`）

两批聚合结果写入同一个目标集合，通过 upsert 按不同指标字段共存于同一文档中。

两批共享同一个设备组映射数据（`group_id → group_name`），但独立准备指标列表、独立执行聚合和写入。

### 5.7 GNB 单批处理

GNB 只执行一次聚合，`indicatorLevel` 传 null：

- 源数据表：GNB 专用固定表（如 `gnb_pm_value_60`）
- 指标范围：所有 GNB 指标（不区分级别）
- 目标表：GNB 组汇总表（如 `gnb_pm_group_hour_data`）

### 5.8 pct 指标处理差异

ENB 和 GNB 对 pct 型指标的处理方式不同：

**ENB/GSM：**
- pct 指标参与 MongoDB `$group` 阶段，使用 `$avg` 聚合
- 即对各设备已计算好的 pct 值取平均

**GNB：**
- pct 指标不参与 MongoDB `$group` 阶段，而是从聚合结果中分离
- 先对公式中引用的所有子 counter 按各自的 `statis_type` 完成 MongoDB 聚合
- 聚合完成后，遍历每条结果文档，将 pct 指标的公式（`arithmetic` 字段）中各子 counter 替换为聚合结果值，然后求值计算最终 pct 结果
- 特殊值处理：子 counter 值为空或为 `-` 时结果记为 `-`；计算结果为 Infinity/NaN 时记为 `N/A`

### 5.9 结果处理与写入

聚合完成后，对结果文档做以下处理：

1. **字段重命名：** 将 MongoDB 聚合内部的字段名转为标准字段名（如 `startTime` → `start_time`，`groupId` → `group_id`）
2. **时间字段提取：** 从 `start_time` 提取 UTC 小时数和星期几，写入 `hour` 和 `week` 字段
3. **空值处理：** 指标值为空或 NaN 时写入 `"N/A"`
4. **单位换算：** 对 Decimal128 类型的指标值，根据单位 ID 和统计类型做换算
5. **写入方式：** 批量 upsert，按 `group_id + start_time` 匹配，存在则更新，不存在则插入

### 6.4 查询流程中的 group_id 过滤逻辑

组数据查询时，最终需要将各种过滤条件转化为 `group_id` 的 MongoDB `$in` 过滤条件。处理步骤：

1. **全运营商模板判断：** 如果模板关联了所有运营商，不做 group_id 过滤，直接返回全部数据

2. **有基站编码过滤条件（`small_cell_code`）：**
   - 查询 `rela_device_group_cell` 表，找到这些基站所属的二级组 ID
   - 移除 `small_cell_code` 过滤条件（组维度数据中无此字段）
   - 继续步骤 4

3. **有设备组过滤条件（`group_id`）：**
   - 直接使用传入的组 ID 列表作为二级组 ID
   - 继续步骤 4

4. **补充一级组：** 根据二级组 ID 列表，查询 `top_device_group` 和 `device_group` 的关联关系，找到所属的一级组
5. **合并过滤：** 将二级组 ID 列表和对应的一级组 ID（`top_{id}` 格式）合并为最终的 `group_id $in` 过滤条件

**组名称模糊搜索：**
- 搜索二级组名称：正则匹配 `group_name` 中包含 `/` 且 `/` 之后出现搜索关键词的文档（二级组名称格式为 `一级组名称/二级组名称`，因此用 `/` 区分层级）
- 搜索一级组名称：同时匹配 `group_id` 为 `top_*` 格式**且** `group_name` 包含搜索关键词的文档
- 两个条件为 OR 关系

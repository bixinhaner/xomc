# 日志收集功能设计文档

> **定位**：面向 Go 重构的权威参考文档，描述日志收集的**公共流程**与**平台差异点**。
>
> **文档范围**：仅覆盖 4G/5G 基站（eNB/gNB）的日志收集功能。
>
> **核心设计原则**：立即收集和周期收集共享 80% 以上的校验与下发逻辑，平台差异通过适配器隔离。

---

## 一、日志类型与收集方式

### 1.1 日志类型

| 日志类型 | logType 值 | 支持的收集方式 | 存储目录 |
|---------|-----------|--------------|---------|
| 设备运行日志 | `deviceLog` | 立即收集 + 周期收集 | `.../log/` |
| 安全日志 | `securityLog` | **仅周期收集** | `.../security_log/` |

### 1.2 周期收集的平台支持范围

| 收集类型 | 支持平台 |
|---------|---------|
| 周期收集（设备运行日志） | **5G 基站** + **高通 QAV3/QAV4** |
| 周期收集（安全日志） | **仅高通 QAV3/QAV4** |

> 其他 4G 平台（Intel_CR / 436Q / NEU430 / BAIBLQ / MLQ / MLN / BM 等）**不支持**周期日志收集。

### 1.3 安全日志与设备日志的差异

安全日志**不是独立流程**，与设备日志共用同一套任务表和周期收集流程。差异仅体现在：

| 差异维度 | 设备日志 | 安全日志 |
|----------|---------|---------|
| 收集方式 | 立即 + 周期 | **仅周期** |
| reportPeriod 前端单位 | 分钟 | **小时** |
| 上报 fileType 参数 | `LOG` | `SECURITY_LOG` |
| 文件数量限制 | 受 CollectMaxLogFileNum 限制 | **豁免** |
| 平台支持范围 | 立即收集：全部；周期：5G + QAV3/QAV4 | **仅 QAV3/QAV4** |
| 周期下发间隔值 | 直接使用（秒） | 值 ÷ 3600 后下发（设备侧接受小时） |

## 二、任务状态定义（公共）

立即收集��周期收集共用同一套状态定义。

| 状态值 | 含义 | 适用场景 |
|--------|------|---------|
| 0 | 未开始（已创建，未下发） | 立即 + 周期 |
| 1 | 正在收集中（命令已下发） | 立即 + 周期 |
| 2 | 收集完成 | 立即 + 周期 |
| 3 | 收集失败（超时/错误/离线） | 立即 + 周期 |
| 4 | 收集终止（用户手动停止） | 立即 + 周期 |
| 5 | 等待文件上传（Upload 已响应，等文件到达） | 仅立即 |
| 6 | 已结束（用户终止周期上报，SetParam 成功） | 仅周期 |
| 7 | 停止失败（停止 SetParam 返回错误） | 仅周期 |

## 三、公共校验逻辑

以下校验逻辑被立即收集和周期收集**共同使用**，是重构的核心公共代码。

### 3.1 请求层校验

| 校验项 | 逻辑 | 失败处理 |
|--------|------|---------|
| 磁盘使用率 | Redis `disk_usage:run_log` ≥ 90% | 返回 901「磁盘空间不足」 |

### 3.2 业务层校验（任务创建前）

| 校验项 | 逻辑 | 适用场景 | 失败处理 |
|--------|------|---------|---------|
| 重复任务 | 同设备同类型 status 0/1 已存在 | 仅立即收集 | 返回 401 |
| 文件数量上限 | 已有文件数 ≥ CollectMaxLogFileNum | 仅立即收集 | 返回 901 |

### 3.3 执行层校验（命令下发前，公共）

以下校验在立即收集和周期收集的执行线程中**完全相同**：

| 校验项 | 逻辑 | 失败处理 |
|--------|------|---------|
| 终止标志（仅立即） | 内存 ImmediateCollectLogTaskFlag | 状态 4（终止） |
| 操作权限 | featureCode 用户授权（4G/5G 各有功能码） | 状态 3（失败） |
| 设备在线 | Redis 设备缓存 | 状态 3（失败） |

### 3.4 执行层校验（周期收集额外项）

| 校验项 | 逻辑 | 失败处理 |
|--------|------|---------|
| 任务状态 | status 5/6（已终止）→ 跳过 | 跳过此设备 |
| 平台兼容性 | 仅 5G 基站和高通 QAV3/QAV4 支持周期日志，其他平台直接失败 | 状态 3 |
| 安全日志平台 | logType=securityLog 且非 QAV3/QAV4 → 失败 | 状态 3 |

## 四、立即收集流程

> 立即收集仅支持**设备运行日志**（deviceLog），安全日志不支持立即收集。

### 4.1 任务创建（公共）

```
前端请求参数：
  serial_number    设备序列号（逗号分隔，支持批量）
  device_code      设备编码
  device_type      eNB（4G）/ gNB（5G）
  isGnb            1=5G / 0=4G
  logType          deviceLog
  execute_type     Immediately（立即）

处理流程：
  ① 请求层校验（磁盘使用率）
  ② 业务层校验（重复任务 + 文件数量上限）
  ③ 写入 log_device_report 表
     若同设备已有已结束任务（状态 2/3/4/6/7/8）→ 复用记录（更新状态为 0）
     否则 → 新建记录
  ④ 投递 immediateCollectLogFile 到实时队列
     → 返回 200 给前端（异步执行，不阻塞响应）
```

### 4.2 TR069 交互流程（公共）

队列被执行线程消费，每台设备独立处理：

```
┌─ 执行层校验 ──────────────────────────────────────┐
│  ① 终止标志检查                                     │
│  ② 操作权限校验                                     │
│  ③ 设备在线检查                                     │
└─────────────────────────────────────────────────────┘
  │ 校验通过，状态 → 1（正在收集）
  │
  ▼
【第一次报文】Upload Request（OMC → 设备）

  构造上传 URL（见 4.3 URL 构造规则）

  TR069 Upload 报文：
  ┌──────────────┬──────────────────────────────────┐
  │ FileType      │ "4 Vendor Log File 1,2,3,4"      │
  │               │ 或 "2 Vendor Log File"            │
  │ URL           │ 构造的上传地址                     │
  │ CommandKey    │ "Collect LOG,{uuid}"              │
  └──────────────┴──────────────────────────────────┘

  等待 Upload Response（超时 = enbTimeout 秒）：
    无响应 → 状态 3，超时
    FaultCode → 状态 3，失败
    成功 → 继续

  ▼
【第二次报文】TransferComplete（设备 → OMC）

  设备打包日志并上传到 OMC 文件服务，上传完成后通知：
  ┌──────────────┬──────────────────────────────────┐
  │ CommandKey    │ "Collect LOG,{uuid}"（匹配上次）   │
  │ FaultCode     │ 0=成功 / 错误码                   │
  └──────────────┴──────────────────────────────────┘

  等待 TransferComplete（超时 = enbTimeout 秒）：
    无响应 → 状态 3，超时
    FaultCode → 状态 3，失败
    成功 → 文件服务接收文件
           → 写入 log_device_report_file 表
           → 状态 → 2（收集完成）
           → 更新消息中心为成功
```

### 4.3 上传 URL 构造规则

| 平台 | URL 模式 |
|------|---------|
| 通用（4G/5G 基站） | `{fileuploadRootUrl}/FileUploadService?fileType=LOG&taskId={taskId}&filename=` |

### 4.4 FileType 字段

| 平台 | FileType 值 |
|------|------------|
| 普通 4G 基站 | `"4 Vendor Log File 1,2,3,4"` |
| 5G（BaiBNX/BaiBNQ/中国电信） | `"2 Vendor Log File"` |

> **重构建议**：URL 构造和 FileType 映射是仅有的两个平台差异点，应通过适配器隔离。

### 4.5 停止立即收集

```
在内存中为该 taskId 添加终止标志
→ 数据库任务状态更新为 4（终止）
→ 广播刷新页面消息
```

## 五、周期日志流程

> 周期收集支持**设备运行日志**和**安全日志**。
> - 设备运行日志：5G 基站 + 高通 QAV3/QAV4 支持
> - 安全日志：仅高通 QAV3/QAV4 支持

### 5.1 任务调度（公共）

```
前端设置：上报周期、起止时间、日志类型（deviceLog / securityLog）→ 提交请求

处理流程：
  ① 磁盘使用率校验

  ② 安全日志单位转换（仅 logType=securityLog）：
     reportPeriod 小时 × 3600 → 秒

  ③ 起止时间策略判断：
     startTime > 当前时间 → 创建定时开始任务（到时投队列，isEnableReport=yes）
     startTime ≤ 当前时间 → 直接投队列（isEnableReport=yes）
     endTime > 当前时间   → 创建定时结束任务（到时投队列，endReport=yes）

  ④ 写入 log_period_report_task 表
     → 返回 200
```

### 5.2 TR069 交互流程（公共）

```
┌─ 执行层校验 ──────────────────────────────────────┐
│  ① 任务状态检��（5/6 已终止 → 跳过）                │
│  ② 操作权限校验                                     │
│  ③ 设备在线检查                                     │
│  ④ 平台兼容性校验：                                  │
│     设备运行日志：仅 5G + QAV3/QAV4 支持             │
│     安全日志：仅 QAV3/QAV4 支持                      │
└─────────────────────────────────────────────────────┘
  │ 校验通过
  │ 从参数映射缓存获取该平台的 TR069 私有参数路径：
  │   • 使能开关路径
  │   • 日志上传 URL 路径
  │   • 上传间隔路径
  │ （安全日志使用固定专属路径，不走通用参数映射）
  │
  ▼
【核心报文】SetParameterValues（OMC → 设备）

  启用时（isEnableReport = "yes"）：
  ┌──────────────┬───────────────────────────────────┐
  │ 使能开关       │ "1"                                │
  │ URL           │ .../FileUploadService?fileType=LOG  │
  │               │ 安全日志：fileType=SECURITY_LOG      │
  │ 间隔           │ reportPeriod（秒）                  │
  │               │ 安全日志：值 ÷ 3600（设备接受小时）    │
  └──────────────┴───────────────────────────────────┘

  停用时（isEnableReport = "no"）：
  ┌──────────────┬───────────────────────────────────┐
  │ 使能开关       │ "0"                                │
  └──────────────┴───────────────────────────────────┘

  等待 SetParameterValuesResponse（超时 = enbTimeout 秒）：
    无响应 → 状态 3，超时
    FaultCode（启用时）→ 状态 3，失败
    FaultCode（停用时）→ 状态 7（停止失败）
    成功（启用）→ 状态 1（进行中）
    成功（停用，定时到期 endReport=yes）→ 状态 2（已完成）
    成功（停用，用户手动终止）→ 状态 6（已结束）
```

**SetParam 成功后**：设备按配置间隔，通过 HTTP 主动上传日志到 FileUploadService，OMC 接收后写入 `log_period_report_record` 表。

### 5.3 停止周期上报

```
用户点击"停止上报"：
  ① 删除未触发的定时任务
  ② 数据���状态 → 4（终止）
  ③ 投递 periodReportLogFile（isEnableReport=no）到队列
     → 执行线程向设备下发 SetParameterValues（使能开关="0"）
```

## 六、平台差异汇总

### 6.1 立即收集的平台差异

| 差异维度 | 差异内容 | 涉及平台 |
|----------|---------|---------|
| FileType 字段 | `"4 Vendor Log File 1,2,3,4"` vs `"2 Vendor Log File"` | 普通 4G vs 5G |

> **公共占比约 95%**：FileType 映射是唯一差异点。

### 6.2 周期收集的平台差异

| 差异维度 | 差异内容 | 涉及平台 |
|----------|---------|---------|

| 安全日志 | 仅 QAV3/QAV4 支持 | 高通平台 |

| 安全日志参数路径 | 固定专属路径，不走通用映射 | 安全日志 |
| 间隔值转换 | 安全日志值 ÷ 3600 | 安全日志 |

> **公共占比约 80%**：参数路径映射和平台兼容性判断是主要差异点。

## 八、安全日志特殊处理链路

安全日志**仅支持周期收集**，完整追踪在每个环节的特殊处理：

| 环节 | 处理逻辑 |
|------|---------|
| 前端传参 | `reportPeriod` 单位为**小时** |
| 请求层 | 直接透传，不转换 |
| 业务层（任务创建） | 小时 × 3600 → 秒，写库 |
| 业务层（任务列表展示） | 秒 ÷ 3600 → 小时，返回前端 |
| 业务层（文件数量校验） | **不涉及**（安全日志无立即收集） |
| 执行层（平台校验） | 仅 QAV3/QAV4 支持，其他标记失败 |
| 执行层（参数路径） | 使用固定专属路径，不走通用参数映射 |
| 执行层（fileType 参数） | `SECURITY_LOG`（非 `LOG`） |
| 执行层（周期间隔下发） | 值 ÷ 3600 得小时值下发（设备侧接受小时） |
| 文件存储 | 保存到 `.../security_log/` 目录 |

## 十、重构架构建议

### 10.1 公共/差异分层

```
┌───────────────────────────────────────────────────┐
│  日志收集管理层（公共）                              │
│  创建任务 / 查询进度 / 停止收集 / 查询文件列表       │
└──────────────────┬────────────────────────────────┘
                   │
┌──────────────────▼────────────────────────────────┐
│  公共校验管道                                       │
│  磁盘 → 重复任务 → 文件数量                         │
└──────────────────┬────────────────────────────────┘
                   │
  ┌────────────────┴────────────────┐
  ▼                                 ▼
┌─────────────────────┐  ┌──────────────────────────┐
│  立即收集执行器       │  │  周期收集执行器            │
│  仅 deviceLog        │  │  deviceLog + securityLog  │
│  公共校验 → Upload   │  │  公共校验 + 平台兼容性     │
│  → TransferComplete  │  │  → [GetValues] → SetValues│
│  → 文件接收          │  │  → 设备主动上报            │
└─────────────────────┘  └──────────────────────────┘
         │                          │
         └──────────┬───────────────┘
                    ▼
         ┌─────────────────────┐
         │  平台适配器           │
         │  getUploadUrl()      │
         │  getFileType()       │
         │  getParamPaths()     │
         │  isPeriodicSupported()│
         └─────────────────────┘
```

### 10.2 对齐现有代码模式

| 设计要素 | 对齐的现有模式 | 说明 |
|----------|---------------|------|
| 命令下发 | acs/cmdqueue 的 Command + Push | Upload / SetParameterValues 统一走命令队列 |
| 事件监听 | EventBus.Subscribe | TransferComplete 事件驱动，非轮询 |
| 平台差异 | Carrier 接口适配器 | URL/FileType/参数路径通过适配器获取 |
| 安全日志差异 | 参数化处理 | logType 作为参数传递，而非 if 分支 |
| 任务状态机 | software/state_machine.go 的 validTransitions | 状态转换有明确规则 |

### 10.3 与升级流程的模式复用

日志收集和设备升级在 TR069 层面有高度相似性：

| 模式 | 升级流程 | 立即收集 | 周期收集 |
|------|---------|---------|---------|
| 命令类型 | Download | Upload | SetParameterValues |
| 等待响应 | DownloadResponse | UploadResponse | SetParameterValuesResponse |
| 异步完成通知 | TransferComplete | TransferComplete | 设备主动 HTTP 上报 |
| 超时处理 | enbTimeout 统一 | enbTimeout 统一 | enbTimeout 统一 |
| 错误处理 | FaultCode → 失败 | FaultCode → 失败 | FaultCode → 失败 |

> **建议**：提取公共的「TR069 命令执行 + 等待响应」模式为通用组件，升级/日志/备份等功能共用。

### 10.4 公共代码占比估算

| 模块 | 公共占比 | 差异点 |
|------|----------|--------|
| 请求层校验（磁盘） | **100%** | 无差异 |
| 业务层校验 | **95%** | 安全日志无立即收集，无需文件数量校验 |
| 任务创建与管理 | **100%** | 无差异（logType 参数化） |
| 执行层公共校验（权限+在线） | **100%** | 无差异 |
| 立即收集 TR069 交互 | **95%** | FileType 映射 |

# 日志收集功能设计文档

> **定位**：面向 Go 重构的权威参考文档，描述日志收集的**公共流程**与**平台差异点**。
>
> **核心设计原则**：立即收集和周期收集共享 80% 以上的校验与下发逻辑，平台差异通过适配器隔离。

---

## 一、日志类型

| 日志类型 | logType 值 | 触发方式 | 存储目录 |
|---------|-----------|---------|---------|
| 设备运行日志 | `deviceLog` | 立即 / 周期 | `.../log/` |
| 安全日志 | `securityLog` | 立即 / 周期 | `.../security_log/` |
| 周期日志（eNB 专属） | — | 仅周期 | `.../log/` |

**关键认识**：安全日志**不是独立流程**，与设备日志共用同一套任务表和收集流程。差异仅体现在以下几点（后文会在每个环节标注）：

| 差异维度 | 设备日志 | 安全日志 |
|----------|---------|---------|
| reportPeriod 前端单位 | 分钟 | **小时** |
| 上报 fileType 参数 | `LOG` | `SECURITY_LOG` |
| 文件数量限制 | 受 CollectMaxLogFileNum 限制 | **豁免** |
| 平台支持范围 | 全部 | **仅高通 QAV3/QAV4** |
| 周期下发间隔值 | 直接使用（秒） | 值 ÷ 3600 后下发（设备侧接受小时） |

## 二、任务状态定义（公共）

立即收集和周期收集共用同一套��态定义。

| 状态值 | 含义 | 适用场景 |
|--------|------|---------|
| 0 | 未开始（已创建，未下发） | 立即 + 周期 |
| 1 | 正在收集中（命令已下发） | 立即 + 周期 |
| 2 | 收集完成 | 立即 + 周期 |
| 3 | 收集失败（超时/错误/离线） | 立即 + 周期 |
| 4 | 收集终止（用户手动停止） | 立即 + 周期 |
| 5 | 等待文件上传（Upload 已响应，等文件到达） | 仅立即 |
| 6 | 已结束（用户终止周期上报，SetParam 成功） | 仅周期 |
| 7 | 停止失败（停止 SetParam 返回错误） | 仅周期 |
| 8 | 等待重启（DXDF 平台需重启生效） | 仅周期 |

## 三、公共校验逻辑

以下校验逻辑被立即收集和周期收集**共同使用**，是重构的核心公共代码。

### 3.1 请求层校验

| 校验项 | 逻辑 | 失败处理 |
|--------|------|---------|
| 磁盘使用率 | Redis `disk_usage:run_log` ≥ 90% | 返回 901「磁盘空间不足」 |

### 3.2 业务层校验（任务创建前）

| 校���项 | 逻辑 | 适用场景 | 失败处理 |
|--------|------|---------|---------|
| 重复任务 | 同设备同类型 status 0/1 已存在 | 仅立即收集 | 返回 401 |
| 安全日志单位转换 | reportPeriod 小时 × 3600 → 秒 | 安全日志 | — |
| 文件数量上限 | 已有文件数 ≥ CollectMaxLogFileNum | 仅立即收集（安全日志豁免） | 返回 901 |

### 3.3 执行层校验（命令下发前，公共）

以下校验在立即收集和周期收集的执行线程中**完全相同**：

| 校验项 | 逻辑 | 失败处理 |
|--------|------|---------|
| 终止标志（仅立即） | 内存 ImmediateCollectLogTaskFlag | 状态 4（终止） |
| 操作权限 | featureCode 用户授权（4G/5G/CPE/EGW 各有功能码） | 状态 3（失败） |
| 设备在线 | Redis 设备缓存 | 状态 3（失败） |

### 3.4 执行层校验（周期收集额外项）

| 校验项 | 逻辑 | 失败处理 |
|--------|------|---------|
| 任务状态 | status 5/6（已终止）→ 跳过 | 跳过此设备 |
| 平台兼容性 | Intel_CR / 436Q / NEU430 / BAIBLQ / MLQ / MLN / BM 等不支持周期日志 | 状态 3 |
| 安全日志平台 | logType=securityLog 且非 QAV3/QAV4 | 状态 3 |

## 四、立即收集流程

### 4.1 任务创建（公共）

```
前端请求参数：
  serial_number    设备序��号（逗号分隔，支持批量）
  device_code      设备编码
  device_type      eNB / EGW / CPE
  isGnb            1=5G / 0=4G
  logType          deviceLog / securityLog
  execute_type     Immediately / timing（CPE 定时）
  reportPeriod     安全日志专用（前端单位：小时）
  start_time/end_time  CPE 定时收集时使用

处理流程：
  ① 请求层校验（磁盘使用率）
  ② 业务层校验（重复任务 + 安全日志单位转换 + 文件数量上限）
  ③ 写入 log_device_report 表
     若同设备已有已结束任务（状态 2/3/4/6/7/8）→ 复用记录（更新状态为 0）
     否则 → 新建记录
  ④ 投递 immediateCollectLogFile 到实时队列
     → 返回 200 给前端（异步执行，不阻塞响应）
```

> **CPE 定时收集特殊**：不直接投队列，通过定时任务（Quartz / 调度器）延时触发。

### 4.2 TR069 交互流程（公共）

队列被执行线程消费，每台设备独立处理：

```
┌─ 执行层校验 ──────────────────────────────────────┐
│  ① 终止标志检查                                     │
│  ② 操作权限校验                                     │
│  ③ 设备在线检查                                     │
└─────────────────────────────────────────────────────┘
  │ 校验通过，状态 → 1（正在收集）
  │
  ▼
【第一次报文】Upload Request（OMC → 设备）

  构造上传 URL（见 4.3 URL 构造规则）

  TR069 Upload 报文：
  ┌──────────────┬──────────────────────────────────┐
  │ FileType      │ "4 Vendor Log File 1,2,3,4"      │
  │               │ 或 "2 Vendor Log File"            │
  │ URL           │ 构造的上传地址                     │
  │ CommandKey    │ "Collect LOG,{uuid}"              │
  └──────────────┴──────────────────────────────────┘

  等待 Upload Response（超时 = enbTimeout 秒）：
    无响应 → 状态 3，超时
    FaultCode → 状态 3，失败
    成功 → 继续

  ▼
【第二次报文】TransferComplete（设备 → OMC）

  设备打包日志并上传到 OMC 文件服务，上传完成后通知：
  ┌──────────────┬──────────────────────────────────┐
  │ CommandKey    │ "Collect LOG,{uuid}"（匹配上次）   │
  │ FaultCode     │ 0=成功 / 错误码                   │
  └──────────────┴──────────────────────────────────┘

  等待 TransferComplete（超时 = enbTimeout 秒）：
    无响应 → 状态 3，超时
    FaultCode → 状态 3，失败
    成功 → 文件服务接收文件
           → 写入 log_device_report_file 表
           → 状态 → 2（收集完成）
           → 更新消息中心为成功
```

### 4.3 上传 URL 构造规则

| 设备类型/平台 | URL 模式 |
|--------------|---------|
| 普通/5G 基站 | `{fileuploadRootUrl}/FileUploadService?fileType=LOG&taskId={taskId}&filename=` |
| DXDF 平台 | `{fileuploadRootUrl}/YDFileUploadService/upload/log/logFile?fileType=LOG&taskId={taskId}&filename=` |
| CPE | `{fileuploadPath}/FileUploadService?fileType=LOG&taskId={taskId}&filename={自动生成文件名}` |
| 安全日志 | 同上述规则，但 fileType=**SECURITY_LOG** |

### 4.4 FileType 字段

| 设备类型/平台 | FileType 值 |
|--------------|------------|
| 普通 4G 基站 | `"4 Vendor Log File 1,2,3,4"` |
| DXDF / CPE / 5G（BaiBNX/BaiBNQ/中国电信） | `"2 Vendor Log File"` |

> **重构建议**：URL 构造和 FileType 映射是仅有的两个平台差异点，应通过适配器隔离。

### 4.5 停止立即收集

| 场景 | 处理 |
|------|------|
| 立即收集（execute_type=Immediately） | 内存设置终止标志 + 状态 → 4 + 广播刷新 |
| 定时收集（CPE） | 删除定时 Job + 状态 → 4 + 投递关闭命令到队列 |

## 五、周期日志流程

### 5.1 任务调度（公共）

```
前端设置：上报周期、起止时间 → 提交请求

处理流程：
  ① 磁盘使用率校验

  ② 起止时间策略判断：
     startTime > 当前时间 → 创建定时开始任务（到时投队列，isEnableReport=yes）
     startTime ≤ 当前时间 → 直接投队列（isEnableReport=yes）
     endTime > 当前时间   → 创建定时结束任务（到时投队列，endReport=yes）

  ③ 写入 log_period_report_task 表
     → 返回 200
```

### 5.2 TR069 交互流程（公共）

```
┌─ 执行层校验 ──────────────────────────────────────┐
│  ① 任务状态检查（5/6 已终止 → 跳过）                │
│  ② 操作权限校验                                     │
│  ③ 设备在线检查                                     │
│  ④ 平台兼容性校验（见第三章 3.4）                    │
└─────────────────────────────────────────────────────┘
  │ 校验通过
  │ 从参数映射缓存获取该平台的 TR069 私有参数路径：
  │   • 使能开关路径
  │   • 日志上传 URL 路径
  │   • 上传间隔路径
  │ （安全日志使用固定专属路径，不走通用参数映射）
  │
  ├─ [仅 DXDF 平台] 可选：先 GetParameterValues 查询当前值
  │   与目标值完全一致 → 跳过下发
  │
  ▼
【核心报文】SetParameterValues（OMC → 设备）

  启用时（isEnableReport = "yes"）：
  ┌──────────────┬───────────────────────────────────┐
  │ 使能开关       │ "1"                                │
  │ URL           │ .../FileUploadService?fileType=LOG  │
  │               │ 安全日志：fileType=SECURITY_LOG      │
  │               │ DXDF：/YDFileUploadService/...       │
  │ 间隔           │ reportPeriod（秒）                  │
  │               │ 安全日志：值 ÷ 3600（设备接受小时）    │
  └──────────────┴───────────────────────────────────┘

  停用时（isEnableReport = "no"）：
  ┌──────────────┬───────────────────────────────────┐
  │ 使能开关       │ "0"                                │
  └──────────────┴───────────────────────────────────┘

  等待 SetParameterValuesResponse（超时 = enbTimeout 秒）：
    无响应 → 状态 3，超时
    FaultCode（启用时）→ 状态 3，失败
    FaultCode（停用时）→ 状态 7（停止失败）
    成功（启用）→ DXDF 等需重启平台：状态 8；其他：状态 1
    成功（停用，定时到期 endReport=yes）→ 状态 2（已完成）
    成功（停用，用户手动终止）→ 状态 6（已结束）
```

**SetParam 成功后**：设备按配置间隔，通过 HTTP 主动上传日志到 FileUploadService，OMC 接收后写入 `log_period_report_record` 表。

### 5.3 停止周期上报

```
用户点击"停止上报"：
  ① 删除未触发的定时任务
  ② 数据库状态 → 4（终止）
  ③ 投递 periodReportLogFile（isEnableReport=no）到队列
     → 执行线程向设备下发 SetParameterValues（使能开关="0"）
```

## 六、平台差异汇总

### 6.1 立即收集的平台差异

| 差异维度 | 差异内容 | 涉及平台 |
|----------|---------|---------|
| 上传 URL 路径 | DXDF 使用 `/YDFileUploadService/...` | DXDF |
| 上传 URL 文件名 | CPE 自动生成文件名 | CPE |
| FileType 字段 | `"4 Vendor Log File 1,2,3,4"` vs `"2 Vendor Log File"` | 普通 4G vs 其他 |
| fileType 参数 | `LOG` vs `SECURITY_LOG` | 安全日志 |

> **公共占比约 90%**：URL 构造和 FileType 映射是唯一差异点。

### 6.2 周期收集的平台差异

| 差异维度 | 差异内容 | 涉及平台 |
|----------|---------|---------|
| 不支持周期日志 | Intel_CR / 436Q / NEU430 / BAIBLQ / MLQ / MLN / BM | 多个 4G 平台 |
| 安全日志仅支持 | QAV3 / QAV4 | 高通平台 |
| TR069 参数路径 | 各平台私有路径不同 | 全部（通过参数映射） |
| 安全日志参数路径 | 固定专属路径，不走通用映射 | 安全日志 |
| 间隔值转换 | 安全日志值 ÷ 3600 | 安全日志 |
| 预查询（GetValues） | DXDF 先查询，一致则跳过 | DXDF |
| 需重启生效 | SetParam 成功后需重启 | DXDF |
| 上传 URL 路径 | DXDF 使用 `/YDFileUploadService/...` | DXDF |

> **公共占比约 75%**：参数路径映射和平台兼容性判断是主要差异点。

## 八、安全日志特殊处理链路

完整追踪安全日志在每个环节的特殊处理，方便重构时统一适配：

| 环节 | 处理逻辑 |
|------|---------|
| 前端传参 | `reportPeriod` 单位为**小时** |
| 请求层 | 直接透传，不转换 |
| 业务层（任务创建） | 小时 × 3600 → 秒，写库 |
| 业务层（任务列表展示） | 秒 ÷ 3600 → 小时，返回前端 |
| 业务层（文件数量校验） | **跳过**，不受限 |
| 执行层（平台校验） | 仅 QAV3/QAV4 支持，其他标记失败 |
| 执行层（参数路径） | 使用固定专属路径，不走通用参数映射 |
| 执行层（fileType 参数） | `SECURITY_LOG`（非 `LOG`） |
| 执行层（周期间隔下发） | 值 ÷ 3600 得小时值下发（设备侧接受小时） |
| 文件存储 | 保存到 `.../security_log/` 目录 |

## 十、重构架构建议

### 10.1 公共/差异分层

```
┌───────────────────────────────────────────────────┐
│  日志收集管理层（公共）                              │
│  创建任务 / ��询进度 / 停止收集 / 查询文件列表       │
└──────────────────┬────────────────────────────────┘
                   │
┌──────────────────▼────────────────────────────────┐
│  公共校验管道                                       │
│  磁盘 → 重复任务 → 文件数量 → 安全日志单位转换       │
│  ↓ 安全日志差异通过 logType 参数化，无需 if 分支     │
└──────────────────┬────────────────────────────────┘
                   │
  ┌────────────────┴────────────────┐
  ▼                                 ▼
┌─────────────────────┐  ┌──────────────────────────┐
│  立即收集执行器       │  │  周期收集执行器            │
│  公共校验 → Upload   │  │  公共校验 + 平台兼容性     │
│  → TransferComplete  │  │  → [GetValues] → SetValues│
│  → 文件接收          │  │  → 设备主动上报            │
└─────────────────────┘  └──────────────────────────┘
         │                          │
         └──────────┬───────────────┘
                    ▼
         ┌─────────────────────┐
         │  平台适配器           │
         │  getUploadUrl()      │
         │  getFileType()       │
         │  getParamPaths()     │
         │  isSupported()       │
         │  needReboot()        │
         └─────────────────────┘
```

### 10.2 对齐现有代码模式

| 设计要素 | 对齐的现有模式 | 说明 |
|----------|---------------|------|
| 命令下发 | acs/cmdqueue 的 Command + Push | Upload / SetParameterValues 统一走命令队列 |
| 事件监听 | EventBus.Subscribe | TransferComplete 事件驱动，非轮询 |
| 平台差异 | Carrier 接口适配器 | URL/FileType/参数路径通过适配器获取 |
| 安全日志差异 | 参数化处理 | logType 作为参数传递，而非 if 分支 |
| 任务状态机 | software/state_machine.go 的 validTransitions | 状态转换有明确规则 |

### 10.3 与升级流程的模式复用

日志收集和设备升级在 TR069 层面有高度相似性：

| 模式 | 升级流程 | 立即收集 | 周期收集 |
|------|---------|---------|---------|
| 命令类型 | Download | Upload | SetParameterValues |
| 等待响应 | DownloadResponse | UploadResponse | SetParameterValuesResponse |
| 异步完成通知 | TransferComplete | TransferComplete | 设备主动 HTTP 上报 |
| 超时处理 | enbTimeout 统一 | enbTimeout 统一 | enbTimeout 统一 |
| 错误处理 | FaultCode → 失败 | FaultCode → 失败 | FaultCode → 失败 |

> **建议**：提取公共的「TR069 命令执行 + 等待响应」模式为通用组件，升级/日志/备份等功能共用。

### 10.4 公共代码占比估算

| 模块 | 公共占比 | 差异点 |
|------|----------|--------|

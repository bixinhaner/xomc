## 1. 文档概述

### 1.1 编写目的

本文档详细定义系统管理模块的数据库表结构，包括字段名、数据类型、字段说明、约束条件及索引设计，为数据库开发、数据迁移、接口对接提供统一规范。

### 1.2 适用范围

本文档适用于以下数据库表的创建与维护：
- 用户管理相关表
- 部门管理相关表
- 角色与权限管理相关表
- 日志管理相关表
- 字典管理相关表
- 参数管理相关表
- 国际化管理相关表
- 租户管理相关表（预留）

### 1.3 设计原则

1. **规范性**：表名、字段名采用小写+下划线命名方式
2. **完整性**：主键、外键、唯一约束、非空约束完整定义
3. **可追溯**：所有表包含创建时间、更新时间、创建人、更新人字段
4. **扩展性**：预留扩展字段，支持后续业务扩展

## 2. 用户管理相关表

### 2.1 用户表（sys_user）

| 字段名          | 数据类型     | 字段说明     | 约束                        | 备注                            |
| --------------- | ------------ | ------------ | --------------------------- | ------------------------------- |
| id              | BIGINT       | 用户ID       | PRIMARY KEY, AUTO_INCREMENT | 自增主键                        |
| username        | VARCHAR(64)  | 用户名       | UNIQUE NOT NULL             | 登录账号                        |
| password        | VARCHAR(128) | 密码         | NOT NULL                    | BCrypt加密存储                  |
| email           | VARCHAR(128) | 邮箱         | NULL                        | 格式校验                        |
| phone           | VARCHAR(20)  | 手机号       | NULL                        | 格式校验                        |
| department_id   | BIGINT       | 部门ID       | NULL                        | 关联sys_department.id           |
| avatar          | VARCHAR(256) | 头像URL      | NULL                        | -                               |
| source          | VARCHAR(32)  | 登录来源     | NULL                        | 如：PC、APP                     |
| expire_time     | DATETIME     | 过期时间     | NULL                        | NULL表示永不过期                |
| status          | TINYINT      | 状态         | NOT NULL DEFAULT 1          | 0-禁用 1-启用                   |
| last_login_time | DATETIME     | 最近登录时间 | NULL                        | -                               |
| last_login_ip   | VARCHAR(50)  | 最近登录IP   | NULL                        | -                               |
| create_time     | DATETIME     | 创建时间     | NOT NULL                    | 默认CURRENT_TIMESTAMP           |
| update_time     | DATETIME     | 更新时间     | NOT NULL                    | 默认CURRENT_TIMESTAMP ON UPDATE |
| create_by       | VARCHAR(64)  | 创建人       | NOT NULL                    | 关联sys_user.username           |
| update_by       | VARCHAR(64)  | 更新人       | NOT NULL                    | 关联sys_user.username           |
| remark          | VARCHAR(512) | 备注         | NULL                        | -                               |

**索引设计：**
- PRIMARY KEY (`id`)
- UNIQUE KEY `uk_username` (`username`)
- KEY `idx_department_id` (`department_id`)
- KEY `idx_status` (`status`)
- KEY `idx_create_time` (`create_time`)

数据权限实例

组合方式配置:
  - 模式: 严格模式
    规则: 必须同时满足 network_type 和 device_group
    场景: 高安全性要求
    
  - 模式: 宽松模式  
    规则: 满足 network_type 或 device_group 任一即可
    场景: 普通运维场景
    
  - 模式: 混合模式
    规则: 按设备类型分别配置
    示例: 2G设备按device_group控制，5G设备全放开



SELECT 字段列表 
FROM device_info 
WHERE is_delete = 0
  AND ( -- 网络类型权限过滤
        network_type IN (用户允许的网络类型列表)
        OR 用户拥有ALL网络类型权限
      )
  AND ( -- 设备组权限过滤
        device_group IN (用户允许的设备组列表)
        OR 用户拥有ALL设备组权限
        OR 用户没有配置设备组权限（忽略此条件）
      )
  AND ( -- 根据组合规则进行最终过滤
        组合规则 = 'AND' ? (满足网络类型条件 AND 满足设备组条件)
        : 组合规则 = 'OR' ? (满足网络类型条件 OR 满足设备组条件)
        : 按业务规则判断
      )

**操作前校验流程：**

1. **Step 1**：获取目标设备信息（network_type、device_group）
2. **Step 2**：获取当前用户权限列表
3. **Step 3**：网络类型校验
   - 若用户无网络类型权限 → 拒绝
4. **Step 4**：设备组校验
   - 若用户有设备组权限配置
     - 检查设备组是否在允许列表中 → 拒绝/通过
   - 若用户无设备组权限配置
     - 忽略设备组校验
5. **Step 5**：根据组合规则综合判断
   - AND模式：需同时通过Step3和Step4
   - OR模式：通过Step3或Step4任一即可

| 用户A  | 2G           | -              | 忽略设备组   | 所有2G设备                |

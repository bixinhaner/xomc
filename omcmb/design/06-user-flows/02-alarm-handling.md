# 用户流程: 告警处理 (Alarm Handling)

> OMC 统一网管系统 - 用户流程

## 概述

告警处理是网管系统最关键的日常运维流程。从告警产生到处理完毕的完整闭环，包括告警发现、详情查看、确认处理、纠正操作和告警清除。

## 详细步骤

### 步骤 1: 告警产生

```
触发:
  - 设备侧检测到异常 → 上报告警到 OMC 系统
  - 告警通过 SNMP Trap / 北向接口 / WebSocket 送达

系统行为:
  - 告警入库 (当前告警表)
  - 触发实时推送 (WebSocket)
  - 更新 Dashboard 告警计数
  - 更新 Header 告警铃铛 Badge
```

### 步骤 2: 发现告警

```
用户发现告警的途径:

途径 A - Dashboard:
  ┌──────────────────────┐
  │ 告警概览              │
  │ 紧急: 2  重要: 15    │  ← 数字变化 + 闪烁
  │ 一般: 45  提示: 12    │
  └──────────────────────┘
  点击数字 → 跳转到对应级别的告警列表

途径 B - 当前告警列表:
  - 新告警实时出现在列表顶部 (WebSocket 推送)
  - 新行伴随黄色高亮闪烁动画 (2s)
  - 表格自动刷新, 不影响用户当前操作

途径 C - Header 告警铃铛:
  ┌─────────┐
  │ 🔔 ²    │  ← 红色 Badge (未确认告警数)
  └─────────┘
  点击铃铛 → 弹出最近告警 Popover:
  ┌──────────────────────────────────┐
  │ 最新告警                         │
  ├──────────────────────────────────┤
  │ 🔴 CELL_UNAVAILABLE             │
  │    eNodeB-001  2分钟前           │
  │ 🟡 HIGH_CPU_USAGE                │
  │    gNodeB-003  5分钟前           │
  │ 🟡 LINK_DEGRADATION              │
  │    eNodeB-005  12分钟前          │
  ├──────────────────────────────────┤
  │ [查看全部告警]                    │
  └──────────────────────────────────┘

途径 D - 声音/浏览器通知 (可选):
  - 紧急告警: 播放告警音效 (需用户开启)
  - 浏览器 Notification: 即使不在 OMC Tab 也能看到
```

### 步骤 4: 确认告警

```
操作:

单条确认:
  - 告警详情 Drawer → [确认告警] 按钮
  - 或告警列表操作列 → [确认] 按钮
  - 确认后: 告警状态变为 "已确认", 按钮变灰

批量确认:
  - 告警列表选中多条 → 工具栏 [批量确认]
  - 确认对话框: "确定要确认选中的 {N} 条告警吗?"
  - 确认后: 所有选中告警状态变为 "已确认"

确认含义:
  - 表示运维人员已知晓该告警
  - 不代表告警已处理完毕
  - 已确认告警不再触发声音/通知提醒
```

### 步骤 5: 采取纠正措施

```
根据告警类型和处理建议, 用户可采取以下操作:

操作 A - 跳转到设备管理:
  告警详情 → [跳转设备] → 设备详情页
  查看设备运行状态, 诊断问题

操作 B - 执行 MML 命令:
  告警详情 → [MML 操作] → MML 执行页面 (自动选中设备)
  根据处理建议执行诊断/修复命令

操作 C - 修改配置参数:
  导航到配置管理 → 选择该设备 → 修改相关参数
  如: 调整功率参数、修改邻区配置等

操作 D - 软件升级/回退:
  导航到软件管理 → 对问题设备执行升级或回退

操作 E - 现场处理:
  需要安排人员到现场处理 (如硬件更换)
  告警保持 "已确认" 状态, 等待现场处理完成
```

### 步骤 6: 告警清除

```
自动清除:
  - 设备恢复正常 → 自动上报清除消息
  - 系统收到清除消息 → 告警从当前列表移除
  - 当前告警列表: 该行淡出动画 (300ms)
  - Dashboard 告警计数递减

手动清除:
  - 告警详情 → [清除告警] 按钮
  - 适用于: 设备已恢复但未自动上报清除的场景
  - 确认对话框: "确定要手动清除该告警吗?"

批量清除:
  - 告警列表选中多条 → [批量清除]
  - 通常用于清理过期或误报告警
```

### 步骤 7: 归档到历史告警

```
行为:
  - 告警清除后自动移入历史告警表
  - 历史告警保留完整信息 (产生时间、确认时间、清除时间、处理人)

查看历史:
  导航: 告警管理 > 历史告警
  支持按时间范围、级别、设备、告警名称筛选
  用于: 告警趋势分析、问题复盘
```

### 步骤 8: 创建告警规则 (可选)

```
场景: 某类告警频繁出现, 希望自动处理

操作:
  导航: 告警管理 > 告警规则
  [新建规则]:
  ┌────────────────────────────────────────┐
  │ 新建告警规则                      [X] │
  ├────────────────────────────────────────┤
  │ * 规则名称:   [________________]      │
  │ * 匹配条件:                           │
  │   告警名称 = [CELL_UNAVAILABLE ▾]     │
  │   告警级别 = [全部 ▾]                │
  │   设备范围 = [全部设备 ▾]             │
  │ * 动作:                                │
  │   ☑ 自动确认                           │
  │   ☐ 自动清除 (清除延迟: [60] 分钟)    │
  │   ☑ 发送通知 (邮件/短信)              │
  │   ☐ 执行 MML 命令                     │
  ├────────────────────────────────────────┤
  │                   [取消]    [保存]      │
  └────────────────────────────────────────┘
```

## 异常处理汇总

| 步骤 | 可能异常 | 处理方式 |
|------|---------|---------|
| 步骤 2 告警推送 | WebSocket 断连 | 降级为 Polling (30s), 顶部显示连接断开 Banner |
| 步骤 3 查看详情 | 告警已被清除 | 提示 "该告警已清除" + 跳转历史告警 |
| 步骤 4 确认告警 | 无权限 | [确认] 按钮禁用 + Tooltip "无权限" |
| 步骤 5 MML 操作 | 设备离线 | 提示 "设备离线, 无法执行 MML" |
| 步骤 6 手动清除 | 清除失败 | Toast 错误 + 保留告警状态 |

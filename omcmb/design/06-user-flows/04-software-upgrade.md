# 用户流程: 软件升级 (Software Upgrade)

> OMC 统一网管系统 - 用户流程

## 概述

软件升级流程覆盖从固件上传、升级计划创建、执行监控到版本验证的完整链路。升级操作对网络有重大影响，流程中设计了多重确认和回退机制。

## 详细步骤

### 步骤 1: 上传固件包

```
页面: 软件管理 > 版本管理
路径: /software/version

操作:
  1. 点击 [上传版本] 按钮
  2. 弹出上传对话框:

  ┌──────────────────────────────────────────────┐
  │ 上传软件版本                            [X] │
  ├──────────────────────────────────────────────┤
  │                                              │
  │ * 版本类型:   [基站软件 ▾]                   │
  │ * 适用设备:   [eNodeB ▾]                     │
  │ * 版本号:     [________________]             │
  │   版本说明:   [________________]             │
  │                                              │
  │ * 软件包:                                    │
  │ ┌─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐     │
  │ │                                      │     │
  │ │  点击或拖拽固件文件到此区域上传        │     │
  │ │  支持 .bin, .pkg, .zip 格式           │     │
  │ │  单个文件不超过 500MB                  │     │
  │ │                                      │     │
  │ └─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘     │
  │                                              │
  │ 上传进度:                                    │
  │ ████████████████░░░░░░  67%                  │
  │ 已上传 335MB / 500MB  速度: 12MB/s           │
  │                                              │
  ├──────────────────────────────────────────────┤
  │                    [取消]    [确认上传]        │
  └──────────────────────────────────────────────┘

  3. 上传完成 → MD5/SHA256 校验
  4. 校验通过 → 版本出现在版本列表中

错误处理:
  - 文件格式不支持: "不支持的文件格式, 请上传 .bin/.pkg/.zip 文件"
  - 文件过大: "文件大小不能超过 500MB"
  - 上传中断: "上传中断, [重试]" (支持断点续传)
  - 校验失败: "文件校验失败, 文件可能损坏, 请重新上传"
```

### 步骤 2: 创建升级计划

```
页面: 软件管理 > 升级计划
路径: /software/upgrade-plan

操作:
  1. 点击 [新建升级计划]
  2. 填写计划信息:

  ┌──────────────────────────────────────────────┐
  │ 新建升级计划                            [X] │
  ├──────────────────────────────────────────────┤
  │                                              │
  │ * 计划名称:   [________________]             │
  │ * 目标版本:   [v3.2.1 ▾]      ← 从版本列表选│
  │                                              │
  │ * 目标设备:   [选择设备...]                   │
  │   已选: eNodeB-001, eNodeB-002 等 5 台       │
  │                                              │
  │ * 执行策略:                                  │
  │   ○ 立即执行                                 │
  │   ● 定时执行  时间: [2024-01-16 02:00]       │
  │                      (建议选择业务低峰期)     │
  │                                              │
  │ * 升级模式:                                  │
  │   ○ 并行升级 (所有设备同时升级)               │
  │   ● 滚动升级 (逐批升级, 每批 [2 ▾] 台)       │
  │                                              │
  │   ☑ 升级后自动激活                           │
  │   ☑ 升级失败自动回退                         │
  │                                              │
  ├──────────────────────────────────────────────┤
  │                    [取消]    [保存计划]        │
  └──────────────────────────────────────────────┘
```

### 步骤 3: 审核升级计划 (可选)

```
场景: 生产环境升级需要审批

流程:
  1. 计划创建后状态为 "待审核"
  2. 审核人在升级计划列表看到待审核计划
  3. 点击 [审核] → 查看计划详情
  4. [通过] 或 [驳回 (填写原因)]
  5. 审核通过 → 计划状态变为 "待执行"

无审核流程时:
  计划创建后直接为 "待执行" 状态
```

```

  ├──────────────────────────────────────────────┤
  │                                              │
  │ 升级计划: 基站软件升级 v3.2.1                 │
  │ 目标设备: 5 台                               │
  │ 目标版本: v3.2.1                             │
  │ 升级模式: 滚动升级 (每批 2 台)               │
  │                                              │
  │ ⚠ 升级过程中设备将短暂中断服务!               │
  │                                              │
  │ 请输入 "UPGRADE" 确认:                       │
  │ ┌──────────────────────────────┐             │
  │ │                              │             │
  │ └──────────────────────────────┘             │
  │                                              │
  ├──────────────────────────────────────────────┤

  └──────────────────────────────────────────────┘

  启动后: Toast "升级任务已启动, 请在任务面板中查看进度"
```

### 步骤 6: 版本激活

```
自动激活 (推荐):
  - 升级计划配置了 "升级后自动激活"
  - 固件下载安装完成后自动重启并激活新版本

手动激活:
  - 升级完成后设备运行旧版本, 新版本待激活
  - 用户在升级详情页 → 选择设备 → [激活版本]
  - 确认: "激活新版本将重启设备, 确定继续?"
  - 激活过程: 设备重启 (约 2-5 分钟)
```

### 步骤 7: 验证完成

```
验证方式:

A. 版本查询:
   软件管理 > 设备版本查询
   确认设备当前运行版本与目标版本一致

B. 设备状态确认:
   设备管理 > 设备列表
   确认所有升级设备状态为 "在线"

C. 告警检查:
   告警管理 > 当前告警
   检查升级设备是否有新产生的告警

D. 性能验证:
   性能管理 > KPI 报表
   对比升级前后的关键 KPI 指标
```

### 步骤 8: 回退 (Rollback)

```
触发条件:
  - 升级后发现严重问题 (告警增多、KPI 下降)
  - 设备升级失败 (自动回退)

手动回退:
  升级计划详情 → 选择设备 → [回退版本]
  确认: "确定要将设备回退到 v3.1.0 吗?"

自动回退:
  - 升级计划配置了 "升级失败自动回退"
  - 单台设备升级失败 → 自动回退该设备
  - 不影响其他设备的升级

回退过程:
  1. 恢复旧版本固件
  2. 设备重启 (约 2-5 分钟)
  3. 验证版本恢复
  4. 设备恢复在线
```

## 异常处理汇总

| 步骤 | 可能异常 | 处理方式 |
|------|---------|---------|
| 步骤 1 上传 | 网络中断导致上传失败 | 支持断点续传, [重试] |
| 步骤 1 上传 | 文件校验失败 | 提示重新下载固件并上传 |
| 步骤 4 启动 | 部分设备离线 | 提示哪些设备离线, 可选跳过 |
| 步骤 5 升级中 | 单台设备升级失败 | 自动回退该设备, 继续其他设备 |
| 步骤 5 升级中 | 网络中断 | 已开始的设备继续, 未开始的暂停 |
| 步骤 6 激活 | 设备重启失败 | 告警通知 + 自动回退 |
| 步骤 8 回退 | 回退也失败 | 紧急告警 + 需人工介入 |

# 错误状态 (Error States)

> OMC 统一网管系统 - 交互设计规范

## 概述

错误状态设计的目标是：清晰告知用户发生了什么问题，提供可操作的恢复路径，避免用户陷入死胡同。所有错误信息应使用友好、专业的中文表述。

---

## 1. 网络错误 (Network Error)

### 1.1 触发条件
- 请求超时 (timeout)
- DNS 解析失败
- 服务器不可达 (ECONNREFUSED)

### 1.2 表现形式

```
┌─────────────────────────────────────────┐
│ ⚠ 网络请求失败，请检查网络连接  [重试]  │  ← Toast 通知
└─────────────────────────────────────────┘

类型: Toast Notification (顶部居中)
图标: WarningOutlined (黄色)
文字: "网络请求失败，请检查网络连接"
操作: [重试] 按钮 (Text Button)
自动关闭: 不自动关闭 (需用户操作)
```

### 1.3 行为规范

```
1. 请求失败 → 显示 Toast 通知
2. 页面内容保持上一次成功加载的数据 (不清空)
3. [重试] 按钮 → 重新发起相同请求
4. 自动重试: 最多 2 次，间隔 2s, 4s (exponential backoff)
5. 自动重试全部失败后 → 显示 Toast 通知
```

## 2. 服务器错误 500 (Server Error)

### 2.1 触发条件
- HTTP 500 Internal Server Error
- HTTP 502 Bad Gateway
- HTTP 503 Service Unavailable

### 2.2 表现形式

**场景 A: 页面级请求失败 (页面主数据加载失败)**

```
┌─────────────────────────────────────┐
│                                     │
│         [500 插图]                  │
│                                     │
│    服务器开小差了，请稍后重试        │
│    错误代码: 500                     │
│                                     │
│    [重试]    [返回首页]              │
│                                     │
└─────────────────────────────────────┘

位置: 内容区域 (保留侧边栏和顶栏)
插图: 简洁的错误状态插图 (SVG)
标题: 20px, @heading-color, font-weight 600
描述: 14px, @text-secondary
操作:
  - [重试] Primary Button → 重新加载当前页面
  - [返回首页] Default Button → 导航到 Dashboard
```

**场景 B: 操作请求失败 (非页面主数据)**

```
┌──────────────────────────────────────────┐
│ ✕ 操作失败: 服务器内部错误 (500) [重试]  │  ← Toast 通知
└──────────────────────────────────────────┘

类型: Toast Notification (顶部居中)
图标: CloseCircleOutlined (红色)
文字: "操作失败: 服务器内部错误 (500)"
操作: [重试] Text Button
自动关闭: 8s 后自动关闭
```

## 3. 页面未找到 404 (Not Found)

### 3.1 触发条件
- URL 路径无效
- 资源已删除或不存在
- HTTP 404 响应

### 3.2 表现形式

```
┌─────────────────────────────────────┐
│                                     │
│         [404 插图]                  │
│                                     │
│    页面未找到                        │
│    您访问的页面不存在或已被移除      │
│                                     │
│    [返回首页]    [返回上一页]        │
│                                     │
└─────────────────────────────────────┘

位置: 内容区域 (保留侧边栏和顶栏)
插图: 404 状态插图 (SVG)
标题: 20px, @heading-color
描述: 14px, @text-secondary
操作:
  - [返回首页] Primary Button → 导航到 Dashboard
  - [返回上一页] Default Button → history.back()
```

## 4. 权限不足 403 (Permission Denied)

### 4.1 触发条件
- 用户无权访问该页面或功能
- HTTP 403 Forbidden
- 角色权限不足

### 4.2 表现形式

```
┌─────────────────────────────────────┐
│                                     │
│         [403 插图/锁图标]            │
│                                     │
│    无访问权限                        │
│    您没有权限访问此页面              │
│    如需权限，请联系系统管理员        │
│                                     │
│    [返回首页]                        │
│                                     │
└─────────────────────────────────────┘

位置: 内容区域 (保留侧边栏和顶栏)
插图: 锁/禁止图标 (SVG)
标题: 20px, @heading-color
描述: 14px, @text-secondary, 最多 2 行
操作: [返回首页] Primary Button
```

### 4.3 按钮级权限控制

```
方案 A - 隐藏 (推荐用于导航菜单):
  无权限的菜单项不在导航中显示

方案 B - 禁用 (推荐用于操作按钮):
  按钮显示但 disabled
  Tooltip: "您没有该操作的权限"
```

## 5. 表单验证错误 (Form Validation Errors)

### 5.1 行内错误 (Inline Error)

```
┌─────────────────────────────────────┐
│ 设备名称 *                           │
│ ┌─────────────────────────────────┐ │
│ │                                 │ │  ← 红色边框 (border-color: #FF4D4F)
│ └─────────────────────────────────┘ │
│ 请输入设备名称                       │  ← 错误提示
└─────────────────────────────────────┘

错误提示规范:
  - 位置: 字段下方, margin-top 4px
  - 字体: 12px
  - 颜色: @error-color (#FF4D4F)
  - 图标: 可选, CloseCircleFilled 12px (图标 + 文字)
  - 输入框边框变为红色
```

### 5.2 顶部错误汇总 (Error Summary)

```
┌────────────────────────────────────────────────┐
│ ⚠ 请修正以下 3 个错误:                          │
│   - 设备名称: 请输入设备名称                     │
│   - IP 地址: IP 地址格式不正确                    │
│   - 端口号: 端口号必须在 1-65535 之间            │
└────────────────────────────────────────────────┘

使用场景:
  - 表单字段较多 (>10 个) 时
  - 用户点击提交按钮后
  - 显示在表单顶部, Alert 组件
  - 类型: Alert type="error"
  - 点击错误项 → 页面滚动到对应字段并聚焦
```

### 5.3 验证时机

| 时机 | 行为 | 说明 |
|------|------|------|
| 失焦 (onBlur) | 验证当前字段 | 用户离开字段时立即反馈 |
| 修改 (onChange) | 若已有错误 → 实时验证 | 用户修正时即时清除错误 |
| 提交 (onSubmit) | 验证全部字段 | 阻止提交 + 定位首个错误 + 显示汇总 |

### 5.4 常见验证消息模板

```
必填:     "请输入{字段名}" / "请选择{字段名}"
格式:     "{字段名}格式不正确"
长度:     "{字段名}长度不能超过{N}个字符"
范围:     "{字段名}必须在{min}-{max}之间"
唯一:     "{字段名}已存在"
匹配:     "两次输入的密码不一致"
类型:     "请输入有效的{类型} (如: IP 地址, 端口号)"
```

## 6. API 错误响应 (API Error Response)

### 6.1 描述
后端 API 返回业务级错误 (HTTP 200 但业务状态码非成功)。

### 6.2 表现形式

```
┌──────────────────────────────────────────┐
│ ✕ 设备名称已存在，请使用其他名称         │  ← Toast 通知
└──────────────────────────────────────────┘

类型: Toast Notification (顶部居中)
图标: CloseCircleOutlined (红色)
文字: 后端返回的错误消息 (中文)
自动关闭: 5s
```

### 6.3 错误消息映射

```
后端错误码          →  前端展示消息
DUPLICATE_NAME      →  "名称已存在，请使用其他名称"
DEVICE_OFFLINE      →  "设备离线，无法执行此操作"
DEVICE_BUSY         →  "设备忙，请稍后重试"
TASK_CONFLICT       →  "存在冲突的任务，请等待当前任务完成"
QUOTA_EXCEEDED      →  "已达到数量上限"
INVALID_PARAM       →  "参数无效: {具体参数名}"
SESSION_EXPIRED     →  自动跳转登录页
```

## 7. 连接断开 (Connection Lost)

### 7.1 触发条件
- WebSocket 连接断开
- 网络持续不可用
- 长时间未收到心跳包

### 7.2 表现形式

```
┌──────────────────────────────────────────────────────┐
│ ⚠ 网络连接已断开，正在尝试重新连接...   [刷新页面]   │  ← 顶部 Banner
└──────────────────────────────────────────────────────┘

位置: 页面最顶部 (Header 之上)
背景色: @warning-color (#FAAD14) 10% 透明度
文字: 14px, @warning-color
图标: DisconnectOutlined
状态文字: 动态更新
  - "网络连接已断开，正在尝试重新连接..."
  - "重新连接中... (第 N 次尝试)"
  - "网络连接已恢复" (成功后 3s 自动消失)
操作: [刷新页面] Text Button
```

### 7.3 重连策略

```
1. 连接断开 → 显示 Banner
2. 立即尝试重连 (第 1 次)
3. 失败 → 2s 后重试 (第 2 次)
4. 失败 → 4s 后重试 (第 3 次)
5. 失败 → 8s 后重试 (第 4 次)
6. 失败 → 16s 后重试 (第 5 次)
7. 之后每 30s 重试一次
8. 重连成功 → Banner 更新为"网络连接已恢复" → 3s 后消失
9. 重连成功 → 自动刷新受影响的数据 (告警列表、任务面板等)
```

## 8. 错误状态设计原则

### 8.1 核心原则

```
1. 不要吓到用户
   ✗ "Fatal Error: ECONNREFUSED at TCP.connect"
   ✓ "网络请求失败，请检查网络连接"

2. 提供恢复路径
   ✗ 只显示错误信息，无操作按钮
   ✓ 提供 [重试] / [返回首页] / [联系管理员] 等操作

3. 保留已有数据
   ✗ 请求失败后清空页面
   ✓ 保持上次成功加载的数据，Toast 提示错误

4. 错误信息要具体
   ✗ "操作失败"
   ✓ "设备 [eNodeB-001] 参数同步失败: 设备离线"

5. 区分错误严重程度
   - 致命: 全页错误 (500, 404, 403)
   - 操作级: Toast 通知 (API 错误)
   - 字段级: 行内错误 (表单验证)
   - 环境级: 顶部 Banner (连接断开)
```

### 8.2 错误层级选择

```
用户操作出错?
    │
    ├── 整个页面无法使用?
    │   └── 是 → 全页错误 (500 / 404 / 403)
    │
    ├── 某个操作失败?
    │   └── 是 → Toast 通知 (带重试)
    │
    ├── 表单字段不合法?
    │   └── 是 → 行内错误 (字段下方红色提示)
    │
    └── 系统级连接问题?
        └── 是 → 顶部 Banner (持续显示直到恢复)
```

## 9. 实现参考

### Ant Design 组件映射

| 错误类型 | 组件 | 用法 |
|---------|------|------|
| Toast 通知 | `message.error()` | 操作失败提示 |
| 全页错误 | `<Result status="500" />` | 服务器错误页 |
| 404 页面 | `<Result status="404" />` | 页面未找到 |
| 403 页面 | `<Result status="403" />` | 权限不足 |
| 行内错误 | `<Form.Item validateStatus="error">` | 表单字段验证 |
| 错误汇总 | `<Alert type="error">` | 表单顶部错误列表 |
| 连接 Banner | 自定义 `<ConnectionBanner />` | 全局连接状态 |

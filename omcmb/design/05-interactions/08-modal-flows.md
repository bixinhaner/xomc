# 弹窗流程 (Modal Flows)

> OMC 统一网管系统 - 交互设计规范

## 概述

弹窗 (Modal) 和抽屉 (Drawer) 是 OMC 系统中执行快速操作、查看详情、填写表单的主要容器。本文定义弹窗的打开/关闭行为、表单提交流程和各种变体。

---

## 1. Modal 打开动画

### 1.1 动画规范

```
打开动画:
  - 遮罩层: opacity 0 → 1, duration 200ms
  - 弹窗内容: scale(0.9) + opacity(0) → scale(1) + opacity(1)
  - duration: 300ms
  - timing: ease-out (cubic-bezier(0.215, 0.61, 0.355, 1))
  - 变换原点: 触发按钮位置 (如果可获取) 或屏幕中心

关闭动画:
  - 遮罩层: opacity 1 → 0, duration 200ms
  - 弹窗内容: scale(1) + opacity(1) → scale(0.9) + opacity(0)
  - duration: 200ms
  - timing: ease-in
```

## 2. Modal 关闭方式

### 2.1 关闭方法

| 关闭方式 | 触发 | 是否检查 dirty state |
|---------|------|---------------------|
| X 按钮 | 点击右上角关闭图标 | 是 |
| ESC 键 | 按 ESC 键 | 是 |
| 遮罩点击 | 点击弹窗外的遮罩区域 | 是 |
| 取消按钮 | 点击 [取消] 按钮 | 是 |
| 提交成功 | 表单提交成功后自动关闭 | 否 (已保存) |

### 2.2 Dirty State 检查

```
关闭前检查: 如果弹窗内有表单且表单已修改 (dirty)

  用户尝试关闭
       │
       ├── 表单未修改 → 直接关闭
       │
       └── 表单已修改 → 弹出确认对话框:
           ┌──────────────────────────────────┐
           │ 确认关闭                     [X] │
           ├──────────────────────────────────┤
           │                                  │
           │ 有未保存的更改，确定关闭吗?       │
           │                                  │
           ├──────────────────────────────────┤
           │          [继续编辑]    [放弃更改] │
           └──────────────────────────────────┘
```

## 3. Modal 尺寸规范

### 3.1 标准尺寸

| 尺寸 | 宽度 | 适用场景 |
|------|------|---------|
| Small | 416px | 确认对话框、简单提示 |
| Medium | 600px | 简单表单 (3-6 个字段) |
| Large | 800px | 复杂表单、详情展示 |
| Extra Large | 1000px | 多列表单、表格嵌入 |

### 3.2 高度规范

```
最大高度: 视口高度 - 100px (上下各留 50px)
内容超出: 弹窗 Body 区域内滚动 (Header 和 Footer 固定)
最小高度: 无限制 (内容自适应)
```

### 3.3 结构布局

```
┌──────────────────────────────────────────┐
│ 弹窗标题                            [X] │  ← Header (固定, 不滚动)
├──────────────────────────────────────────┤
│                                          │
│ 弹窗内容                                 │  ← Body (可滚动)
│ ...                                      │
│                                          │
├──────────────────────────────────────────┤
│                     [取消]    [确定]      │  ← Footer (固定, 不滚动)
└──────────────────────────────────────────┘

Header:
  - 标题: 16px, font-weight 600
  - 关闭图标: CloseOutlined, 16px, 右上角
  - 下边框: 1px solid #F0F0F0

Body:
  - 内边距: 24px
  - 溢出: overflow-y auto

Footer:
  - 内边距: 12px 24px
  - 上边框: 1px solid #F0F0F0
  - 按钮右对齐
```

## 4. 嵌套弹窗 (Nested Modals)

### 4.1 交互规范

```
场景: 弹窗内的操作需要打开另一个弹窗
例如: 创建设备 → 需要新建分组 → 打开新建分组弹窗

┌── 遮罩层 1 (透明度较低) ──────────────────────┐
│ ┌── 弹窗 1: 创建设备 ────────────────────────┐│
│ │ * 设备名称: [________]                     ││
│ │ * 设备分组: [选择分组 ▾]  [+ 新建分组]     ││
│ │            ↓                               ││
│ │  ┌── 遮罩层 2 ────────────────────────┐    ││
│ │  │ ┌── 弹窗 2: 新建分组 ───────────┐  │    ││
│ │  │ │ * 分组名称: [________]        │  │    ││
│ │  │ │               [取消] [确定]    │  │    ││
│ │  │ └──────────────────────────────┘  │    ││
│ │  └───────────────────────────────────┘    ││
│ └────────────────────────────────────────────┘│
└───────────────────────────────────────────────┘

规范:
  - 最多允许 2 层嵌套 (避免过多层次)
  - 新弹窗的遮罩层叠加在上一个弹窗上方
  - 每层遮罩层: rgba(0, 0, 0, 0.45)
  - z-index 递增: 1000, 1010, 1020...
  - ESC 键: 关闭最上层弹窗
  - 底层弹窗不可交互 (被遮罩覆盖)
```

## 5. 全屏模式 (Fullscreen Modal)

### 5.1 交互规范

```
场景: 弹窗内容复杂，需要更大空间 (如拓扑图查看、大表格)

┌──────────────────────────────────────────────────────┐
│ 弹窗标题                        [缩小] [全屏] [X]   │
├──────────────────────────────────────────────────────┤
│                                                      │
│                                                      │
│                  全屏内容区域                          │
│                                                      │
│                                                      │
├──────────────────────────────────────────────────────┤
│                               [取消]    [确定]        │
└──────────────────────────────────────────────────────┘

切换按钮: Header 右侧, 在关闭按钮左边
  [全屏]: FullscreenOutlined 图标 → 点击进入全屏
  [缩小]: FullscreenExitOutlined 图标 → 点击退出全屏

全屏尺寸: 宽度 100vw - 48px, 高度 100vh - 48px
动画: 尺寸和位置平滑过渡 300ms
```

## 6. Modal 表单提交流程

### 6.1 标准提交流程

```
用户填写表单
    │
    ├── 点击 [取消]
    │   ├── 表单未修改 → 直接关闭
    │   └── 表单已修改 → 确认弃更改对话框
    │
    └── 点击 [确定/保存/提交]
        │
        ├── 前端验证
        │   ├── 验证失败 → 显示行内错误, 不发请求
        │   └── 验证通过 ↓
        │
        ├── [确定] 按钮进入 Loading 状态
        │   - 文字: "保存中..."
        │   - 按钮禁用
        │   - [取消] 按钮也禁用
        │   - Modal 不可关闭 (ESC, 遮罩点击无效)
        │
        ├── 发送 API 请求
        │   ├── 成功:
        │   │   1. 关闭弹窗
        │   │   2. Toast: "保存成功"
        │   │   3. 刷新父页面数据
        │   │
        │   └── 失败:
        │       1. 按钮恢复正常状态
        │       2. Toast: "保存失败: {错误原因}"
        │       3. 弹窗保持打开 (用户可修改后重试)
```

### 6.2 按钮状态流转

```
正常:    [取消]    [保 存]          ← 两个按钮都可用
提交中:  [取消]    [● 保存中...]    ← 都禁用, 确认按钮有 Spinner
成功:    弹窗关闭
失败:    [取消]    [保 存]          ← 恢复正常, 用户可重试
```

## 7. Drawer 抽屉变体

### 7.1 描述
Drawer 从屏幕右侧滑出，适用于详情查看、属性编辑等不需要打断用户操作的场景。

### 7.2 视觉规范

```
┌────────────────────────────┬──────────────────────────┐
│                            │ 设备详情            [X] │
│                            ├──────────────────────────┤
│       主页面内容            │                          │
│       (部分可见,            │  设备名称: eNodeB-001    │
│        可能变暗)            │  IP 地址: 192.168.1.1   │
│                            │  状态: 在线              │
│                            │  ...                     │
│                            │                          │
│                            ├──────────────────────────┤
│                            │         [编辑] [关闭]    │
└────────────────────────────┴──────────────────────────┘

方向: 从右侧滑入
宽度: 600px (默认), 可配置 400px / 800px / 50%
动画: translateX(100%) → translateX(0), duration 300ms, ease-out
遮罩: rgba(0, 0, 0, 0.45), 可选无遮罩 (不阻止主页面交互)
关闭方式: X 按钮, ESC 键, 遮罩点击 (如有遮罩)
```

### 7.3 Drawer vs Modal 选择

| 特征 | 使用 Modal | 使用 Drawer |
|------|-----------|-------------|
| 操作类型 | 创建/重要确认 | 查看详情/编辑属性 |
| 与主页面关系 | 独立操作 | 关联操作 (需参考主页面) |
| 数据量 | 少量字段 | 较多信息展示 |
| 用户注意力 | 需要聚焦 | 可参考上下文 |
| 关闭后 | 回到操作前状态 | 可能需要刷新 |
| 嵌套 | 支持 | 不推荐嵌套 |

## 8. 确认对话框 (Confirm Dialog)

### 8.1 标准确认

```
┌──────────────────────────────────────┐
│                                      │
│  ⓘ 确定要同步该设备的配置吗?          │
│                                      │
│              [取消]    [确定]          │
└──────────────────────────────────────┘

图标: QuestionCircleOutlined (蓝色)
标题: 操作确认文案
按钮: [取消] + [确定]
```

### 8.2 危险确认

```
┌──────────────────────────────────────┐
│                                      │
│  ⚠ 确定要删除设备 eNodeB-001 吗?     │
│     此操作不可撤销!                    │
│                                      │
│              [取消]    [确定删除]      │
└──────────────────────────────────────┘

图标: ExclamationCircleOutlined (红色/黄色)
标题: 危险操作确认文案
补充: "此操作不可撤销!" (红色文字)
按钮: [取消] Default + [确定删除] Danger
```

## 9. 步骤弹窗 (Step Modal)

### 9.1 交互规范

```
场景: 弹窗内需要多步完成的操作 (如 KPI 提取向导)

┌──────────────────────────────────────────────────┐
│ KPI 提取                                    [X] │
├──────────────────────────────────────────────────┤
│ ───●──────────●──────────○──────────○───        │
│   1.选择指标   2.设置参数   3.选择网元   4.确认   │
├──────────────────────────────────────────────────┤
│                                                  │
│ 步骤内容区域                                      │
│ ...                                              │
│                                                  │
├──────────────────────────────────────────────────┤
│ [上一步]                        [下一步]          │
└──────────────────────────────────────────────────┘

步骤条: Steps 组件, 水平排列, 弹窗 Body 顶部
按钮:
  第一步: [取消] + [下一步]
  中间步骤: [上一步] + [下一步]
  最后一步: [上一步] + [完成/提交]
验证: 每步有独立验证, 验证通过才能进入下一步
```

## 10. 实现参考

### Ant Design 组件映射

| 弹窗类型 | Ant Design 组件 | 关键 Props |
|---------|----------------|-----------|
| 标准弹窗 | `<Modal>` | `open`, `onCancel`, `onOk`, `width` |
| 确认对话框 | `Modal.confirm()` | `title`, `content`, `okType` |
| 危险确认 | `Modal.confirm()` | `okType="danger"`, `okText` |
| Drawer | `<Drawer>` | `open`, `placement="right"`, `width={600}` |
| 步骤弹窗 | `<Modal>` + `<Steps>` | 自定义组合 |
